## DEFINITION
Infix to Postfix conversion is a stack-based algorithm that transforms an arithmetic expression from infix notation (operators between operands, e.g., A + B) to postfix notation (operators after operands, e.g., AB+), using a stack to temporarily hold operators and parentheses while respecting operator precedence and associativity rules. The algorithm scans the infix expression left-to-right, outputs operands immediately, and uses the stack to reorder operators so that the resulting postfix expression can be evaluated without parentheses or precedence rules.

## SCOPE_BOUNDARY
This node covers the standard Shunting Yard algorithm for infix-to-postfix conversion: operand handling, operator precedence (^ > * / > + -), left-to-right associativity for + - * /, right-to-left associativity for ^, parentheses handling (push '(', pop until '(' on ')'), and end-of-input stack clearing. It does NOT cover postfix evaluation (separate application), prefix conversion, unary operators, or error handling for malformed expressions.

## WALKTHROUGH
Imagine you are writing a calculator app that evaluates expressions like "3 + 4 * 2 / (1 - 5)^2". The CPU cannot directly understand infix because it needs to know which operation to do first — but postfix makes evaluation trivial: just scan left-to-right, push numbers, and when you see an operator, pop two numbers, apply it, push result. So how do we automatically convert infix to postfix? We'll use a stack as a "holding area" for operators. Start with a simple expression: A + B * C. Scan A → output A. Scan + → stack empty, push +. Scan B → output B. Scan * → top is +, * has higher precedence, so push *. Scan C → output C. End → pop all: * then + → output: ABC*+. Now try with parentheses: (A + B) * C. The '(' forces + to wait until ')' appears. This systematic left-to-right scan with stack decisions is the complete algorithm.

## DIAGNOSTIC_QUESTION_4
Compare the postfix conversions of A ^ B ^ C and A * B * C. Why are the results different even though both operators are binary?

## DIAGNOSTIC_ANSWER_4
^ is right-associative: A ^ B ^ C = A ^ (B ^ C) → postfix ABC^^. * is left-associative: A * B * C = (A * B) * C → postfix AB*C*.  
During conversion: for ^, when second ^ is scanned, top is ^ with same precedence but right-assoc means we do NOT pop, we push new ^. For *, same precedence and left-assoc means we pop the first * before pushing the second.

## COMMON_MISCONCEPTION
Students consistently treat ^ (exponentiation) as left-associative like * and /, writing A ^ B ^ C → AB^C^ instead of ABC^^. This happens because they memorize "higher precedence operators are popped first" but forget the associativity exception: for same-precedence operators, left-assoc means pop existing, right-assoc means push new. In boards and JEE, expressions like 2^3^2 appear — correct value is 2^(3^2)=512, not (2^3)^2=64. The postfix ABC^^ evaluates correctly (push 2, push 3, push 2, ^ → 9, ^ → 512) while AB^C^ gives 64. This single error costs 2-3 marks in board exams and appears in JEE Main as a "find the output" MCQ trap.

## WORKED_EXAMPLE_1
PROBLEM: Convert the infix expression (A + B) * C - D ^ E / F to postfix. Show stack and output after each token scan.
STEPS:
- Step 1: Initialize empty stack, empty output. Scan '(' → push '('.
- Step 2: Scan A → operand, output A. Scan + → stack top '(', push +. Scan B → output B.
- Step 3: Scan ')' → pop until '(': pop + → output +, pop '(' discard. Output so far: AB+.
- Step 4: Scan * → stack empty, push *. Scan C → output C. Output: AB+C.
- Step 5: Scan - → top is *, - has lower precedence than *, so pop * → output *, push -. Output: AB+C*.
- Step 6: Scan D → output D. Scan ^ → top is -, ^ higher precedence, push ^. Scan E → output E.
- Step 7: Scan / → top is ^, / lower than ^, pop ^ → output ^. Top now -, / higher than -, push /. Scan F → output F. Output: AB+C*DE^F.
- Step 8: End of input → pop remaining: pop / → output /, pop - → output -. Final postfix: AB+C*DE^F/-.
REASONING: The algorithm uses stack to delay operators until their operands are ready and precedence allows. Parentheses force immediate evaluation of subexpression. Right-associativity of ^ would matter if we had ^ ^ sequence.
ANSWER: AB+C*DE^F/-

## COMPETENCY_QUESTION_1
QUESTION: In a competitive programming problem, you are given an infix expression string containing single-letter variables, operators +, -, *, /, ^, and parentheses. Write a Python function `infix_to_postfix(expr: str) -> str` that implements the conversion algorithm. Your code must handle operator precedence and associativity correctly. Test it on "(a+b)*(c^d-e)".
COMPETENCY: Translating real-world situations to mathematical expressions / Algorithmic implementation
STEPS:
- Step 1: Define precedence dictionary: {'+':1, '-':1, '*':2, '/':2, '^':3}. Define associativity: '^' right, others left.
- Step 2: Initialize empty stack list, empty output list. Iterate through each character in expr.
- Step 3: If char is operand (isalpha), append to output. If '(', push. If ')', pop and append to output until '(' found, then pop '('.
- Step 4: If operator: while stack not empty and top != '(' and (precedence[top] > precedence[char] or (precedence[top] == precedence[char] and char != '^')): pop and append to output. Then push char.
- Step 5: After loop, pop all remaining operators to output. Return ''.join(output).
- Step 6: Test: (a+b)*(c^d-e) → ab+cd^e-* (verify manually).
ANSWER: 
```python
def infix_to_postfix(expr):
    prec = {'+':1, '-':1, '*':2, '/':2, '^':3}
    assoc_right = {'^'}
    stack = []
    out = []
    for ch in expr:
        if ch.isalpha():
            out.append(ch)
        elif ch == '(':
            stack.append(ch)
        elif ch == ')':
            while stack and stack[-1] != '(':
                out.append(stack.pop())
            stack.pop()  # remove '('
        else:  # operator
            while stack and stack[-1] != '(' and \
                  (prec[stack[-1]] > prec[ch] or \
                   (prec[stack[-1]] == prec[ch] and ch not in assoc_right)):
                out.append(stack.pop())
            stack.append(ch)
    while stack:
        out.append(stack.pop())
    return ''.join(out)

print(infix_to_postfix("(a+b)*(c^d-e)"))  # Output: ab+cd^e-*
```
