DEFINITION: Infix to Postfix conversion is a stack-based algorithm that transforms an arithmetic expression from infix notation (operators between operands, e.g., A + B) to postfix notation (operators after operands, e.g., AB+), using a stack to temporarily hold operators and parentheses while respecting operator precedence and associativity rules. The algorithm scans the infix expression left-to-right, outputs operands immediately, and uses the stack to reorder operators so that the resulting postfix expression can be evaluated without parentheses or precedence rules.
WALKTHROUGH: Imagine you are writing a calculator app that evaluates expressions like "3 + 4 * 2 / (1 - 5)^2". The CPU cannot directly understand infix because it needs to know which operation to do first — but postfix makes evaluation trivial: just scan left-to-right, push numbers, and when you see an operator, pop two numbers, apply it, push result. So how do we automatically convert infix to postfix? We'll use a stack as a "holding area" for operators. Start with a simple expression: A + B * C. Scan A → output A. Scan + → stack empty, push +. Scan B → output B. Scan * → top is +, * has higher precedence, so push *. Scan C → output C. End → pop all: * then + → output: ABC*+. Now try with parentheses: (A + B) * C. The '(' forces + to wait until ')' appears. This systematic left-to-right scan with stack decisions is the complete algorithm.

D4 Q: Compare the postfix conversions of A ^ B ^ C and A * B * C. Why are the results different even though both operators are binary?
D4 A: ^ is right-associative: A ^ B ^ C = A ^ (B ^ C) → postfix ABC^^. * is left-associative: A * B * C = (A * B) * C → postfix AB*C*.
