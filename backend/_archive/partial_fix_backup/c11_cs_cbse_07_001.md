## DEFINITION
A tuple in Python is an ordered, immutable collection of elements that can store heterogeneous data types and allows duplicate values. Once created, the elements of a tuple cannot be modified, added, or removed.

## WALKTHROUGH
Imagine you are writing a program to store the fixed dimensions of a rectangular box — length, width, and height — that should never change during the program's execution. You could use a list, but lists can be accidentally modified. A tuple is perfect here because it is immutable: once created, its values cannot be altered. Think of a tuple like a sealed envelope containing a written note — you can read the note (access elements) but you cannot erase or rewrite it. In Python, tuples are created by placing comma-separated values inside parentheses `()` or by using the `tuple()` constructor. They maintain insertion order, allow duplicate values, and can hold mixed data types (e.g., integers, strings, floats). This makes them ideal for representing fixed data like coordinates (x, y), RGB color codes (r, g, b), or database records.

## DIAGNOSTIC_QUESTION_1
What is the correct definition of a tuple in Python? Choose the most accurate statement:
A) A mutable ordered collection that allows duplicates.
B) An immutable ordered collection that allows duplicates and heterogeneous data.
C) An unordered collection of unique elements.

## DIAGNOSTIC_ANSWER_1
The correct answer is **B**. A tuple is an immutable ordered collection that allows duplicates and heterogeneous data.

## DIAGNOSTIC_QUESTION_2
Explain in your own words why a tuple is more suitable than a list for storing the RGB values of a color (e.g., red = (255, 0, 0)) in a graphics program.

## DIAGNOSTIC_ANSWER_2
A tuple is more suitable because RGB values are fixed constants that should not change during program execution. The immutability of tuples prevents accidental modification, ensures data integrity, and can improve performance (since Python can optimize immutable objects). ## DIAGNOSTIC_QUESTION_3
Write Python code to create a tuple named `student_record` that stores the following data for a student: name ("Priya"), roll number (101), and marks (87.5). Then, write code to access and print the marks.

## DIAGNOSTIC_ANSWER_3
**Code:**

**Steps:** 1) Create tuple with heterogeneous data using parentheses. 2) Access the third element (index 2) using zero-based indexing.  
A wrong answer might use square brackets `[]` (creating a list), use 1-based indexing (`student_record[3]`), or try to modify the tuple (e.g., `student_record[2] = 90`). This reveals confusion between list/tuple syntax, indexing rules, or immutability.

## DIAGNOSTIC_QUESTION_4
Consider the following code:
```python
t = (1, 2, [3, 4])
t[2].append(5)
print(t)
```
What is the output? Explain why this does NOT violate tuple immutability.

## DIAGNOSTIC_ANSWER_4
**Output:** `(1, 2, [3, 4, 5])`  
**Explanation:** The tuple `t` itself is immutable — its *references* to elements cannot change. However, the third element is a *list*, which is mutable. The tuple stores a reference to that list object. Calling `append()` mutates the *list object*, not the tuple's reference. The tuple still points to the same list object.  
A wrong answer (e.g., "this raises an error" or "tuples are fully immutable") reveals the common misconception that tuple immutability extends recursively to all contained objects. This is a critical senior-secondary distinction.

## DIAGNOSTIC_QUESTION_5
A programmer wants to store the monthly sales targets for a year (12 fixed values) and says: "I'll use a list because I might need to sort them later." Evaluate this decision. Is a list or tuple more appropriate? Justify your answer with two reasons.

## DIAGNOSTIC_ANSWER_5
A **tuple** is more appropriate.  
**Reason 1:** Sales targets are fixed for the year — they represent constant reference data, not data that changes. Using a tuple communicates intent (immutability) and prevents accidental modification.  
**Reason 2:** If sorting is needed, `sorted(sales_tuple)` returns a new sorted list without altering the original tuple, preserving the original order for reference.  
A wrong evaluation (choosing list) shows the student prioritizes convenience over semantic correctness and doesn't understand that tuples can be used with `sorted()` or that immutability is a design feature for fixed data.

## DIAGNOSTIC_QUESTION_6
Design a tuple structure to represent a 3D point in space with an optional label (e.g., "origin", "vertex_A"). The structure must support: (a) fixed coordinates (x, y, z), (b) an optional string label, and (c) immutability of coordinates. Show how to create two instances: one with a label and one without.

## DIAGNOSTIC_ANSWER_6
**Good answer:** Use a tuple with 3 or 4 elements where the last element is the optional label. Since tuples are immutable, coordinates cannot change.  
```python

point2 = (1.5, -2.0, 3.7)         # without label
```
**Alternative:** Use a tuple of `(coordinates_tuple, label)` where `coordinates_tuple = (x, y, z)`.  
A poor answer uses a list for coordinates, includes mutable structures, or tries to enforce optionality via `None` without explaining the design. This reveals inability to apply tuple properties to structure real-world data.

## COMMON_MISCONCEPTION
Students often believe that **tuple immutability means the entire object graph is frozen** — i.e., if a tuple contains a list, the list cannot be modified. They write code like `t = (1, [2, 3]); t[1].append(4)` and expect a `TypeError`. When it works, they are confused. This happens because they conflate *container immutability* (the tuple's references cannot change) with *content immutability* (the referenced objects themselves may be mutable). This is a senior-secondary level error rooted in not distinguishing between the container and its contents.

## ON_FAILURE
To fix this, do the following:  
1. **Demonstrate live:** Create `t = (1, [2, 3])`, show `id(t[1])`, then `t[1].append(4)`, show `id(t[1])` again — same id, list mutated.  
2. **Contrast with:** `t[1] = [5, 6]` — this *does* raise `TypeError` because it tries to change the tuple's reference.  
3. **Explain:** "The tuple holds *references* (addresses). Immutability means the addresses in the tuple cannot change. But the objects at those addresses can change if they are mutable."  
4. **Practice:** Give exercises where students predict whether `t[0] += 1` (immutable int), `t[1].append(5)` (mutable list), `t[1] = [7]` (reassignment) will work.

## WORKED_EXAMPLE_1
PROBLEM: A weather station records the daily high temperature (in °C) for a week as fixed reference data: 32, 34, 31, 33, 35, 36, 34. Store this in a tuple named `weekly_highs`. Then, write code to: (a) print the temperature of the 4th day, (b) check if 35°C appears in the tuple, and (c) find how many times 34°C occurs.

STEPS:
- Step 1: Identify the data — seven integers representing fixed daily highs. Since they are reference values that shouldn't change, a tuple is appropriate.
- Step 2: Create the tuple using parentheses: `weekly_highs = (32, 34, 31, 33, 35, 36, 34)`.
- Step 3: Access the 4th day (index 3 due to zero-based indexing): `print(weekly_highs[3])` → outputs 33.
- Step 4: Use `in` operator to check membership: `print(35 in weekly_highs)` → outputs `True`.
- Step 5: Use the `count()` method (though formally taught later, it's intuitive here): `print(weekly_highs.count(34))` → outputs `2`.
- Step 6: Verify: The tuple preserves order, allows duplicates (34 appears twice), and is immutable — attempting `weekly_highs[0] = 30` would raise `TypeError`.

REASONING: This example demonstrates tuple creation, indexing, membership testing, and counting — all core properties. The real-world context (weather data) makes the immutability requirement natural: recorded temperatures are facts, not variables.

ANSWER: 
- 4th day temperature: 33°C
- 35°C present: True
- 34°C occurs: 2 times

## WORKED_EXAMPLE_2
PROBLEM: A school stores each student's data as a tuple: (name, class, roll_number, [subject1_marks, subject2_marks, subject3_marks]). Create a tuple for a student "Arjun" in class 11, roll 25, with marks [88, 92, 79]. Then, explain why the marks list inside the tuple can be modified even though the tuple is immutable.

STEPS:
- Step 1: Identify components: string, integer, integer, list of three integers.
- Step 2: Create the tuple: `student = ("Arjun", 11, 25, [88, 92, 79])`.
- Step 3: Access the marks list: `marks = student[3]`.
- Step 4: Modify the list: `marks[1] = 95` (updates second subject mark). Now `student` is `("Arjun", 11, 25, [88, 95, 79])`.
- Step 5: Explain: The tuple stores a *reference* to the list object. Immutability means the tuple's reference (the address) cannot change. But the list object itself is mutable — its contents can change. The tuple still points to the same list object.
- Step 6: Contrast: `student[3] = [90, 90, 90]` would raise `TypeError` because it tries to change the tuple's reference.

REASONING: This illustrates the critical distinction between container immutability and content mutability. It prepares students for the common misconception addressed in DIAGNOSTIC_QUESTION_4 and ON_FAILURE.

ANSWER: 
- Student tuple: `("Arjun", 11, 25, [88, 92, 79])`
- After modification: `("Arjun", 11, 25, [88, 95, 79])`
- Reason: Tuple holds reference to list; list is mutable; tuple's reference unchanged.

## WORKED_EXAMPLE_3
PROBLEM: A game stores player positions as 3D coordinates (x, y, z). Write a function `create_position(x, y, z)` that returns a tuple. Then create three positions: `p1 = create_position(0, 0, 0)`, `p2 = create_position(10, 5, -3)`, `p3 = create_position(-2, 8, 7)`. Store all three in a tuple `all_positions`. Finally, write code to print the y-coordinate of the second position.

STEPS:
- Step 1: Define function returning a 3-element tuple: `def create_position(x, y, z): return (x, y, z)`.
- Step 2: Call function to create three position tuples.
- Step 3: Create a tuple of tuples: `all_positions = (p1, p2, p3)` → `((0,0,0), (10,5,-3), (-2,8,7))`.
- Step 4: Access second position (index 1): `second_pos = all_positions[1]` → `(10, 5, -3)`.
- Step 5: Access y-coordinate of that position (index 1): `y_coord = second_pos[1]` → `5`.
- Step 6: Alternatively, chain indexing: `print(all_positions[1][1])` → `5`.
- Step 7: Verify immutability: `all_positions[0] = (1,1,1)` raises `TypeError`.

REASONING: This combines tuple creation, function return values, nested tuples, and chained indexing — a realistic scenario in game development or graphics. It reinforces that tuples can contain other tuples, and indexing works hierarchically.

ANSWER: 
- `all_positions = ((0, 0, 0), (10, 5, -3), (-2, 8, 7))`
- y-coordinate of second position: 5

## COMPETENCY_QUESTION_1
QUESTION: A developer is building a configuration module for an app. The configuration includes: app_name (string), version (string), max_users (integer), and enabled_features (list of strings). The config is loaded once at startup and should never change during runtime. The developer uses a list: `config = ["MyApp", "2.1", 100, ["auth", "dashboard", "reports"]]`. 
(a) Identify two problems with using a list here. 
(b) Rewrite using a tuple. 
(c) Explain why the list inside the tuple (enabled_features) can still be modified, and whether this violates the "never change" requirement.

COMPETENCY: Translating real-world requirements to appropriate data structures with justification.

STEPS:
- Step 1: Identify that config data is fixed at startup → should be immutable.
- Step 2: List problems: (1) List allows accidental modification (e.g., `config[2] = 200`), (2) List semantics imply mutability, misleading other developers.
- Step 3: Rewrite: `config = ("MyApp", "2.1", 100, ["auth", "dashboard", "reports"])`.

## COMPETENCY_QUESTION_2
QUESTION: Consider the following code snippet intended to swap two variables using a tuple:
```python
a = 10
b = 20
(a, b) = (b, a)
print(a, b)
```
(a) What is the output?  
(b) Explain step-by-step how Python evaluates the right-hand side and assigns to the left-hand side.  
(c) A student writes `(a, b) = (a, b)` thinking it swaps. What happens? Why?  
(d) Can this swap technique work with three variables? Show code.

COMPETENCY: Analyzing and explaining language mechanics (tuple packing/unpacking) beyond surface syntax.

STEPS:
- Step 1: Output is `20 10` — values swapped.
- Step 2: RHS `(b, a)` creates a tuple `(20, 10)` *before* assignment. Then tuple unpacking assigns first element to `a`, second to `b`.
- Step 3: `(a, b) = (a, b)` creates tuple `(10, 20)`, then assigns `a=10`, `b=20` — no swap. The RHS uses *original* values.
- Step 4: Yes: `a, b, c = 1, 2, 3` then `a, b, c = c, a, b` → `a=3, b=1, c=2`. RHS tuple `(c, a, b)` uses original values `(3, 1, 2)`.

ANSWER: 
(a) 20 10  
(b) RHS evaluated first → tuple `(20, 10)` created → unpacked to LHS variables.  
(c) No swap; RHS uses original values.  
(d) Yes: `x, y, z = 10, 20, 30; x, y, z = z, x, y` → `x=30, y=10, z=20`.

DIFFICULTY: hard
