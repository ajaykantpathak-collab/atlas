## DEFINITION
Database connectivity refers to the mechanism that allows a Python program to communicate with a database management system (DBMS) like MySQL, enabling operations such as querying, inserting, updating, and deleting data through a standardized interface.

## COGNITIVE_LEVEL
understand

## MASTERY_CRITERIA
The student must be able to explain the need for database connectivity, list the sequential steps to connect Python with MySQL, and describe the distinct roles of the connector module, connection object, and cursor object.

## SCOPE_BOUNDARY
This node covers the conceptual foundation of database connectivity: the need for a connector/driver, the high-level workflow (install → import → connect → cursor → execute → fetch → commit/rollback → close), and the client-server architecture. It does NOT cover installation commands, actual connection code syntax, cursor methods, SQL execution details, transaction control statements, or exception handling — those are addressed in subsequent nodes.

## WALKTHROUGH
Imagine you are building a Python app for your school library. The librarian has all book records stored in a MySQL database. How does your Python program read that data or update it when a book is returned? Python cannot directly "speak" to MySQL — they are separate programs, often on different machines, communicating over a network using a specific protocol. This is where a **database connector** (like `mysql-connector-python`) comes in: it acts as a translator that converts Python function calls into MySQL network packets. The workflow always follows a fixed sequence: install the connector library, import it, establish a connection with credentials, create a cursor to run SQL, execute queries, fetch results if needed, commit changes for writes, and finally close the cursor and connection to free resources. This node gives you the "big picture" before you write any code.

## DIAGNOSTIC_QUESTION_1
What is the primary purpose of a database connector (like `mysql-connector-python`) in Python-MySQL connectivity?

## DIAGNOSTIC_ANSWER_1
A database connector acts as a bridge that translates Python function calls into the MySQL network protocol, allowing the Python program to communicate with the MySQL server. A wrong answer (e.g., "it stores data" or "it is the database itself") reveals that the student confuses the connector with the database or the data, not understanding it is a communication library.

## DIAGNOSTIC_QUESTION_2
Why can't a Python program directly execute SQL commands on a MySQL database without a connector?

## DIAGNOSTIC_ANSWER_2
Python and MySQL run as separate processes, often on different machines, and communicate over a network using a specific protocol (MySQL protocol). The connector implements this protocol. A wrong answer (e.g., "Python doesn't know SQL") shows the student doesn't understand the client-server architecture and the need for a standard communication protocol; SQL is just text — the protocol handles authentication, packet framing, and result serialization.

## DIAGNOSTIC_QUESTION_3
List the correct sequence of high-level steps to perform a database operation from Python, starting from a fresh environment.

## DIAGNOSTIC_ANSWER_3
1. Install the connector library (e.g., `pip install mysql-connector-python`). 2. Import the module (`import mysql.connector`). 3. Establish a connection using credentials (`conn = mysql.connector.connect(...)`). 4. Create a cursor object (`cursor = conn.cursor()`). 5. Execute SQL queries (`cursor.execute(...)`). 6. Fetch results if it's a SELECT (`cursor.fetchall()`). 7. Commit changes if it's DML (`conn.commit()`). 8. Close cursor and connection (`cursor.close(); conn.close()`). A wrong sequence (e.g., executing before connecting) indicates the student hasn't grasped the dependency order: connection → cursor → execution.

## DIAGNOSTIC_QUESTION_4
Compare the roles of the connection object and the cursor object in Python-MySQL connectivity. Which one manages transactions? Which one executes SQL?

## DIAGNOSTIC_ANSWER_4
The **connection object** represents the session with the database server and manages transactions (commit/rollback). The **cursor object** is used to execute SQL statements and fetch results. A wrong answer that swaps their roles shows confusion about the API design: the connection is the "session", the cursor is the "work pointer".

## DIAGNOSTIC_QUESTION_5
Evaluate the statement: "Once a connection is established, it remains open indefinitely unless the program crashes." Is this good practice? Why or why not?

## DIAGNOSTIC_ANSWER_5
No, it is not good practice. Connections consume server resources (memory, file descriptors, locks) and count toward the server's `max_connections` limit. Leaving them open causes connection leaks, leading to "Too many connections" errors. Connections must be closed explicitly in a `finally` block or via context managers. A wrong answer that agrees reveals a misunderstanding of resource management in production database applications.

## COMMON_MISCONCEPTION
Students often think that **importing the `mysql.connector` module automatically connects to the database**. They confuse the *module* (which provides the API) with the *connection object* created by `connect()`. This leads to errors like trying to call `cursor()` on the module (`mysql.connector.cursor()`) instead of on the connection object (`conn.cursor()`), resulting in `AttributeError: module 'mysql.connector' has no attribute 'cursor'`.

## ON_FAILURE
**Remediation:** Show the student two lines side-by-side:  
`import mysql.connector`  
`conn = mysql.connector.connect(host='localhost', user='root', password='pass', database='test')`  
Ask: "What is the type of `mysql.connector`?" (module) → "What is the type of `conn`?" (connection object).  
Then ask: "Which one has the `cursor()` method?" Have them run `print(dir(mysql.connector))` vs `print(dir(conn))` to see the methods. This concrete comparison clarifies that `connect()` *returns* the object you actually work with.

## WORKED_EXAMPLE_1
PROBLEM: A school wants to build a Python program to display student names from a MySQL table `students`. Outline the steps the programmer must follow, from installing the connector to closing the connection.

STEPS:
- Step 1: Identify the need for a MySQL connector for Python. The programmer installs `mysql-connector-python` using `pip install mysql-connector-python`.
- Step 2: Import the connector module in the Python script: `import mysql.connector`.
- Step 3: Establish a connection to the MySQL server using `mysql.connector.connect(host='localhost', user='root', password='pass', database='school')`. This returns a connection object `conn`.
- Step 4: Create a cursor object from the connection: `cursor = conn.cursor()`.
- Step 5: Execute a SELECT query: `cursor.execute("SELECT name FROM students")`.
- Step 6: Fetch all results: `rows = cursor.fetchall()`.
- Step 7: Iterate and print each student name: `for row in rows: print(row[0])`.
- Step 8: Close the cursor and connection: `cursor.close(); conn.close()`.

REASONING: Each step builds on the previous one. The connector provides the API, the connection authenticates and maintains the session, the cursor executes SQL and retrieves results, and closing releases server-side resources. Skipping any step breaks the chain.

ANSWER: The program will print all student names from the `students` table, one per line.

## WORKED_EXAMPLE_2
PROBLEM: A Python program connects to MySQL and executes an INSERT statement to add a new book to the `books` table, but the data does not appear in the table. The code does not call `conn.commit()`. Explain why the data is missing and correct the code.

STEPS:
- Step 1: Recognize that by default, `mysql-connector-python` uses `autocommit=False`.
- Step 2: Understand that DML statements (INSERT, UPDATE, DELETE) are part of a transaction.
- Step 3: The transaction must be committed explicitly with `conn.commit()` to make changes permanent in the database.
- Step 4: Modify the code to include `conn.commit()` after `cursor.execute()`.
- Step 5: Verify by querying the table again (SELECT) to confirm the row exists.

REASONING: Without `commit()`, the transaction remains uncommitted and is rolled back when the connection closes, so changes are never persisted. This is a critical concept for data integrity in any database application.

ANSWER: The data appears in the table only after adding `conn.commit()` after the INSERT execution.

## WORKED_EXAMPLE_3
PROBLEM: Design a Python function `get_student_fee(student_id)` that connects to a MySQL database `school`, queries the `fees` table for the given `student_id`, and returns the fee amount. Handle the case where the `student_id` is not found and ensure resources are always released.

STEPS:
- Step 1: Import `mysql.connector`.
- Step 2: Define the function with parameter `student_id`.
- Step 3: Inside a `try` block, establish connection using credentials: `conn = mysql.connector.connect(host='localhost', user='root', password='pass', database='school')`.
- Step 4: Create cursor and execute parameterized query: `cursor.execute("SELECT amount FROM fees WHERE student_id = %s", (student_id,))`.
- Step 5: Fetch one row: `row = cursor.fetchone()`.
- Step 6: If `row is N/A`, return `"Student not found"`; else return `row[0]`.
- Step 7: In `finally` block, close cursor and connection if they exist: `if cursor: cursor.close(); if conn: conn.close()`.
- Step 8: Call the function with a test `student_id` (e.g., `101`) and print result.

REASONING: This example combines connection, parameterized query (security against SQL injection), fetching a single row, conditional logic, and guaranteed resource cleanup via `try-finally`. It mirrors real-world patterns where a function encapsulates a single database lookup.

ANSWER: The function returns the fee amount (e.g., `5000`) if the student exists, or the string `"Student not found"` if no matching row exists.

## COMPETENCY_QUESTION_1
QUESTION: A student writes the following code to connect to MySQL and fetch data:
```python
import mysql.connector
conn = mysql.connector.connect(host='localhost', user='root', password='pass', database='test')
cursor = conn.cursor()
cursor.execute("SELECT * FROM users")
print(cursor.fetchall())
```
The program runs without errors but the output is empty, even though the `users` table has data. Identify **two** possible reasons and suggest fixes.

COMPETENCY: Error identification and correction
STEPS:
- Step 1: Check if the connection succeeded but pointed to the wrong database (e.g., `database='test'` but table is in `school`).
- Step 2: Verify the table name and column names match exactly (MySQL table names are case-sensitive on Linux).
- Step 3: Ensure `cursor.fetchall()` is called after `execute()` (it is).
- Step 4: Consider that another transaction may have uncommitted data (unlikely for SELECT).
- Step 5: Most likely reasons: (a) connected to wrong database, (b) table name case mismatch (e.g., `Users` vs `users`).

ANSWER: Two reasons: 1) The database `test` might not have the `users` table (maybe it's in another database). Fix: Verify the correct database name in `connect()`. 2) The table might be named `Users` (case-sensitive on Linux). Fix: Use exact case `SELECT * FROM Users`. Also ensure the MySQL server is running and accessible.

## COMPETENCY_QUESTION_2
QUESTION: In a banking application, a transfer of ₹5000 from Account A to Account B requires two UPDATE statements. Explain why both must succeed or both fail (atomicity), and how Python-MySQL connectivity supports this. Write a code snippet using `try-except-else` to implement the transfer with proper transaction control.

COMPETENCY: Translating real-world situations to code with transaction logic
STEPS:
- Step 1: Understand atomicity: transfer is a single logical operation; partial failure leaves data inconsistent.
- Step 2: Use a single connection (default `autocommit=False`).
- Step 3: Execute first UPDATE (debit A), then second UPDATE (credit B).
- Step 4: If both succeed, call `conn.commit()`. If any fails, call `conn.rollback()`.
- Step 5: Write code with `try-except-else`: on exception, rollback; else commit.
- Step 6: Close connection in `finally`.

ANSWER: 
```python
import mysql.connector
conn = mysql.connector.connect(host='localhost', user='root', password='pass', database='bank')
cursor = conn.cursor()
try:
    cursor.execute("UPDATE accounts SET balance = balance - 5000 WHERE acc_id = 'A'")
    cursor.execute("UPDATE accounts SET balance = balance + 5000 WHERE acc_id = 'B'")
except Exception as e:
    conn.rollback()
    print("Transfer failed:", e)
else:
    conn.commit()
    print("Transfer successful")
finally:
    cursor.close()
    conn.close()
```
Atomicity is ensured because either both updates are committed together or both are rolled back. The connection object manages the transaction boundary.
