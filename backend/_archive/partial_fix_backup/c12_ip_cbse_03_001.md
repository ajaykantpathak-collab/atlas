## DEFINITION
A computer network is a collection of interconnected computing devices (such as computers, servers, printers, and smartphones) linked by communication channels (wired or wireless) that enables them to share resources (hardware, software, data) and exchange information following defined protocols. The fundamental purpose is to facilitate resource sharing, communication, data exchange, and distributed processing among multiple users and systems.

## WALKTHROUGH
Imagine your school has 50 computers in the lab, but only one high-speed printer and one internet connection. Without a network, each computer would need its own printer and modem — expensive and impractical. A network connects all computers to the printer and internet through cables or Wi-Fi, letting everyone share these resources. Begin by asking: "What changes when computers are connected versus isolated?" Guide students to identify shared hardware (printer, scanner), shared software (licensed applications), shared data (central database), and communication (email, chat). Emphasize that a network requires not just physical connections but also agreed-upon rules (protocols) for communication. The key insight: a network is defined by its *function* (sharing and communication), not just its wires.

## DIAGNOSTIC_QUESTION_1
Define a computer network in one sentence using the terms 'nodes', 'links', and 'protocols'.

## DIAGNOSTIC_ANSWER_1
A computer network is a set of nodes (computing devices) connected by links (communication channels) that communicate using common protocols to share resources and information. A wrong answer that only mentions "computers connected by cables" reveals the misconception that physical connection alone constitutes a network, ignoring the essential role of protocols and the purpose of resource sharing.

## DIAGNOSTIC_QUESTION_2
Explain why simply connecting two laptops with an Ethernet cable does not automatically create a functional computer network.

## DIAGNOSTIC_ANSWER_2
A functional network requires configured network interfaces, agreed-upon protocols (e.g., TCP/IP), addressing (IP addresses), and enabled sharing services — the cable is only the physical medium. A student who says "they are connected, so it's a network" confuses physical connectivity with logical networking; they miss that protocols and configuration are mandatory for communication and resource sharing.

## DIAGNOSTIC_QUESTION_3
A school has 30 standalone PCs. The principal wants to buy a single high-capacity printer for all. List the minimum network components and configuration steps needed to achieve this, and explain how this demonstrates the purpose of resource sharing.

## DIAGNOSTIC_ANSWER_3
Components: 30 NICs, a switch, 30 Ethernet cables, printer with network interface or print server. Configuration: assign IP addresses, install printer driver on server, share printer, map on each PC. This demonstrates resource sharing — one printer serves 30 users, reducing cost and maintenance. A wrong answer listing only cables and switch shows the student focuses on hardware but misses the software/configuration layer that enables sharing.

## DIAGNOSTIC_QUESTION_4
Compare and contrast a computer network with a distributed system. Identify two similarities and two differences.

## DIAGNOSTIC_ANSWER_4
Similarities: both involve multiple computers communicating over links; both share resources. Differences: (1) In a network, users are aware of multiple machines (explicit login, file transfer); in a distributed system, the collection appears as a single coherent system (transparency). (2) Networks focus on connectivity and communication; distributed systems focus on unified computation and fault tolerance. A student equating the two misses the transparency and single-system-image distinction central to distributed systems.

## DIAGNOSTIC_QUESTION_5
Evaluate the statement: "A computer network's primary purpose is to connect computers." Justify your answer with reference to the definition of a network.

## DIAGNOSTIC_ANSWER_5
The statement is incomplete. Connection is the *means*, not the *purpose*. The definition centers on resource sharing (hardware, software, data) and communication — connection enables these. A network that connects computers but shares no resources serves no practical purpose. A student agreeing with the statement confuses infrastructure with objective; they need to distinguish between the physical topology and the functional goals.

## DIAGNOSTIC_QUESTION_6
Design a minimal network scenario for a home with three devices (laptop, smart TV, phone) that need to share a single internet connection and stream videos from the laptop to the TV. Draw a labeled diagram and list the required network elements (hardware, software, protocols).

## DIAGNOSTIC_ANSWER_6
Diagram: ISP modem → wireless router (AP + switch) → laptop (Wi-Fi), smart TV (Wi-Fi), phone (Wi-Fi). Elements: modem (WAN interface), router (NAT, DHCP, firewall), Wi-Fi (802.11), TCP/IP stack on all devices, DLNA/miracast for streaming. A poor answer showing only a router and devices without protocols (DHCP, NAT, TCP/IP) or streaming protocol reveals a hardware-only mental model, missing the layered protocol architecture that makes sharing work.

## COMMON_MISCONCEPTION
Students often equate a computer network with its physical components (cables, routers, switches) and overlook that a network is fundamentally a *logical* construct defined by protocols and services. They write "a network is computers connected by wires" in exams, losing marks because the NCERT definition emphasizes "interconnected computers *that can communicate and share resources* using *common communication protocols*." This error stems from seeing the visible hardware but not the invisible protocol stack (TCP/IP, HTTP, SMB) that enables sharing. For example, two PCs linked by a cable but with firewalls blocking all traffic and no file sharing enabled are physically connected but functionally *not* a network — a distinction that appears in CBSE case-based questions.

## ON_FAILURE
If the student defines a network only by hardware, do this 3-step remediation: (1) Show two laptops connected by a cable with file sharing OFF — ping fails, no shared folders visible. Ask: "Is this a network?" (2) Enable file sharing, set static IPs, verify ping and folder access. Ask: "What changed? The cable is same." (3) Have them write the NCERT definition highlighting "protocols" and "resource sharing." Re-test with Diagnostic Question 2.

## WORKED_EXAMPLE_1
PROBLEM: A small office has 10 computers, one laser printer, one scanner, and one broadband internet connection. Currently each computer has its own printer and uses mobile hotspot for internet. The owner wants to network them to share the printer, scanner, and internet. List the additional hardware, software configuration, and protocols required. Calculate the cost saving if a printer costs ₹8,000, scanner ₹5,000, and each mobile hotspot ₹300/month (assume 12 months).
STEPS:
- Step 1: Identify current state — 10 printers, 10 scanners, 10 hotspots = 10×(8000+5000) + 10×300×12 = ₹1,30,000 + ₹36,000 = ₹1,66,000 first year.
- Step 2: Identify networked state — 1 printer, 1 scanner, 1 broadband (assume ₹10,000 setup + ₹800/month) = ₹13,000 + ₹9,600 = ₹22,600 first year.
- Step 3: Additional hardware for network: 10 NICs (built-in), 1 switch (₹1,500), 10 Ethernet cables (₹200 each = ₹2,000), 1 wireless router for Wi-Fi (₹2,500) = ₹6,000.
- Step 4: Software configuration: Enable file/printer sharing on OS, install printer/scanner drivers on server PC, configure DHCP on router, set up NAT for internet sharing.
- Step 5: Protocols: TCP/IP (addressing, routing), SMB/CIFS (file/printer sharing), HTTP/HTTPS (web), DHCP (auto IP), NAT (internet sharing).
- Step 6: Savings = ₹1,66,000 - (₹22,600 + ₹6,000) = ₹1,37,400 in first year.
REASONING: This example quantifies the "resource sharing" purpose — the core reason networks exist. It connects hardware, software, and protocols to tangible cost reduction, showing that a network is an investment that pays off by eliminating redundant peripherals and connections.
ANSWER: Hardware: switch, cables, router; Software: sharing services, drivers, DHCP/NAT config; Protocols: TCP/IP, SMB, DHCP, NAT; First-year saving: ₹1,37,400.

## WORKED_EXAMPLE_2
PROBLEM: A school computer lab has 40 PCs connected via a switch to a Linux server. The server hosts a student database (MySQL), a shared folder for assignments (Samba), and runs a print queue for a network printer. Students log in from any PC, access their files, submit assignments, and print. Identify which network purposes are served by each service, and explain what would happen if the switch failed but the server and PCs remained powered on.
STEPS:
- Step 1: Map services to purposes: MySQL database → data sharing (centralized student records); Samba shared folder → file sharing (assignments); Print queue → hardware sharing (printer); Linux login (LDAP/SSH) → user authentication/access control.
- Step 2: Identify communication purpose: Students communicate with server (request-response) and potentially peer-to-peer (if enabled).
- Step 3: Analyze switch failure: Switch operates at Layer 2 (data link). If it fails, all PCs lose Layer 2 connectivity to server and each other — no frames delivered.
- Step 4: Consequence: No IP packets can reach server → database inaccessible, shared folders unreachable, print jobs fail, logins fail. Network is down despite working endpoints.
- Step 5: Insight: Physical connectivity (switch) is necessary but not sufficient; the logical services (purposes) depend on the entire stack.
REASONING: This example ties each network service to a specific purpose from the definition, and uses a failure scenario to test understanding that the network is a system — the purpose is achieved only when all layers work. It prepares students for troubleshooting questions in board exams.
ANSWER: Purposes: data sharing (MySQL), file sharing (Samba), hardware sharing (printer), authentication (login). Switch failure → complete loss of connectivity → all purposes fail.

## WORKED_EXAMPLE_3
PROBLEM: Design a network for a 3-floor library with 20 catalog PCs (ground floor), 10 research PCs (first floor), 5 admin PCs (second floor), one central server (ground floor), and two network printers (one per upper floor). Requirements: catalog PCs access book database only; research PCs access database + internet + shared journals; admin PCs access everything including payroll. All PCs must print to nearest printer. Draw topology, assign VLANs, and list protocols for each requirement.
STEPS:
- Step 1: Topology: Star per floor — each floor has a switch; three floor switches connect to a core switch (ground floor) which connects to server and router.
- Step 2: VLANs: VLAN 10 (Catalog, ground), VLAN 20 (Research, first), VLAN 30 (Admin, second), VLAN 40 (Servers), VLAN 50 (Printers). Inter-VLAN routing on core switch/router.
- Step 3: Access control: ACLs on router — VLAN 10 → only DB port (3306) on server; VLAN 20 → DB + internet (80/443) + journal server; VLAN 30 → all.
- Step 4: Printing: Printers in VLAN 50; each VLAN allowed to print via print server (IPP port 631) on nearest printer.
- Step 5: Protocols: TCP/IP (base), MySQL (3306) for DB, HTTP/HTTPS (80/443) for internet, SMB (445) for journals, IPP (631) for printing, DHCP for IP assignment, DNS for name resolution, 802.1Q for VLAN tagging.
- Step 6: Verify: Catalog PC → DB works, internet blocked; Research → DB, internet, journals work; Admin → all work; Print jobs route to correct printer.
REASONING: This advanced example combines the network purpose (selective resource sharing) with segmentation (VLANs), access control (ACLs), and service-specific protocols — mirroring CBSE competency questions that ask for "design a network for given requirements." It shows how the basic definition scales to real-world policy enforcement.
ANSWER: Topology: hierarchical star; VLANs: 10,20,30,40,50; Protocols: TCP/IP, MySQL, HTTP/S, SMB, IPP, DHCP, DNS, 802.1Q; Access enforced via inter-VLAN ACLs.

## COMPETENCY_QUESTION_1
QUESTION: A teacher says: "If I connect all lab computers with cables, I have a network." A student replies: "No, you also need to configure IP addresses and enable file sharing." Who is correct? Justify your answer using the definition of a computer network. List two protocols that must be active for file sharing to work.
COMPETENCY: Error identification and correction
STEPS:
- Step 1: Recall the definition — network requires interconnection AND communication via protocols for resource sharing.
- Step 2: Evaluate teacher's statement: cables provide physical layer only; no logical communication or sharing → incorrect.
- Step 3: Evaluate student's statement: IP addresses (network layer) and file sharing (application layer) are necessary for sharing → correct.
- Step 4: Identify protocols: TCP/IP for addressing/routing, SMB/CIFS for file sharing (or NFS).
ANSWER: The student is correct. A network is defined by its ability to share resources and communicate using protocols, not merely by physical cables. Two essential protocols: TCP/IP (for logical addressing and delivery) and SMB/CIFS (for file/printer sharing services).
DIFFICULTY: medium

## COMPETENCY_QUESTION_2
QUESTION: A startup has 5 employees working remotely from different cities. They need to collaboratively edit documents, share a code repository, hold video meetings, and access a central customer database securely. The founder proposes: "Let's buy a server, put it in the office, and connect everyone via VPN." Analyze this proposal. Identify which network purposes are served, which are not fully addressed, and suggest two improvements with specific technologies.
COMPETENCY: Translating real-world situations to network design
STEPS:
- Step 1: Map requirements to purposes: collaborative editing → file/data sharing; code repo → data sharing + version control; video meetings → real-time communication; customer DB → data sharing + security.
- Step 2: Evaluate VPN + office server: Serves centralized data sharing (DB, repo, files) and secure remote access (VPN encrypts traffic) → good for sharing and security.
- Step 3: Identify gaps: (1) Video meetings over VPN may suffer latency/jitter if server is far; (2) Collaborative editing on office server may be slow for remote users; (3) Single point of failure (office internet/power).
- Step 4: Improvement 1: Use cloud-based collaboration (Google Workspace / Microsoft 365) for real-time editing and video — offloads latency-sensitive traffic from VPN.
- Step 5: Improvement 2: Host code repo and DB on cloud (GitHub, AWS RDS) with VPN only for legacy systems — improves availability and performance.
- Step 6: Protocols involved: IPsec/OpenVPN (VPN), HTTPS (cloud services), WebRTC (video), Git (repo), TLS (database encryption).
ANSWER: Proposal serves resource sharing and secure access but not optimally for real-time collaboration and video. Improvements: (1) Move collaborative editing and video to cloud SaaS (Google Meet, Docs) using HTTPS/WebRTC; (2) Host repository and database on cloud (GitHub, AWS) with TLS, reducing VPN load and improving uptime.
DIFFICULTY: hard
