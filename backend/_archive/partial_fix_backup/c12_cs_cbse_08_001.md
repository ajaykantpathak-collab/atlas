## DEFINITION
A data structure is a specialized format for organizing, processing, retrieving, and storing data in a computer's memory so that it can be accessed and modified efficiently. It defines the logical relationship between individual data elements and the operations allowed on them (insertion, deletion, traversal, search, sort).

## WALKTHROUGH
Imagine you are building a contact list app for your phone. You need to store names and numbers, but you also need to quickly search for a contact, add new ones, delete old ones, and maybe even show them in alphabetical order. If you just dump everything in a single long text file, searching becomes painfully slow as the list grows. This is exactly why we need data structures — they are like different types of storage cabinets (some like stacked plates, some like a queue at a ticket counter, some like a family tree) each optimized for specific access patterns. We begin by asking: "How is the data logically related?" If elements are in a sequence (one after another), it's linear; if they branch out, it's non-linear. Then we ask: "Does the size need to change at runtime?" That decides static vs dynamic. By the end of this node, you will be able to look at a problem (e.g., undo feature in a text editor) and immediately say: "This needs a stack because it follows LIFO."

## DIAGNOSTIC_QUESTION_1
What is the fundamental difference between a linear data structure and a non-linear data structure? Give one example of each.

## DIAGNOSTIC_ANSWER_1
Linear data structures arrange elements in a sequential order where each element has a unique predecessor and successor (except first and last), e.g., array, stack, queue, linked list. Non-linear data structures arrange elements hierarchically or in a network where an element can be connected to multiple others, e.g., tree, graph. A wrong answer (e.g., "linear means sorted, non-linear means unsorted") reveals confusion between logical arrangement and physical ordering; the student is conflating data organization with data values.

## DIAGNOSTIC_QUESTION_2
A student says: "An array is a dynamic data structure because we can add elements to it by writing code like `arr.append(5)` in Python." Is this statement correct? Explain why or why not.

## DIAGNOSTIC_ANSWER_2
The statement is incorrect. In the context of data structure classification (as per NCERT), an array is a **static** data structure because its size is fixed at compile time / declaration and cannot be changed during runtime in languages like C/C++. Python's `list` is a dynamic array implementation that handles resizing internally, but the abstract data structure "array" is static. A wrong answer reveals the student is confusing the high-level language feature (Python list) with the fundamental data structure concept (static vs dynamic memory allocation).

## DIAGNOSTIC_QUESTION_3
You are designing a system to manage the "Undo" functionality in a text editor. Which data structure would you choose and why? Explain the principle it follows.

## DIAGNOSTIC_ANSWER_3
A **stack** is the appropriate data structure because the Undo operation must reverse the most recent action first (Last In, First Out – LIFO). Each user action (typing, delete, format) is pushed onto the stack; when Undo is pressed, the top action is popped and reversed. If the student chooses queue (FIFO), they misunderstand the temporal order required — undo must revert the latest change, not the earliest.

## DIAGNOSTIC_QUESTION_4
Compare and contrast the memory representation of a static array and a linked list. How does this difference affect insertion at the beginning?

## DIAGNOSTIC_ANSWER_4
A static array uses contiguous memory locations; inserting at the beginning requires shifting all existing elements one position right (O(n) time). A linked list uses non-contiguous memory (nodes linked by pointers); inserting at the beginning only requires creating a new node and updating its `next` pointer to the current head (O(1) time). A student who says "both are O(1)" ignores the shifting cost in arrays; a student who says "linked list is always faster" ignores the extra memory overhead per node and lack of cache locality.

## DIAGNOSTIC_QUESTION_5
Evaluate the statement: "A tree is just a special case of a graph." Is this true? Justify your answer with reference to the definitions of both data structures.

## DIAGNOSTIC_ANSWER_5
Yes, it is true. A graph is a collection of vertices (nodes) and edges connecting them, with no restrictions on cycles or number of parents. A tree is a connected, acyclic graph where each node (except root) has exactly one parent. Thus, every tree is a graph, but not every graph is a tree. A student who says "no, they are completely different" fails to recognize the hierarchical relationship in the mathematical definitions.

## DIAGNOSTIC_QUESTION_6
Create a real-world scenario (not from the textbook) that requires a **queue** data structure. Describe the entities, the operations performed, and why FIFO is essential.

## DIAGNOSTIC_ANSWER_6
Example: A hospital emergency room triage system. Patients (entities) are enqueued upon arrival with a priority tag (but within same priority, FIFO). Operations: `enqueue` (new patient arrives), `dequeue` (doctor calls next patient), `peek` (view next patient without removing). FIFO is essential because medical ethics and fairness demand that patients with the same urgency are treated in order of arrival. A poor answer would describe a stack-like scenario (e.g., "undo button") or a scenario where priority alone decides (ignoring FIFO within priority).

## COMMON_MISCONCEPTION
Students often believe that "data structure" and "data type" are synonyms. They write: "Integer, float, string are data structures." This is wrong because **primitive data types** (int, float, char, boolean) are built-in and hold a single value, whereas **data structures** are user-defined or composite organizations of multiple data elements with specific logical relationships and operations. The confusion arises because Python lists and dictionaries are both built-in types AND data structures, blurring the line. In C/C++, the distinction is sharp: `int` is a data type, `struct node { int data; node* next; }` is a data structure.

## ON_FAILURE

(4) Re-diagnose with: "Is a Python `list` a primitive data type? Why or why not?" (Answer: No, it's a dynamic array data structure because it holds multiple elements and supports operations like append/pop).

## WORKED_EXAMPLE_1
PROBLEM: A school library wants to digitize its book issue/return system. Each book has a unique ID. When a book is returned, it is placed on a "reshelving trolley". The librarian always picks the book from the top of the trolley to put back on the shelf. Identify the data structure that models this trolley, state its organizing principle, and list the two primary operations with their standard names.

STEPS:
- Step 1: Identify the real-world behavior — books are added to the top and removed from the top.
- Step 2: Recognize the access pattern — the last book placed is the first one taken out (Last In, First Out).
- Step 3: Map LIFO behavior to the standard data structure — this is a Stack.
- Step 4: Name the operations — adding a book is `push`, removing a book is `pop`.
- Step 5: Verify — if the trolley were a queue (FIFO), the first returned book would be reshelved first, which is not what the librarian does.

REASONING: The physical constraint of a vertical stack (trolley) forces LIFO access. In software, a stack abstracts this behavior: `push` adds to top, `pop` removes from top. No other element can be accessed directly, ensuring the invariant.

ANSWER: Data structure: Stack. Principle: LIFO (Last In, First Out). Operations: `push` (insert), `pop` (delete).

## WORKED_EXAMPLE_2
PROBLEM: A restaurant uses a digital token system. Customers receive a token number on arrival. The counter displays the next token to be served. When a customer is served, their token is removed from the display. Model this system using a data structure. Identify the structure, its principle, and the operations for "new arrival" and "customer served".

STEPS:
- Step 1: Observe the order of service — the customer who arrived first (earliest token) is served first.
- Step 2: Recognize the access pattern — First In, First Out (FIFO).
- Step 3: Map FIFO to the standard data structure — this is a Queue.
- Step 4: Name the operations — new arrival adds to rear: `enqueue`; customer served removes from front: `dequeue`.
- Step 5: Contrast with stack — if it were a stack, the last arrival would be served first (unfair).

REASONING: A queue maintains two pointers (front and rear). `enqueue` inserts at rear, `dequeue` deletes from front. This preserves arrival order, which is essential for fairness in service systems.

ANSWER: Data structure: Queue. Principle: FIFO (First In, First Out). Operations: `enqueue` (insert at rear), `dequeue` (delete from front).

## WORKED_EXAMPLE_3
PROBLEM: A social media app wants to implement a "Mutual Friends" feature. For a given user, it must quickly find friends who are also friends with another specific user. The friend network is large and constantly changing (users add/remove friends daily). Which data structure category (linear/non-linear) and which specific structure (from array, linked list, stack, queue, tree, graph) is most suitable? Justify with two reasons.

STEPS:
- Step 1: Analyze the relationships — users are nodes, friendships are edges. A user can have many friends; friends have their own friends. This is a network, not a sequence.
- Step 2: Classify — non-linear data structure (graph).
- Step 3: Eliminate linear structures — array, linked list, stack, queue cannot naturally represent many-to-many connections.
- Step 4: Eliminate tree — a tree has no cycles and each node has one parent; friend networks have cycles (A-B-C-A) and multiple connections.
- Step 5: Select graph — specifically an undirected graph (friendship is mutual). Representation: adjacency list (using linked lists or dynamic arrays per vertex) for memory efficiency and fast neighbor iteration.
- Step 6: Justify operations — `add_friend` = add edge (O(1) with adjacency list), `find_mutual` = intersection of neighbor sets (O(deg(u) + deg(v))).

REASONING: Graphs are the only non-linear structure that natively models arbitrary pairwise relationships with cycles. Adjacency list representation balances memory (O(V+E)) and speed for sparse social networks.

ANSWER: Category: Non-linear. Structure: Graph (undirected, adjacency list representation). Reasons: (1) Naturally models many-to-many relationships with cycles. (2) Supports efficient dynamic updates (add/remove edges) and neighbor traversal for mutual friend queries.

## COMPETENCY_QUESTION_1
QUESTION: A developer is building a navigation app that shows the shortest route between two locations on a map. The map consists of intersections (nodes) connected by roads (edges with distances). The app must handle real-time traffic updates that change road distances dynamically. 
(a) Which data structure category (linear/non-linear) should model the road network? Why?
(b) Which specific structure (array, linked list, stack, queue, tree, graph) is appropriate? Why?
(c) If the developer uses an adjacency matrix to represent this graph, what is the space complexity for 10,000 intersections? Is this practical? Explain.

COMPETENCY: Translating real-world situations to mathematical/computational models
STEPS:
- Step 1: Recognize that road networks have many-to-many connections with cycles → non-linear.
- Step 2: Select graph as the only non-linear structure supporting arbitrary connections and cycles.
- Step 3: Calculate adjacency matrix space = V² = 10,000² = 100 million entries. Each entry stores distance (e.g., 4 bytes) → 400 MB minimum. For sparse graphs (average degree ~4), adjacency list uses O(V+E) ≈ 10,000 + 40,000 = 50,000 entries → ~200 KB. Matrix is impractical.
- Step 4: Conclude adjacency list (dynamic array or linked list per vertex) is better for sparse, dynamic graphs.

ANSWER: (a) Non-linear — roads form a network with multiple paths and cycles. (b) Graph (weighted, undirected) — only structure that models arbitrary connections with edge weights. (c) Space = O(V²) = 100M entries ≈ 400 MB (if 4 bytes/entry). Impractical for sparse graph; adjacency list (O(V+E)) uses ~200 KB and allows faster updates for traffic changes.
DIFFICULTY: medium

QUESTION: Consider the following Python code snippet:
```python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = N/A

head = Node(10)
head.next = Node(20)
head.next.next = Node(30)
```
(a) Draw the memory diagram showing the three nodes and their links.
(b) What is the time complexity to insert a new node with value 5 at the **beginning** of this structure? At the **end**?
(c) If this were a Python `list` [10, 20, 30], what would be the time complexity for the same two insertions?
(d) Based on (b) and (c), explain why a linked list is preferred over a dynamic array when frequent insertions at the beginning are required.

COMPETENCY: Comparing and justifying computational efficiency
STEPS:
- Step 1: Draw three boxes with `data` and `next` arrow pointers: 10 → 20 → 30 → N/A.
- Step 2: Insert at beginning: create node(5), set its `next` to head, update head → O(1). Insert at end: traverse to last node (30), set its `next` to new node → O(n).
- Step 3: Python list insert at beginning: `list.insert(0, 5)` shifts all elements right → O(n). Insert at end: `list.append(5)` amortized O(1).
- Step 4: Linked list wins for front insertion (O(1) vs O(n)); array wins for end insertion (amortized O(1) vs O(n)) and cache locality. Choose linked list when front insertions dominate.

ANSWER: (a) 10 → 20 → 30 → N/A. (b) Beginning: O(1), End: O(n). (c) List beginning: O(n), List end: O(1) amortized. (d) Linked list avoids shifting all elements on front insertion because nodes are non-contiguous; only pointer update needed. Dynamic array must shift all elements to make room at index 0.
