## DEFINITION
A string in Python is an immutable sequence of Unicode characters enclosed within single quotes (' '), double quotes (" "), or triple quotes (''' ''' or """ """) used to represent textual data.

## WALKTHROUGH
Imagine you are building a program to store student details for your school's annual day. You need to store names like "Aarav", addresses like "Sector 14, Gurugram", and multi-line messages like the event invitation. How does Python store this text? Unlike numbers, text is a *sequence* of individual characters. Python uses the **string** data type for this. Begin by typing `name = "Aarav"` in the shell. Notice the quotes. Now try `address = 'Sector 14, Gurugram'` — single quotes work too. For the multi-line invitation, you need triple quotes: `msg = '''Dear Parents,\nYou are invited...'''`. The key insight: **strings are sequences** — Python treats "Aarav" as an ordered collection ['A','a','r','a','v'], which enables powerful operations later. Also note: once created, a string *cannot be changed* (immutable), a concept we'll verify in node c11_cs_cbse_06_007.

## DIAGNOSTIC_QUESTION_1
What is the output of `print(type('5'))` and why is it different from `print(type(5))`?

## DIAGNOSTIC_ANSWER_1
Output: `<class 'str'>` for `'5'` and `<class 'int'>` for `5`. The quotes make `'5'` a string (text), while `5` without quotes is an integer (number). A wrong answer (e.g., both are `<class 'int'>`) reveals the student thinks quotes are decorative or that Python automatically converts numeric-looking strings to numbers.

## DIAGNOSTIC_QUESTION_2
Explain why `path = 'C:\new_folder\test.txt'` prints incorrectly but `path = r'C:\new_folder\test.txt'` works. What does the `r` prefix do?

## DIAGNOSTIC_ANSWER_2
In the first string, `\n` is interpreted as a newline escape sequence and `\t` as a tab, corrupting the path. The `r` prefix creates a **raw string** where backslashes are treated literally. A wrong answer (e.g., "r means string") shows the student doesn't understand escape sequences or that backslash has special meaning inside normal strings.

## DIAGNOSTIC_QUESTION_3
Write a Python statement to store the exact text: `He said, "Python's syntax is easy!"` including both single and double quotes. Test your answer mentally.

## DIAGNOSTIC_ANSWER_3
`msg = 'He said, "Python\'s syntax is easy!"'` (using outer single quotes, escaping the inner single quote) OR `msg = "He said, \"Python's syntax is easy!\""` (outer double quotes, escaping inner double quotes) OR `msg = '''He said, "Python's syntax is easy!"'''` (triple quotes avoid escaping). A wrong answer using mismatched quotes like `"He said, "Python's..."` reveals confusion about quote nesting and escaping rules.

## DIAGNOSTIC_QUESTION_4
Compare: `s1 = "Hello"` and `s2 = 'Hello'`. Are they identical in every way? Justify using memory and type concepts.

## DIAGNOSTIC_ANSWER_4
Yes, they are identical. Both create a `str` object with the same character sequence, same length, same methods, and same memory representation. Python does not distinguish between single and double quoted strings. A wrong answer claiming they are different types or have different methods reveals a fundamental misunderstanding of string representation in Python.

## DIAGNOSTIC_QUESTION_5
A student writes `name = "Aarav"` then `name[0] = "K"` to change it to "Karav". Predict the error and explain why this violates a core property of strings.

## DIAGNOSTIC_ANSWER_5
It raises `TypeError: 'str' object does not support item assignment`. Strings are **immutable** — you cannot modify characters in-place. Any "modification" creates a new string. A wrong answer expecting "Karav" or no error shows the student treats strings like mutable lists (a common confusion from other languages or from later list chapters).

## COMMON_MISCONCEPTION
Students believe **single quotes are for characters and double quotes are for strings** (like in C/Java). In Python, `'a'` and `"a"` are both strings of length 1 — there is no separate `char` type. This leads to errors like trying to declare `char grade = 'A'` or thinking `len('a')` is invalid. They also think triple quotes are only for comments/docstrings, not realizing they are multi-line string literals.

## WORKED_EXAMPLE_1
PROBLEM: A school library system needs to store a book's title, author, and a multi-line summary. Title: "The White Tiger", Author: 'Aravind Adiga', Summary: a paragraph with quotes and line breaks. Write Python code to store all three in variables using the most appropriate quote style for each. Explain your choice.
STEPS:
- Step 1: Identify that title has no internal quotes → use double quotes for clarity: `title = "The White Tiger"`
- Step 2: Author has no quotes but we'll use single quotes to show variety: `author = 'Aravind Adiga'`
- Step 3: Summary contains both single and double quotes AND multiple lines → must use triple quotes to avoid escaping: `summary = '''The novel "The White Tiger" won the Booker Prize.\nIt's a darkly humorous story.'''`
- Step 4: Verify by printing all three: `print(title)`, `print(author)`, `print(summary)`
- Step 5: Confirm output preserves line breaks and quotes exactly as intended.
REASONING: Triple quotes are the only style that natively handles multi-line text and mixed quotes without escape sequences. Single/double quotes are interchangeable for single-line strings; using both styles demonstrates flexibility.
ANSWER:
```python
title = "The White Tiger"
author = 'Aravind Adiga'
summary = '''The novel "The White Tiger" won the Booker Prize.
It's a darkly humorous story.'''
```

## WORKED_EXAMPLE_2
PROBLEM: Write a Python program to store a Windows file path `D:\Projects\Python\test.txt` in a variable and print it. First attempt uses normal string, second uses raw string. Show both outputs and explain the difference.
STEPS:
- Step 1: Normal string attempt: `path1 = "D:\Projects\Python\test.txt"`
- Step 2: Print `path1` → observe `\P` is not a valid escape, but `\t` (tab) and `\t` in `test.txt`? Actually `\P` is kept as `\P`, but `\t` becomes tab. Output: `D:\Projects\Python	est.txt` (tab before est.txt)
- Step 3: Raw string attempt: `path2 = r"D:\Projects\Python\test.txt"`
- Step 4: Print `path2` → backslashes preserved: `D:\Projects\Python\test.txt`
- Step 5: Explain: In normal strings, `\t` = tab, `\n` = newline. Raw strings (prefix r) treat backslashes literally.
REASONING: File paths contain backslashes which are escape triggers. Raw strings prevent misinterpretation. This is critical for Windows paths in Python.
ANSWER:
```python
path1 = "D:\Projects\Python\test.txt"
print(path1)  # Output: D:\Projects\Python	est.txt  (tab inserted)
path2 = r"D:\Projects\Python\test.txt"
print(path2)  # Output: D:\Projects\Python\test.txt  (correct)
```

## WORKED_EXAMPLE_3
PROBLEM: Combine concepts: A student writes code to "modify" a string. Predict the error, explain why, then show the correct way to achieve the intended result (change "Delhi" to "Mumbai" in address).
STEPS:
- Step 1: Code: `addr = "Delhi, India"; addr[0] = "M"; print(addr)`
- Step 2: Run mentally → `TypeError: 'str' object does not support item assignment`
- Step 3: Reason: Strings are immutable — cannot change character at index 0.
- Step 4: Correct approach: Create NEW string via slicing+concatenation (future node) or `replace()`: `new_addr = addr.replace("Delhi", "Mumbai")`
- Step 5: Verify: `print(new_addr)` → `Mumbai, India`; original `addr` unchanged.
- Step 6: Key insight: "Modifying" a string always produces a new string object.
REASONING: Immutability is a core design choice in Python for performance (hashability, interning) and safety. Students must unlearn mutable-array thinking from other languages.
ANSWER:
Error: `TypeError`. Correct: `new_addr = addr.replace("Delhi", "Mumbai")` produces `"Mumbai, India"`.

## COMPETENCY_QUESTION_2
QUESTION: Design a Python program for a **Railway Ticket** that stores: PNR (10-digit string), passenger name (with title like "Mr./Ms."), multi-line boarding address, and a fixed disclaimer. Choose the best quote style for each field. Write the code. Then explain what happens if you try to update the PNR by `pnr[3] = '5'` and how to correctly "update" it.
COMPETENCY: Applying string creation, immutability, and correct quote-style selection to a real-world domain (Indian Railways).
STEPS:
- Step 1: PNR → 10-digit string: `pnr = "1234567890"` (digits as string, not int, to preserve leading zeros).
- Step 2: Name with title: `name = "Mr. Arjun Kumar"` (double quotes, contains dot and space).
- Step 3: Multi-line address: `address = '''Flat 302, Sunrise Apartments\nSector 12, Dwarka\nNew Delhi - 110075'''`
- Step 4: Disclaimer (fixed, maybe long): `disclaimer = "This ticket is non-transferable. Valid only with valid ID proof."`
- Step 5: Attempt `pnr[3] = '5'` → `TypeError` (strings immutable).
- Step 6: Correct update: `pnr = pnr[:3] + '5' + pnr[4:]` (slicing+concatenation) or `pnr = pnr.replace(pnr[3], '5', 1)` (replace first occurrence).
ANSWER:
```python
pnr = "1234567890"
name = "Mr. Arjun Kumar"
address = '''Flat 302, Sunrise Apartments
Sector 12, Dwarka
New Delhi - 110075'''
disclaimer = "This ticket is non-transferable. Valid only with valid ID proof."
# pnr[3] = '5' → TypeError
# Correct: pnr = pnr[:3] + '5' + pnr[4:]
```
