## DEFINITION
A computer network is an interconnected collection of autonomous computing devices (nodes) that communicate and share resources (data, hardware, software) through a shared transmission medium governed by standardized communication protocols.

## WALKTHROUGH
Imagine you and three friends are working on a group project from different homes. You need to share a large dataset, a single licensed software tool, and a high-resolution printer — but email attachments are too slow, the software license allows only one install, and the printer is at one friend's house. This is the exact problem computer networks solve: they let autonomous devices share resources seamlessly. Begin by listing every resource you use daily that could be shared (files, printers, internet connection, applications). Then ask: "What minimum elements must exist for two computers to exchange a file?" Guide students to identify sender, receiver, medium, and agreed-upon rules (protocol). The key insight: a network is not just cables — it is a *system of agreements* that makes sharing possible without physical transfer.

## DIAGNOSTIC_QUESTION_1
Define a computer network in your own words, and state the one characteristic that distinguishes it from a mere collection of computers connected by cables.

## DIAGNOSTIC_ANSWER_1
A computer network is a set of autonomous computers interconnected by a transmission medium to share resources and information using common protocols. The distinguishing characteristic is **autonomy** — each computer operates independently and can function without the network; if one fails, others continue working. A wrong answer that focuses only on "cables connecting computers" reveals the misconception that physical connection alone constitutes a network, ignoring the logical layer of protocols and resource-sharing purpose.

## DIAGNOSTIC_QUESTION_2
A school has 20 computers in a lab, all connected to a central switch. The switch is not connected to the internet or any server. Students can only run programs installed locally on each machine. Is this a computer network? Justify your answer using the definition of resource sharing.

## DIAGNOSTIC_ANSWER_2
No, this is not a computer network in the functional sense. Although the computers are physically interconnected, no resources (files, printers, applications, internet) are being shared between them — each operates as a standalone system. A wrong answer claiming "yes, because they are connected by cables" reveals the misconception that physical topology equals a network. The student must understand that *resource sharing* is the defining purpose; without it, the infrastructure is merely a potential network, not an operational one.

## DIAGNOSTIC_QUESTION_3
Your family has a desktop, a laptop, a smartphone, and a smart TV. You want to print a document from the smartphone to a USB printer connected to the desktop, and stream a movie from the laptop to the smart TV. List the four essential network components required for each scenario and identify which component differs between the two.

## DIAGNOSTIC_ANSWER_3
For printing: Sender = smartphone, Receiver = desktop (attached to printer), Medium = Wi-Fi (home router), Protocol = IP/TCP/printing protocol (e.g., IPP). For streaming: Sender = laptop, Receiver = smart TV, Medium = Wi-Fi (same router), Protocol = IP/TCP/streaming protocol (e.g., DLNA/UPnP). The **protocol** differs because printing and streaming require different application-layer rules. A wrong answer that lists the same protocol for both reveals the misconception that "the network" uses one universal protocol for all tasks, rather than a protocol stack where the application layer changes with the service.

## DIAGNOSTIC_QUESTION_4
Compare the resource-sharing capabilities of a peer-to-peer (P2P) network of three laptops versus a client-server network with one server and three clients. In which scenario does the failure of one device cause the greatest disruption to resource access? Explain why.

## DIAGNOSTIC_ANSWER_4
In the client-server model, failure of the **server** disrupts resource access for all three clients simultaneously because the server is the centralized resource provider. In the P2P model, failure of one laptop only removes the resources hosted on that specific laptop; the other two can still share with each other. A wrong answer claiming P2P is more vulnerable reveals the misconception that decentralized systems are inherently less reliable, confusing *absence of central control* with *absence of redundancy*. The student must analyze the *role* of each node, not just count devices.

## DIAGNOSTIC_QUESTION_5
A company decides to replace all standalone PCs with a networked environment. The IT manager argues: "Networks eliminate all data loss risks because files are stored on multiple computers." Evaluate this claim. Is it fully true, partially true, or false? Provide two specific network-related risks that actually *increase* with networking.

## DIAGNOSTIC_ANSWER_5
The claim is **false**. Networking introduces new risks: (1) **Unauthorized access** — a breach on one node can expose shared resources across the network; (2) **Malware propagation** — a virus/worm on one machine can spread automatically to others via shared drives or network exploits. While centralized backups *can* reduce data loss, the network itself does not guarantee it. A wrong answer accepting the claim reveals the misconception that networking is purely beneficial without trade-offs, ignoring the expanded attack surface — a critical concept for the cyber safety nodes ahead (c11_cs_cbse_11_010 onwards).

## DIAGNOSTIC_QUESTION_6
Design a minimal home network for a family of four that allows: (a) printing from any device to a single printer, (b) accessing a shared photo library from any device, (c) parental control on internet access for children's devices. Draw a labeled diagram showing devices, connections, and the *one* additional hardware component needed beyond the router. Explain why that component is necessary.

## DIAGNOSTIC_ANSWER_6
Diagram: ISP modem → Wireless Router (with built-in switch/AP) → {Parent phones, Kids' tablets, Laptop, Network Printer, NAS (Network Attached Storage)}. The **NAS** is the additional component — it provides always-on, centralized storage for the photo library without requiring a specific computer to stay on. A poor answer that uses a laptop as the file server reveals the misconception that any computer can act as a server *reliably*; it ignores the server requirements of uptime, storage redundancy, and access control — concepts that lead into node c11_cs_cbse_11_008 (Client-Server Architecture).

## COMMON_MISCONCEPTION
Students often believe "network = internet" — they think a group of computers connected in a room without internet access is *not* a network. This stems from daily experience where "network" and "Wi-Fi/internet" are used interchangeably. For example, a student may say "The lab computers are networked" only if they can browse Google. The correct understanding: a **LAN** (Local Area Network) exists independently of internet connectivity; the internet is a *network of networks* (WAN). This misconception blocks understanding of intranets, offline file sharing, and the distinction between LAN/WAN in node c11_cs_cbse_11_002.

## ON_FAILURE
If the student equates network with internet: (1) Disconnect the classroom router's WAN cable; (2) Have students ping each other's IPs and transfer a file via shared folder; (3) Ask: "Did the network stop working?" (4) Define LAN as "a network confined to a limited geographical area, operating with or without internet." Reinforce with the textbook's distinction: internet is a *global system of interconnected networks* — not a single network.

## WORKED_EXAMPLE_1
PROBLEM: A small accounting firm has 5 standalone PCs. Each PC has a locally installed copy of accounting software (single-user license) and a USB printer. The accountants currently email spreadsheet files to each other for review, causing version conflicts. The firm wants to implement a network to: (1) share a single high-speed printer, (2) maintain one central database for the accounting software, (3) eliminate email-based file sharing. List the minimum hardware and software components required, and explain how each maps to the four network components (sender, receiver, medium, protocol).
STEPS:
- Step 1: Identify the resources to be shared — printer (hardware), database (software/data), files (data). This defines the *purpose* of the network.
- Step 2: Determine the sender/receiver roles — each PC acts as both sender (requesting print, querying database) and receiver (receiving print confirmation, query results). The database server (one PC designated) is primarily a receiver of queries and sender of results.
- Step 3: Select the transmission medium — since all PCs are in one office, use UTP Cat 6 Ethernet cables connected to an 8-port switch (wired LAN). This is the *medium*.
- Step 4: Define the protocol stack — TCP/IP for addressing and routing, SMB/CIFS for file/printer sharing, and the accounting software's proprietary protocol for database access. These are the *rules*.
- Step 5: Add required software — network OS (Windows/Linux) with file/print sharing enabled, accounting software configured for multi-user mode with a central database engine (e.g., SQL Server Express).
- Step 6: Verify the design against the three goals — (1) All PCs print to shared printer via switch → goal met. (2) Central DB on server PC accessed by all → goal met. (3) Files stored on shared folder, not emailed → goal met.
REASONING: This example demonstrates that a network is not just hardware; it is a *system* where each component (sender, receiver, medium, protocol) must be deliberately chosen to satisfy specific resource-sharing requirements. The accounting firm's pain points (version conflicts, multiple licenses, printer proliferation) map directly to the advantages of networking: centralized data, shared peripherals, and concurrent access.
ANSWER: Hardware: 5 PCs, 1 switch (8-port), 1 high-speed network printer, UTP Cat 6 cables. Software: Network OS with sharing services, multi-user accounting software with central DB, TCP/IP + SMB + app protocol stack.

## WORKED_EXAMPLE_2
PROBLEM: A student sets up a home "network" by connecting a laptop and a desktop with a single Ethernet cable (no router, no switch). They assign static IPs: 192.168.1.10/24 and 192.168.1.20/24. They can ping each other but cannot access the internet. The student concludes: "My network is broken because there's no internet." Analyze this situation using the definition of a computer network and the distinction between LAN and internet connectivity.
STEPS:
- Step 1: Recall the definition — a network is autonomous devices interconnected to share resources via protocols. Internet access is *not* in the definition.
- Step 2: Verify physical interconnectivity — the Ethernet cable provides the medium; link lights are on → physical layer OK.
- Step 3: Verify logical addressing — both devices have IPs in the same subnet (192.168.1.0/24) → they can address each other.
- Step 4: Verify protocol operation — ping uses ICMP over IP; successful ping confirms IP layer and ICMP protocol work.
- Step 5: Identify the missing resource — internet access requires a *gateway* (router) connected to an ISP. The two-PC network has no gateway.
- Step 6: Conclude — the LAN is fully functional for local resource sharing (files, printers, games). The absence of internet does not make it "broken"; it makes it an *isolated LAN*.
REASONING: This example targets the "network = internet" misconception directly. By walking through the layers (physical → data link → network → application), the student sees that the network *exists and works* at Layers 1-3. Internet is a service *on top* of the network, provided by a router/gateway — a concept that leads into node c11_cs_cbse_11_004 (router) and c11_cs_cbse_11_006 (IP addressing).
ANSWER: The network is NOT broken. It is a fully operational isolated LAN (Layer 1-3 functional). Internet access requires a router (gateway) and ISP connection — separate from the LAN itself.

## WORKED_EXAMPLE_3
PROBLEM: A school computer lab has 30 Raspberry Pi computers (Linux-based) connected via a 48-port switch. The teacher wants to: (a) push a Python script to all Pis simultaneously, (b) collect output logs from all Pis to a central folder, (c) ensure students cannot modify each other's files. Design the network architecture (logical, not physical) specifying: user authentication method, file sharing protocol, directory permissions, and automation tool. Justify each choice in terms of the four network components.
STEPS:
- Step 1: Define sender/receiver roles — Teacher's master Pi = sender (script push) and receiver (log collection); 30 student Pis = receivers (script) and senders (logs). Autonomy maintained: each Pi runs its own OS.
- Step 2: Choose authentication — LDAP or local user accounts with same username/password on all Pis (simpler for Class 11 scope). This enforces *identity* at the protocol layer.
- Step 3: Select file sharing protocol — SMB/CIFS (Samba on Linux) because it supports Windows/Linux interoperability, authentication, and permission mapping.
- Step 4: Design directory structure on master Pi — /scripts (read-only for students, write for teacher), /logs/studentXX (write for studentXX, read for teacher, no access for others). This uses protocol-level permissions (ACLs).
- Step 5: Automate push/pull — Use `ansible` or a simple `ssh` + `scp` loop from master Pi: `for i in {1..30}; do scp script.py pi@192.168.1.$i:/home/pi/; done`. SSH provides encrypted transport (protocol security).
- Step 6: Verify against requirements — (a) Script pushed to all via loop → done. (b) Logs collected via reverse scp or student-initiated push to /logs/studentXX → done. (c) Permissions prevent cross-student access → done.
REASONING: This advanced example integrates concepts from multiple forward nodes: IP addressing (c11_cs_cbse_11_006), client-server roles (c11_cs_cbse_11_008), protocols (c11_cs_cbse_11_009), and security (c11_cs_cbse_11_010 onwards). It shows how the four basic components scale: sender/receiver become *roles with permissions*, medium becomes *encrypted channel*, protocol becomes *authenticated, authorized service*. The student sees that "network" evolves from "connection" to "controlled resource-sharing ecosystem."
ANSWER: Architecture: Master Pi (server) + 30 Student Pis (clients) via switch. Auth: Local accounts synced via script. Protocol: SMB for shares, SSH for automation. Permissions: ACLs on /scripts (teacher RW, students R) and /logs/studentXX (owner RW, teacher R). Automation: Ansible/SSH loop from master.

## COMPETENCY_QUESTION_1
QUESTION: A rural health center has 3 computers: one at the reception, one in the doctor's cabin, and one in the pharmacy. They are not connected. The doctor writes prescriptions on paper; the pharmacist reads them manually; the receptionist types patient data into a local spreadsheet. Propose a network-based workflow that eliminates paper, reduces errors, and allows the doctor to view pharmacy stock levels from the cabin. Your answer must: (a) Identify the three resources being shared, (b) Specify the network type (LAN/MAN/WAN) and justify, (c) Name the protocol layer responsible for ensuring the prescription data reaches the correct application on the pharmacy computer, (d) Explain one security measure needed to protect patient data on this network.
COMPETENCY: Translating real-world situations to network design with justification
STEPS:
- Step 1: Identify shared resources — (1) Patient database (reception ↔ doctor), (2) Prescription data (doctor → pharmacy), (3) Pharmacy stock database (pharmacy → doctor).
- Step 2: Determine network type — All computers in one building → LAN (Local Area Network). Justification: Geographically confined, high-speed, privately owned medium.
- Step 3: Identify protocol layer for application delivery — Transport layer (TCP/UDP) uses port numbers to deliver data to the correct application (e.g., port 80/443 for web-based EMR, or custom port for desktop app).
- Step 4: Specify security measure — Encryption (TLS/SSL) for data in transit + role-based access control (RBAC) so only doctor sees prescriptions, only pharmacist sees stock, receptionist sees only demographics.
- Step 5: Verify workflow — Doctor enters prescription on cabin PC → sent via LAN to pharmacy PC (transport layer delivers to pharmacy app) → pharmacist dispenses → stock auto-updated → doctor views stock from cabin. Paper eliminated, errors reduced, real-time stock visibility achieved.
ANSWER: (a) Resources: Patient DB, Prescription data, Stock DB. (b) LAN — single building, private cabling. (c) Transport layer (ports). (d) TLS encryption + RBAC.

## COMPETENCY_QUESTION_2
QUESTION: Two neighboring schools, School A and School B, each have a functional LAN (as defined in this node). They want to share a high-resolution 3D printer located at School A and a specialized simulation software license server at School B. The schools are 2 km apart with a clear line of sight. The IT coordinator proposes: "Run a single fiber optic cable between the two switches." Critique this proposal. In your critique, address: (a) Whether this creates one network or two interconnected networks, (b) The protocol-level implication for IP addressing, (c) One advantage and one risk of this design compared to using a VPN over the public internet, (d) The device needed at each end to connect the fiber to the existing copper switches.
COMPETENCY: Comparing and justifying network design choices across multiple concepts
STEPS:
- Step 1: Analyze the proposal — A direct fiber link between two LANs creates a single extended Layer 2 network (one broadcast domain) if switches are bridged, or two Layer 3 networks connected by a router.
- Step 2: Determine network count — If bridged at Layer 2: *one* logical network (single subnet). If routed at Layer 3: *two* networks interconnected (internetwork). The proposal says "connect switches" → implies Layer 2 bridge → one network.
- Step 3: IP addressing implication — Single subnet means all devices (both schools) must share one IP range (e.g., 10.0.0.0/16). Requires coordinated DHCP or static planning. Broadcast traffic (ARP, DHCP) crosses the fiber, affecting both schools.
- Step 4: Compare with VPN over internet — Advantage of fiber: dedicated bandwidth, low latency, no ISP dependency. Risk: Physical cable vulnerable to damage, no encryption by default (anyone tapping fiber sees all traffic), single point of failure.
- Step 5: Identify connecting device — Media converter (fiber to copper) or switch with SFP+ transceiver slots at each end. A simple "cable" cannot plug into RJ45 ports.
- Step 6: Synthesize critique — The proposal creates a *single flat LAN* spanning 2 km. It works but lacks segmentation, encryption, and fault isolation. Better: Use two routers (one per school) with a routed link (Layer 3) or VPN — preserves separate subnets, enables firewalling, and is standard practice (leads to c11_cs_cbse_11_004 router, c11_cs_cbse_11_006 IP).
ANSWER: (a) Creates one flat LAN (Layer 2 bridge) unless routers are used. (b) Single IP subnet required; broadcast traffic crosses schools. (c) Advantage: Dedicated high-speed link. Risk: No encryption, physical vulnerability, no segmentation. (d) Media converters or SFP+-enabled switches.
