## DEFINITION
Control flow refers to the order in which individual statements, instructions, or function calls are executed or evaluated in a program. In Python, a statement block (or suite) is a group of statements that execute together as a single unit, defined by consistent indentation level rather than braces or keywords.

## WALKTHROUGH
Imagine you are giving directions to a friend to reach your house from school. You don't just say "go straight"; you say "go straight until the traffic light, **then** turn left, **then** go 200 metres." The "**then**" implies a sequence, but what if there are two possible routes depending on traffic? You'd say "**if** the main road is crowded, **take** the service lane; **otherwise** continue straight." This decision-making and repetition of steps (like "repeat the left-right pattern at every intersection") is exactly what control flow does in a program. In Python, we don't use braces `{}` to group the steps for "if crowded" — we use indentation. Let's learn how indentation creates blocks that the interpreter treats as a single unit, and how the three fundamental control flows — sequential, conditional, iterative — let us write programs that make decisions and repeat work.

## DIAGNOSTIC_QUESTION_1
What is the default control flow mechanism in a Python program when no conditional or looping statements are used?

## DIAGNOSTIC_ANSWER_1
The default control flow is **sequential execution**: statements are executed one after another in the exact order they appear in the source code, from top to bottom. A wrong answer (e.g., "random order" or "alphabetical order") reveals that the student has not internalized the fundamental concept that a program is a sequence of instructions executed linearly unless explicitly directed otherwise.

## DIAGNOSTIC_QUESTION_2
In the following code snippet, which statements belong to the *same block*? Explain how you determined this.
```python
x = 10
if x > 5:
    print("Greater")
    y = x * 2
print("Done")
z = y + 1
```

## DIAGNOSTIC_ANSWER_2
The statements `print("Greater")` and `y = x * 2` belong to the same block (the `if` block) because they share the same indentation level (one level deeper than the `if` line). The statements `x = 10`, `print("Done")`, and `z = y + 1` are at the top-level (zero indentation) and belong to the global/main block. A wrong answer that groups `print("Done")` with the `if` block reveals the misconception that a blank line or a comment ends a block, rather than dedentation.

## DIAGNOSTIC_QUESTION_3
Rewrite the following pseudocode into valid Python code, paying careful attention to block structure. The logic: "Set score to 75. If score is at least 50, print 'Pass' and set grade to 'C'. Otherwise, print 'Fail' and set grade to 'F'. Finally, print the grade."

## DIAGNOSTIC_ANSWER_3
```python
score = 75
if score >= 50:
    print("Pass")
    grade = 'C'
else:
    print("Fail")
    grade = 'F'
print(grade)
```
Steps: (1) Assign 75 to `score`. (2) Write `if` condition with colon. (3) Indent the two statements for the true branch. (4) Write `else:` at same indentation as `if`. (5) Indent the two statements for the false branch. (6) Dedent the final `print(grade)` so it runs regardless. A wrong answer with incorrect indentation (e.g., `grade = 'C'` not indented) shows the student does not understand that indentation *is* the block delimiter in Python.

## DIAGNOSTIC_QUESTION_4
Compare the block structure of Python with a language like C++ or Java that uses curly braces `{}`. What is the *semantic* consequence of Python's indentation-based blocks for nested structures?

## DIAGNOSTIC_ANSWER_4
In brace-delimited languages, whitespace is insignificant; blocks are explicitly marked by `{` and `}`. In Python, indentation is syntactically significant: it *defines* the block. For nested structures, this forces the programmer to maintain consistent visual alignment, making the code's logical structure directly visible. A wrong answer claiming "indentation is just for readability" reveals the dangerous misconception that Python ignores whitespace, leading to `IndentationError` or silent logical bugs when blocks are misaligned.

## DIAGNOSTIC_QUESTION_5
A student writes the following code to calculate the factorial of 5 using a loop. They claim the output will be 120. Evaluate their claim by tracing the control flow and block membership.
```python
n = 5
fact = 1
for i in range(1, n+1):
    fact = fact * i
print(fact)
```
Is the student correct? Justify by explaining which statement(s) are inside the loop block and which are outside.

## DIAGNOSTIC_ANSWER_5
The student is **correct**. The loop block consists only of `fact = fact * i` (indented under `for`). The `print(fact)` is *outside* the loop block (dedented), so it executes once after the loop completes. Trace: i=1→fact=1; i=2→fact=2; i=3→fact=6; i=4→fact=24; i=5→fact=120; loop ends; print(120). A wrong answer claiming the output is 1, 2, 6, 24, 120 (each on new line) reveals the misconception that `print(fact)` is inside the loop block — a classic indentation error.

## DIAGNOSTIC_QUESTION_6
Design a small Python program (5-7 lines) that uses **all three** fundamental control flows: sequential, conditional, and iterative. The program should simulate a simple "login attempt" system: allow up to 3 attempts; if correct password entered, print "Access granted" and stop; if all 3 attempts fail, print "Account locked". Use a `for` loop with `range`, an `if-else`, and a `break` statement. Explain the control flow path for both success on 2nd attempt and failure on all 3.

## DIAGNOSTIC_ANSWER_6
```python
correct_pass = "ip123"
for attempt in range(3):          # iterative flow
    pwd = input("Enter password: ") # sequential inside loop
    if pwd == correct_pass:       # conditional flow
        print("Access granted")
        break                     # exits loop early
    else:
        print("Wrong password")
else:                             # executes only if loop NOT broken
    print("Account locked")
```
**Success on 2nd attempt**: Iteration 1 → input → condition false → else block → print "Wrong" → loop continues. Iteration 2 → input → condition true → print "Access granted" → `break` → jump out of loop → `else` block of loop skipped → program ends. **Failure all 3**: Loop runs 3 times, `break` never hit → after 3rd iteration, loop `else` block executes → "Account locked". A poor answer that puts `print("Account locked")` outside the loop at same indentation as `for` (without `else`) shows misunderstanding of the `for-else` construct and block association.

## COMMON_MISCONCEPTION
**Misconception:** "Indentation in Python is just a style convention like in C++ or Java; the interpreter ignores extra spaces."  
**Why it happens:** Students coming from brace-delimited languages (or HTML/Markdown) assume whitespace is insignificant. They write `if x>0: print("pos")` on one line, or indent inconsistently (mixing tabs and spaces), and are surprised by `IndentationError` or silent logic errors where a statement they *thought* was inside a block actually runs unconditionally.  
**Concrete wrong example:**  
```python
if marks >= 33:
    print("Pass")
print("Congratulations")  # Student thinks this is inside the if-block
```  
The student expects "Congratulations" only for passing marks, but it prints for everyone because it's dedented.

1. **Visual Block Mapping:** Give the student a printed code snippet with 3-4 nested blocks. Ask them to draw vertical lines connecting each line to its block level using a ruler. Physically tracing the indentation columns makes the block structure tangible.

Have them run it, read the `IndentationError` traceback, fix one error at a time, and re-run. This builds the mental model that indentation *is* syntax.  
3. **Flowchart-to-Code Translation:** Draw a flowchart with decision diamond and loop. Have the student write the Python code *only* by following the flowchart paths, enforcing that every "yes/no" branch becomes an indented block. ## WORKED_EXAMPLE_1
PROBLEM: A school library charges a fine for overdue books: ₹2 per day for the first 7 days, ₹5 per day thereafter. Write a Python program that takes the number of overdue days as input, calculates the fine using sequential and conditional control flow, and prints the result. Trace the execution for 10 days overdue.

STEPS:
- Step 1: Identify the three control flow elements needed: sequential (input, calculation, output), conditional (if-else for two rate slabs), and no iteration needed here.
- Step 2: Define the block structure: the `if` block contains the fine calculation for ≤7 days; the `else` block contains the calculation for >7 days. Both blocks must be indented equally under their respective headers.
- Step 3: Write the code with correct indentation:
```python
days = int(input("Enter overdue days: "))
if days <= 7:
    fine = days * 2
else:
    fine = 7 * 2 + (days - 7) * 5
print("Fine = ₹", fine)
```
- Step 4: Trace for `days = 10`: Sequential: `days=10`. Conditional: `10 <= 7` is False → skip `if` block, enter `else` block. Inside `else` block: `fine = 14 + 3*5 = 29`. Sequential: `print` executes → Output: `Fine = ₹ 29`.
- Step 5: Verify: First 7 days = ₹14, next 3 days = ₹15, total ₹29. Correct.

REASONING: This example demonstrates how a real-world piecewise function maps directly to an `if-else` block structure. The indentation visually separates the two mutually exclusive calculation paths, and the final `print` is dedented to execute in both cases (sequential flow after the conditional).

ANSWER: Fine = ₹29

## WORKED_EXAMPLE_2
PROBLEM: Write a program to print the first 5 multiples of 7 (i.e., 7, 14, 21, 28, 35) using a `for` loop. Identify the loop block and trace the control flow for each iteration.

- Step 3: Write the code with the loop block indented:

for i in range(1, 6):

REASONING: The `for` loop header (`for i in range(1,6):`) defines the iteration control; the indented block (two statements) is the loop body. ## WORKED_EXAMPLE_3
PROBLEM: Combine conditional and iterative flow: Write a program that reads 5 integers from the user (one per line) and prints the count of positive numbers entered. Use a `for` loop for input repetition and an `if` statement inside the loop block for the condition. Trace for inputs: 10, -5, 0, 8, -3.

STEPS:
- Step 1: Identify the need for a loop to repeat input 5 times → `for _ in range(5):`. A counter variable `count = 0` must be initialized *before* the loop (sequential).
- Step 2: Inside the loop block (indented), read input, convert to int, and use an `if` block to check positivity. The `if` block increments the counter. This creates a nested block structure: `if` block inside `for` block.
- Step 3: Write the code with two indentation levels:
```python
count = 0
for _ in range(5):
    num = int(input("Enter number: "))
    if num > 0:
        count = count + 1
print("Positive count:", count)
```
- Step 4: Trace for given inputs:
  - Initial: `count=0`.
  - Iter 1: `num=10` → `if 10>0` True → `if` block: `count=1`.
  - Iter 2: `num=-5` → `if -5>0` False → skip `if` block → `count=1`.
  - Iter 3: `num=0` → `if 0>0` False → skip `if` block → `count=1`.
  - Iter 4: `num=8` → `if 8>0` True → `if` block: `count=2`.
  - Iter 5: `num=-3` → `if -3>0` False → skip `if` block → `count=2`.
  - Loop ends. Sequential: `print("Positive count:", 2)`.
- Step 5: Verify: Positive numbers are 10 and 8 → count=2. Correct.
- Step 6: Note the block hierarchy: `for` block (level 1) contains `input`, `if` header, and `if` block (level 2). The `print` is at level 0 (global).

REASONING: This example integrates all three control flows: sequential (initialization, final print), iterative (loop for 5 inputs), and conditional (if inside loop). The nested indentation (two levels) is the syntactic manifestation of nested control flow. Tracing shows how the inner `if` block executes conditionally *within* each iteration of the outer loop block.

ANSWER: Positive count: 2

## COMPETENCY_QUESTION_1
QUESTION: A student writes the following code to compute the sum of even numbers from 1 to 10. They claim the output is 30. Analyze the code, identify the block structure error, explain why the output is wrong, and provide the corrected code.
```python
total = 0
for i in range(1, 11):
    if i % 2 == 0:
        total = total + i
    print(total)
```

COMPETENCY: Error identification and correction in control flow block structure.

STEPS:
- Step 1: Identify the intended logic: accumulate sum of even numbers (2+4+6+8+10=30) and print the final sum once.
- Step 2: Analyze block structure: The `for` block includes both the `if` statement and the `print(total)` because both are indented equally under `for`. The `if` block includes only `total = total + i`.
- Step 3: Trace execution: For each `i`, if even, `total` updates; then `print(total)` executes *every iteration* (not just for evens). Output will be: 0, 2, 2, 6, 6, 12, 12, 20, 20, 30 (ten lines).
- Step 4: The error: `print(total)` is inside the loop block but should be outside (after the loop) to print only the final sum.
- Step 5: Correct by dedenting `print(total)` to align with `for`.

ANSWER: The student's code prints the running total after every iteration because `print(total)` is inside the `for` block (same indentation as `if`). The correct output should be a single line `30`. Fixed code:
```python
total = 0
for i in range(1, 11):
    if i % 2 == 0:
        total = total + i
print(total)  # dedented: outside the for loop
```

## COMPETENCY_QUESTION_2
QUESTION: Design a Python program that simulates an ATM PIN verification system with the following rules:
- The correct PIN is 4821.
- The user has a maximum of 3 attempts.
- After each wrong attempt, display "Incorrect PIN. Attempts left: X".
- If the correct PIN is entered, display "Access Granted" and terminate the verification process immediately.
- If all 3 attempts are exhausted, display "Card Blocked. Contact Bank."
Use a `for` loop with `range`, an `if-else` inside the loop, and the `for-else` construct. Explain the control flow for: (a) correct PIN on 2nd attempt, (b) wrong PIN on all 3 attempts.

COMPETENCY: Translating real-world decision/iteration logic into structured Python control flow with nested blocks.

STEPS:
- Step 1: Identify control flow elements: iterative (3 attempts → `for`), conditional (check PIN → `if-else`), early exit on success (`break`), final action on total failure (`for-else`).
- Step 2: Structure blocks: `for` block (level 1) contains input, `if-else` (level 2). `if` block (level 3) contains success message and `break`. `else` block (level 3) contains failure message. `for-else` block (level 1, aligned with `for`) contains card blocked message.
- Step 3: Write code:
```python
correct_pin = 4821
for attempt in range(3):
    pin = int(input("Enter 4-digit PIN: "))
    if pin == correct_pin:
        print("Access Granted")
        break
    else:
        left = 2 - attempt
        print(f"Incorrect PIN. Attempts left: {left}")
else:
    print("Card Blocked. Contact Bank.")
```
- Step 4: Explain control flow (a): Attempt 0 → wrong → else block prints "Attempts left: 2" → loop continues. Attempt 1 → correct → if block prints "Access Granted" → `break` jumps out of loop → `for-else` block skipped → done.
- Step 5: Explain control flow (b): Attempts 0,1,2 all wrong → else block executes each time printing attempts left → loop completes normally (no `break`) → `for-else` block executes → "Card Blocked".

ANSWER: (a) Access Granted (after 2nd input). (b) Card Blocked. Contact Bank. (after 3 wrong inputs). The `for-else` construct elegantly handles the "exhausted attempts" case without a separate flag variable.
