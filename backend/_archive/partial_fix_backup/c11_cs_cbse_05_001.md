## DEFINITION
Control flow refers to the order in which individual statements, instructions, or function calls are executed or evaluated in a program. In Python, control flow structures (conditional statements like `if`, `if-else`, `if-elif-else` and iterative statements like `while`, `for`) allow the program to make decisions and repeat actions, deviating from the default sequential execution (top-to-bottom, one statement after another).

## WALKTHROUGH
Imagine you are writing a program to calculate the fare for an auto-rickshaw ride in Delhi. The fare is ₹25 for the first 1.5 km, then ₹9.50 per additional km. If you write code line-by-line, you can only handle one fixed distance. But real users travel different distances — sometimes 2 km, sometimes 15 km. How do you make the program *decide* which formula to apply? And what if you want to print the fare for *every* distance from 1 km to 20 km without writing 20 separate print statements? This is where control flow begins: we need **selection** (choose path based on condition) and **iteration** (repeat a block). In Python, indentation (whitespace at the start of a line) defines which statements belong to a block — unlike C++ or Java which use braces `{}`. The interpreter executes the block only if the condition is true (for `if`) or repeatedly while true (for `while`). The key insight: control flow lets you write *one* program that handles *infinite* scenarios.

## DIAGNOSTIC_QUESTION_3
Write a Python code snippet using a `while` loop that prints the numbers 10, 8, 6, 4, 2 (even numbers from 10 down to 2). Initialize a variable `num = 10`.

## DIAGNOSTIC_ANSWER_3
```python
num = 10
while num >= 2:
    print(num)
    num = num - 2
```
**Steps**: (1) Initialize `num = 10`; (2) Condition `num >= 2` is true → enter loop; (3) Print `num` (10); (4) Update `num = 8`; (5) Repeat until `num` becomes 0 (condition fails). ## DIAGNOSTIC_QUESTION_4
Compare the roles of **indentation** in Python vs. **curly braces `{}`** in C++/Java for defining blocks in control flow. Why does Python's design make code more readable but also more fragile?

## DIAGNOSTIC_ANSWER_4
In Python, indentation **is** the block delimiter — the interpreter uses whitespace level to decide which statements belong to the `if` or `while`. In C++/Java, braces `{}` define blocks; indentation is optional (for humans only). Python's design forces consistent visual structure, making code readable by default. But it is fragile: a single misplaced space (e.g., mixing tabs and spaces) changes the block structure silently, causing logic errors without syntax errors. A wrong answer (e.g., "Python uses braces too" or "indentation doesn't matter") shows the student hasn't internalized that indentation is syntactic, not cosmetic — a major source of bugs in Class 11 labs.

## DIAGNOSTIC_QUESTION_5
A program must calculate the sum of all even numbers between 1 and N (inclusive). Two approaches are proposed: (A) `for i in range(2, N+1, 2): total += i` and (B) `for i in range(1, N+1): if i % 2 == 0: total += i`. Evaluate which is better and justify based on **efficiency** and **clarity**.

## DIAGNOSTIC_ANSWER_5
Approach (A) is **better**: it iterates only N/2 times (directly over even numbers), while (B) iterates N times and checks a condition each time. Both are O(N) asymptotically, but (A) has half the loop overhead and no branch prediction misses. Clarity: (A) expresses intent directly ("step by 2"), while (B) requires reading the modulo check. A wrong answer (e.g., "both are same" or "B is better because it's more general") reveals the student doesn't think about loop optimization or that `range(start, stop, step)` is designed for this exact pattern — a key skill for board exam "efficiency" questions.

## COMMON_MISCONCEPTION
**Misconception**: "A `while` loop checks the condition continuously in real-time, like a sensor. If the condition becomes false *during* the loop body, it stops immediately."  
**Why it's wrong**: In Python, the condition is checked **only at the start of each iteration** — before the body runs. If the condition becomes false *inside* the body (e.g., `num` becomes 0), the loop **still finishes the current iteration** before checking again.  
**Concrete example**:  
```python
num = 3
while num > 0:
    print(num)
    num = num - 2  # num becomes 1, then -1
```
Output: `3`, `1`, `-1` — **three** prints, not two. The loop doesn't stop when `num` becomes 0 (it skips 0) or negative; it only stops at the *next* condition check. Students trace this as stopping early because they think the condition is monitored continuously.

## ON_FAILURE
**Step-by-step remediation**:  
1. **Act out the interpreter**: Use a physical trace table on paper. Write columns: `Iteration`, `Condition Check (T/F)`, `num before body`, `Print`, `num after update`.  
2. **Highlight the "check points"**: Mark explicitly: "Condition checked HERE → if True, run body → after body, go back to HERE."  
3. **Contrast with `if`**: Show that `if` checks once; `while` checks repeatedly **only at the top**.  
4. **Give a minimal counter-example**: `num = 1; while num > 0: print(num); num -= 1` → prints `1` only once. Then `num = 2; while num > 0: print(num); num -= 2` → prints `2`, then `num=0`, loop ends. Then `num = 3; while num > 0: print(num); num -= 2` → prints `3`, `1`, then `num=-1`, loop ends. Ask: "Why did it print 1 when num became -1 after?" Guide them to see the check happens *before* the body, not during.

## WORKED_EXAMPLE_1
PROBLEM: A school canteen sells samosas at ₹15 each. Write a program that asks the user for the number of samosas they want, then calculates the total cost. However, if the order is more than 20 samosas, a 10% bulk discount applies. Print the final amount payable. Trace the execution for input 25.

STEPS:
- Step 1: Identify inputs and outputs. Input: integer `qty` (number of samosas). Output: float `amount` (total payable). Constants: `price = 15`, `discount_threshold = 20`, `discount_rate = 0.10`.
- Step 2: Determine control flow needed. Sequential calculation of base cost, then a **conditional** (if qty > 20) to decide whether to apply discount. No repetition needed.
- Step 3: Write the algorithm in pseudocode: 
  `qty = input(); base = qty * 15; if qty > 20: amount = base * 0.9 else: amount = base; print(amount)`
- Step 4: Trace for `qty = 25`: 
  `base = 25 * 15 = 375`; 
  condition `25 > 20` is True → `amount = 375 * 0.9 = 337.5`; 
  print `337.5`.
- Step 5: Verify edge cases: `qty = 20` → no discount (300); `qty = 21` → discount (283.5). Logic holds.

REASONING: This example shows **selection** (if-else) altering the computation path based on data. The condition uses a relational operator (`>`), and the discount is a multiplicative update — both require understanding operator precedence (multiplication before subtraction) and float arithmetic. The trace table reinforces that only ONE branch executes.

ANSWER: For 25 samosas, amount payable = ₹337.5

## WORKED_EXAMPLE_2
PROBLEM: Write a program to find the sum of all multiples of 7 between 1 and 100 (inclusive). Use a `while` loop. Trace the first 3 and last 2 iterations.

STEPS:
- Step 1: Identify the sequence: 7, 14, 21, ..., 98. This is an AP with a=7, d=7, last term ≤100.
- Step 2: Design loop structure. Need: initialization (`num = 7`), condition (`num <= 100`), update (`num += 7`), accumulator (`total = 0`).
- Step 3: Write code:
  ```python
  total = 0
  num = 7
  while num <= 100:
      total += num
      num += 7
  print(total)
  ```
- Step 4: Trace iterations:
  Iteration 1: num=7 (≤100) → total=7 → num=14
  Iteration 2: num=14 → total=21 → num=21
  Iteration 3: num=21 → total=42 → num=28
  ...
  Last two: 
  num=91 → total=... → num=98
  num=98 → total=... → num=105

REASONING: This demonstrates **condition-controlled iteration** (`while`) where the loop variable follows an arithmetic progression. The trace shows the three parts of a loop (init, condition, update) working together. The AP sum verification connects to Class 10 math (c10_math_cbse_05_007) — reinforcing cross-subject links.

## WORKED_EXAMPLE_3
PROBLEM: A student saves money daily: ₹10 on day 1, ₹12 on day 2, ₹14 on day 3, increasing by ₹2 each day. Write a program to find after how many days the total savings reach at least ₹500. Use a `for` loop with `range`. Trace key steps.

STEPS:
- Step 1: Model the problem. Daily saving is an AP: a=10, d=2. Total savings after n days = sum of first n terms of AP. Need smallest n such that sum ≥ 500.
- Step 2: Choose loop type. Since we don't know n in advance but have a clear pattern, use `for` loop with a running sum and break when target reached. Or use `while` with day counter. Here `for` with `range` and accumulator + `break`.
- Step 3: Write code:
  ```python
  total = 0
  for day in range(1, 100):  # safe upper bound
      daily = 10 + (day - 1) * 2
      total += daily
      if total >= 500:
          print("Days:", day, "Total:", total)
          break
  ```
- Step 4: Trace:
  day=1: daily=10, total=10
  day=2: daily=12, total=22
  day=3: daily=14, total=36
  ...
  Use AP sum formula to find exact n: S_n = n/2 * (2*10 + (n-1)*2) = n/2 * (20 + 2n - 2) = n*(n+9)
  Solve n(n+9) ≥ 500 → n² + 9n - 500 ≥ 0 → n ≈ 18.5 → n=19.
  Check: n=18: 18*27=486 <500; n=19: 19*28=532 ≥500.
- Step 5: Loop runs 19 times, prints "Days: 19 Total: 532". The `break` exits immediately — no further iterations.

REASONING: This combines **iteration** (`for` loop), **selection** (`if` inside loop), and **flow modification** (`break`). The AP sum formula (Class 10 math) verifies the loop logic and helps set a safe `range` upper bound. The `break` shows how to exit early — a key control flow concept. This mirrors board exam problems where loops search for a threshold.

ANSWER: After 19 days, total savings = ₹532

## COMPETENCY_QUESTION_2
QUESTION: A program calculates the factorial of a number `n` (n! = 1×2×...×n) using a loop. Two versions are given:

**Version A:**
```python
fact = 1
for i in range(1, n+1):
    fact *= i
```

**Version B:**
```python
fact = 1
i = 1
while i <= n:
    fact *= i
    i += 1
```

(a) For n=5, trace both versions and confirm they produce the same result.  
(b) What happens if n=0 in each version? (Recall 0! = 1)  
(c) Which version is safer if the programmer forgets to initialize `i` in Version B? Justify.  
(d) Suggest a third version using `range` that avoids the n=0 issue explicitly and is considered more "Pythonic".

COMPETENCY: Error identification and correction / Comparing and justifying
STEPS:
- Step 1: Trace Version A for n=5: i=1,2,3,4,5 → fact=1,2,6,24,120. Version B: same.
- Step 2: Test n=0: Version A: `range(1,1)` is empty → loop runs 0 times → fact=1 (correct). Version B: condition `1 <= 0` false → loop skipped → fact=1 (correct).
- Step 3: If `i` not initialized in Version B: `NameError: name 'i' is not defined` at condition check — runtime crash. Version A has no such variable.
- Step 4: Pythonic version: `import math; fact = math.factorial(n)` or using `functools.reduce` — but simplest safe loop: `fact = 1; for i in range(2, n+1): fact *= i` (starts at 2, skips 1, works for n=0,1).
ANSWER: 
(a) Both give 120 for n=5. 
(b) Both correctly give 1 for n=0. 
(c) Version A is safer — no loop variable to initialize; `range` handles it. Version B crashes with `NameError` if `i` missing. 
(d) `fact = 1; for i in range(2, n+1): fact *= i` — avoids multiplying by 1, handles n=0/1 correctly (empty range), and is idiomatic.
DIFFICULTY: hard
