## DEFINITION
File handling is the process of storing data permanently on secondary storage devices (like hard disks) using files, enabling data persistence beyond program execution. A file is a named collection of related data stored on a non-volatile medium, and file types are primarily categorized as text files (human-readable, encoded in character sets like ASCII/UTF-8) and binary files (machine-readable, storing raw bytes for images, audio, executables, etc.).

## DIAGNOSTIC_QUESTION_1
What is the primary purpose of file handling in programming, and name the two main categories of files based on their internal representation.

## DIAGNOSTIC_ANSWER_1
The primary purpose of file handling is to achieve data persistence — storing data on secondary storage so it survives program termination. The two main categories are text files (store data as human-readable characters encoded in schemes like ASCII/UTF-8) and binary files (store data as raw bytes, not directly readable by humans). A wrong answer (e.g., "file handling is for printing output" or "categories are .txt and .pdf") reveals the student confuses file handling with output statements or mixes file extensions with internal representation.

## DIAGNOSTIC_QUESTION_2
Explain why a JPEG image file opened in a text editor shows unreadable characters, while a CSV file opens correctly. Relate this to the internal storage format.

## DIAGNOSTIC_ANSWER_2
A JPEG is a binary file: it stores pixel data as raw bytes (0-255 values) without character encoding. A text editor interprets every byte as a character code, producing gibberish. A CSV is a text file: it stores data as encoded characters (e.g., UTF-8) with delimiters, so a text editor can map each byte to a visible character. If a student says "JPEG is corrupted" or "CSV is not a real file", they misunderstand that binary files are not meant to be read as text and that file type is about encoding, not correctness.

## DIAGNOSTIC_QUESTION_3
A programmer wants to store a Python dictionary containing student records (name, roll number, list of marks) in a file so that it can be easily read by a human later and also parsed by another Python program. Which file type should they choose, and what is a common format for this purpose?

## DIAGNOSTIC_ANSWER_3
Choose a text file. A common format is JSON (JavaScript Object Notation) or CSV. Text files allow human readability and easy parsing. Steps: 1) Identify requirement: human-readable + machine-parsable. 2) Text files support both; binary files are not human-readable. 3) JSON represents nested structures (lists, dictionaries) naturally; CSV is flat but simpler. 4) Decision: text file with JSON. A wrong answer (e.g., "binary file with pickle") shows the student prioritizes Python-specific serialization over interoperability and readability.

## DIAGNOSTIC_QUESTION_4
Compare and contrast text files and binary files in terms of (a) storage efficiency, (b) portability across systems, and (c) ease of debugging. Provide one scenario where each is preferred.

## DIAGNOSTIC_ANSWER_4
(a) Storage efficiency: Binary files are more efficient — they store exact bytes (e.g., a 4-byte integer uses 4 bytes). Text files store numbers as character sequences (e.g., "12345" uses 5 bytes plus delimiter). (b) Portability: Text files are more portable — character encodings (UTF-8) are standardized across platforms. Binary files may suffer from endianness issues (byte order) and require same data structure definitions. (c) Debugging: Text files are easier to debug — open in any editor. Binary files need hex editors or custom parsers. Scenario for text: configuration files (.ini, .json). Scenario for binary: multimedia (images, audio) or large numerical datasets (scientific computing). A wrong answer that claims "text files are always smaller" or "binary files are always portable" reveals confusion about encoding overhead and platform dependence.

## DIAGNOSTIC_QUESTION_5
Critique the following statement: "Since binary files are more storage-efficient, we should always use binary files for all data storage in Python programs." Justify your evaluation with two counterexamples.

## DIAGNOSTIC_ANSWER_5
The statement is flawed. Counterexample 1: Configuration files (e.g., settings.ini) need human editing — binary files require a dedicated tool, making maintenance harder. Counterexample 2: Data exchange between different languages/systems (e.g., a CSV exported from Python to be read by R or Excel) — text formats like CSV/JSON are universal; binary formats like Python's pickle are language-specific. Binary files are optimal for large homogeneous numeric data (e.g., NumPy arrays) or multimedia. A student who agrees with the statement overlooks the trade-offs of readability, interoperability, and development overhead.

## DIAGNOSTIC_QUESTION_6
Design a small project scenario (2-3 sentences) where you must decide between using a text file and a binary file. Specify the data type, intended users, and operations, then state your choice with reasoning.

## DIAGNOSTIC_ANSWER_6
Example: "A school library system stores book records (title, author, ISBN, cover image). The librarian needs to edit book details manually sometimes, but cover images must be stored efficiently." Choice: Use a text file (JSON) for book metadata (human-editable, structured) and separate binary files (JPEG) for cover images. ## COMMON_MISCONCEPTION
Students often believe that file extension (e.g., .txt, .dat, .bin) determines whether a file is text or binary. They think renaming a .jpg to .txt converts it to a text file. In reality, the file's internal byte structure defines its type; the extension is only a hint for the OS and users. For example, a file named data.txt containing raw bytes from an image is still a binary file, and opening it in Notepad shows gibberish. This misconception arises because Windows hides extensions by default and students associate extensions with file "kind" rather than content encoding.

## ON_FAILURE
To correct this, perform a live demo: 1) Create a text file with `open('demo.txt', 'w')` and write "Hello". Open in Notepad — readable. 2) Create a binary file with `open('demo.bin', 'wb')` and write `b'\x48\x65\x6c\x6c\x6f'` (bytes for "Hello"). Open in Notepad — shows "Hello" because bytes happen to be ASCII codes. 3) Write non-ASCII bytes `b'\x80\x81\x82'` to another binary file, open in Notepad — shows garbage. 4) Rename the binary file to .txt and open — still garbage. Emphasize: "The content (bytes) decides the type, not the name." Then ask the student to predict what happens if they write the integer 1000 as text vs. binary (4 bytes vs. '1000').

## WORKED_EXAMPLE_1
PROBLEM: A teacher wants to store the names and marks of 30 students in a file so that she can open it in Notepad to check quickly, and also write a Python program to calculate the average. Should she use a text file or a binary file? Justify with two reasons.

STEPS:
- Step 1: Identify the requirements: (a) human-readable in Notepad, (b) parsable by Python program.
- Step 2: Recall that text files store data as encoded characters (e.g., UTF-8) which Notepad can display.
- Step 3: Recall that binary files store raw bytes; Notepad will show unreadable characters.
- Step 4: Evaluate: Text file meets both requirements (human-readable + Python can read strings and split/parse). Binary file fails (a).
- Step 5: Conclude: Choose text file. Reason 1: Notepad compatibility. Reason 2: Python's built-in string methods (split, strip) simplify parsing.

REASONING: The problem tests the ability to match file type to user needs. Text files are designed for human readability and interoperability; binary files are for efficiency and complex structures. The two reasons directly address the dual requirement.

ANSWER: Text file. Reason 1: Can be opened and read in Notepad (human-readable). Reason 2: Python can easily read lines, split by delimiter, and convert to numbers for average calculation.

## WORKED_EXAMPLE_2
PROBLEM: A game developer needs to save the game state which includes: player position (x, y as floats), inventory (list of item IDs as integers), and a screenshot of the current frame (image data). The save file must be compact and fast to load. Which file type(s) should be used for each component? Explain.

STEPS:
- Step 1: Break down data components: (a) player position (two floats), (b) inventory (list of ints), (c) screenshot (image pixels).
- Step 2: Analyze each: (a) and (b) are structured numerical data; (c) is raw pixel bytes.
- Step 3: Consider text file for (a) and (b): human-readable but larger (float "12.345" takes 6 bytes vs 4 bytes binary) and slower to parse (string to float conversion).
- Step 4: Consider binary file for (a) and (b): compact (fixed 4 or 8 bytes per number), fast load (direct memory mapping), but not human-editable.
- Step 5: For (c) screenshot: must be binary (image formats like PNG/JPG are binary); text would be enormously inefficient (base64 encoding increases size by 33%).
- Step 6: Decision: Use a single binary file (custom format or protocol like Protocol Buffers) for all three, or separate binary files. Text file is unsuitable for screenshot and suboptimal for numerical game state.

REASONING: Game state requires performance and compactness; binary files provide both. The screenshot is inherently binary. Text files would introduce parsing overhead and size bloat.

ANSWER: Binary file for all components. Player position and inventory: binary for compactness (4-8 bytes per number) and fast loading. Screenshot: binary (PNG/JPG) because image data is raw bytes; text encoding would triple the size.

## WORKED_EXAMPLE_3
PROBLEM: A scientist collects temperature readings from a sensor every second for 24 hours (86,400 readings). Each reading is a float (4 bytes). She wants to store them in a file for later analysis in Python and also share with a colleague who uses MATLAB. Compare the storage size and cross-language compatibility of storing as (a) a text file (CSV, one reading per line) and (b) a binary file (raw 4-byte floats). Assume average 8 characters per float in text (including newline).

STEPS:
- Step 1: Calculate text file size: 86,400 readings × 8 bytes/reading = 691,200 bytes ≈ 675 KB.
- Step 2: Calculate binary file size: 86,400 readings × 4 bytes/reading = 345,600 bytes ≈ 337.5 KB.
- Step 3: Compare: Binary file is exactly half the size (4 bytes vs 8 chars).
- Step 4: Analyze cross-language compatibility: CSV text file can be read by Python, MATLAB, Excel, R, etc. without extra libraries. Binary file requires both parties to agree on byte order (endianness), float format (IEEE 754), and use appropriate readers (numpy.fromfile in Python, fread in MATLAB).
- Step 5: Evaluate trade-off: If storage/bandwidth is critical (e.g., satellite downlink), binary wins. If ease of sharing and quick inspection is priority, text wins.
- Step 6: Recommendation: For long-term archival and sharing, use text (CSV) with metadata header. For high-frequency logging on device, use binary; convert to CSV when transmitting.

REASONING: This problem combines quantitative comparison (size calculation) with qualitative analysis (interoperability). It shows that file type choice depends on multiple constraints.

ANSWER: (a) Text file size ≈ 675 KB; (b) Binary file size ≈ 337.5 KB. Binary is 50% smaller. Text (CSV) is universally readable; binary requires agreement on endianness and format. For sharing with MATLAB colleague, CSV is safer unless a standard binary format (e.g., HDF5) is used.

## COMPETENCY_QUESTION_2
QUESTION: A student writes a Python program to store a dictionary `{'name': 'Amit', 'marks': [85, 90, 78]}` in a file using `pickle.dump()`. Another student says "Pickle files are binary, so they are not portable across Python versions or other languages." Evaluate this statement. Is it entirely true? Provide a scenario where pickle is acceptable and one where it is not. Suggest a better alternative for cross-language portability.

COMPETENCY: Error identification and correction with technical justification

STEPS:
- Step 1: Understand pickle: Python-specific serialization to binary format.
- Step 2: Evaluate "not portable across Python versions": Partially true — pickle protocol versions change; older Python may not read newer pickles. But same major version usually works.
- Step 3: Evaluate "not portable across other languages": True — pickle is Python-only; Java, C++, etc. cannot read it without a pickle parser (rare).
- Step 4: Scenario where pickle is acceptable: Internal caching in a Python-only application (e.g., saving a trained ML model for the same Python environment).
- Step 5: Scenario where pickle is not acceptable: Sharing data with a web frontend (JavaScript) or a data pipeline in Java/Scala.
- Step 6: Better alternative: JSON (text) or MessagePack (binary) — both language-agnostic, schema-less, widely supported.

ANSWER: The statement is mostly correct but nuanced: pickle is Python-specific and version-sensitive. Acceptable: Python-only cache. Not acceptable: Multi-language systems. Better alternative: JSON for readability, MessagePack for binary efficiency.
