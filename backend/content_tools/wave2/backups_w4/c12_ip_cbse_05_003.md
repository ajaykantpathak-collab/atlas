## ELI5
A web address is a postal address in disguise. A URL is the standardized string that uniquely identifies a resource on the Web — protocol as the delivery service, domain as the city and street, path as the building and room, query as special instructions. One missing 's' in https changes the behaviour; one added ?download=true changes the request. protocol://subdomain.domain.tld/path?query#fragment is the map of every address bar.

## DEFINITION
A Uniform Resource Locator (URL) is a standardized address string that uniquely identifies a resource on the World Wide Web by specifying its access protocol, the host domain (including optional subdomain), the hierarchical path to the resource on the server, and optional query parameters that pass additional data to the resource. Each component is separated by reserved delimiters: `protocol://subdomain.domain.tld/path?query#fragment`.

## SCOPE_BOUNDARY
This node covers the syntactic structure of URLs as defined in RFC 3986 and taught in NCERT Class 12: protocol (http, https, ftp), domain name hierarchy (subdomain, second-level domain, top-level domain), path segments separated by '/', query string introduced by '?' with key=value pairs separated by '&', and optional fragment introduced by '#'. It does NOT cover DNS resolution mechanics, HTTP request/response details, URL encoding/decoding rules, or REST API design — those are addressed in subsequent nodes (c12_ip_cbse_05_004, c12_ip_cbse_05_005).

## WALKTHROUGH
Imagine you are browsing for NCERT textbooks and type `https://ncert.nic.in/textbook/pdf/kech1ps.pdf` in the address bar — the page loads instantly. But what if you accidentally type `http://ncert.nic.in/textbook/pdf/kech1ps.pdf` (missing 's') or `https://ncert.nic.in/textbook/pdf/kech1ps.pdf?download=true` (added a parameter)? The browser still reaches the server, but the behavior changes. To understand why, we need to dissect the address bar text like a postal address: the protocol is the "delivery service" (HTTP vs HTTPS), the domain is the "city and street" (ncert.nic.in), the path is the "building and room number" (/textbook/pdf/kech1ps.pdf), and the query is the "special instructions" (?download=true). We will learn to parse each part, recognize valid and malformed URLs, and build URLs programmatically — a skill tested in both board practicals and CUET/IPMAT case-study questions.

Takeaway: mastery means the five components separated and each given its job. Exam moves: decomposition questions split a URL into protocol, subdomain, domain, path, and query; function questions explain what each part does; construction questions build a valid address from given parts; malformed questions spot the broken delimiter. Method: take the NCERT textbook link — name protocol, domain, path, then add the download parameter and predict the change. Drill: five components, one build, one break. Students miss it because the address bar reads as one blob — the delimiters are the seams the examiner grades along.

## DIAGNOSTIC_QUESTION_1
Write down the five components of the URL `https://www.example.com:8080/search?q=informatics+practices&page=2#results` and state the function of each component in one sentence.

## DIAGNOSTIC_ANSWER_1
Correct answer: (1) Protocol: `https` — specifies the secure communication scheme. (2) Host: `www.example.com:8080` — identifies the server (domain `example.com`, subdomain `www`, port `8080`). (3) Path: `/search` — locates the specific resource/script on the server. (4) Query: `q=informatics+practices&page=2` — passes key-value parameters to the resource. (5) Fragment: `results` — identifies a secondary resource within the page (client-side only). A wrong answer revealing confusion between host and path (e.g., calling `/search` part of the domain) shows the student has not internalized the hierarchical delimiter structure (`://` separates protocol from host, `/` starts the path, `?` starts query).

## DIAGNOSTIC_QUESTION_2
A student claims: "The domain name in `https://mail.google.com/mail/u/0/#inbox` is `google.com` and the subdomain is `mail`." Is this correct? Explain why or why not, and identify the path, query, and fragment in this URL.

## DIAGNOSTIC_ANSWER_2
Correct answer: Yes, the claim is correct. The full host is `mail.google.com` where `mail` is the subdomain, `google` is the second-level domain, and `com` is the top-level domain. Path: `/mail/u/0/` (hierarchical segments). Query: absent (no `?`). Fragment: `inbox` (after `#`). A wrong answer that includes `#inbox` in the path or misses the fragment entirely reveals the student does not understand that fragments are never sent to the server and are purely client-side navigation aids — a common board exam trap in "identify the component" questions.

## DIAGNOSTIC_QUESTION_3
Parse the following URL into a structured table with columns: Component, Value, Purpose. URL: `ftp://ftp.is.co.za/rfc/rfc1808.txt`
Then, construct a new URL that uses HTTPS protocol, the same domain, a path `/download/rfc1808.txt`, and a query parameter `format=raw`.

## DIAGNOSTIC_ANSWER_3
Correct parse table:
| Component | Value | Purpose |
|-----------|-------|---------|
| Protocol | ftp | File Transfer Protocol for file download |
| Host | ftp.is.co.za | Server address (subdomain ftp, domain is.co.za) |
| Path | /rfc/rfc1808.txt | Hierarchical location of the file |

## DIAGNOSTIC_QUESTION_4
Compare the two URLs and explain which one is more likely to be a phishing attempt, justifying your answer using URL structure analysis:
URL A: `https://www.icici.bank.login.secure-server.xyz/verify?account=12345`
URL B: `https://www.icicibank.com/login?return_url=/dashboard`

## DIAGNOSTIC_ANSWER_4
Correct answer: URL A is the phishing attempt. Analysis: (1) Domain in URL A is `secure-server.xyz` (top-level domain `.xyz`, second-level `secure-server`), with subdomains `www.icici.bank.login` — attackers use long subdomain chains to visually mimic legitimate brands. (2) URL B uses the legitimate domain `icicibank.com` (registered to ICICI Bank). (3) URL A's path `/verify` with query `account=12345` suggests credential harvesting. (4) URL B's query `return_url=/dashboard` is a standard post-login redirect. A student who focuses only on the presence of "icici" in the subdomain and misses the actual domain (the part immediately left of the TLD) falls for the classic "subdomain spoofing" trap — a frequent CUET/IPMAT cybersecurity case-study question.

## DIAGNOSTIC_QUESTION_5
Evaluate the validity of each URL. If invalid, state the specific syntactic error and correct it.
(a) `http://example.com/path with spaces/file.html`
(b) `https://example.com?query=value#fragment`
(c) `//cdn.example.com/script.js`

## DIAGNOSTIC_ANSWER_5
Correct evaluation:
(a) Invalid — spaces are not allowed in URLs; must be percent-encoded as `%20` or `+`. Corrected: `http://example.com/path%20with%20spaces/file.html`.
(b) Valid — path is empty (defaults to `/`), query and fragment are correctly delimited. Browser treats it as `https://example.com/?query=value#fragment`.
(c) Valid — protocol-relative URL (scheme-relative). Inherits the protocol of the current page (HTTP or HTTPS). Used for loading resources securely on both HTTP and HTTPS pages.
A wrong answer that marks (b) invalid because "path is missing" reveals the student does not know the path component is optional and defaults to `/` — a subtle point tested in board "find the error" questions.

## COMMON_MISCONCEPTION
Students consistently confuse the **domain name** with the **full host** and believe `www` is a mandatory part of every URL. For example, given `https://api.github.com/users/octocat`, many write "domain = www.api.github.com" or "subdomain = www" — incorrectly inserting `www` which is absent. This stems from over-exposure to `www`-prefixed websites in early browsing. The NCERT text explicitly states: "www is a subdomain... it is not mandatory to mention protocol and subdomain while entering a URL." Students also treat the fragment (`#section`) as part of the query string sent to the server, not realizing fragments are stripped by the browser before the request is made. This error costs marks in board "label the parts of a URL" questions and in competitive exam "which part is sent to server?" MCQs.

## WORKED_EXAMPLE_1
PROBLEM: A student is given the URL `https://www.cbse.gov.in/cbsenew/question_papers.html?year=2024&class=12&subject=informatics_practices#download` and asked to extract: (a) the protocol and why it matters for security, (b) the exact domain name registered with the registrar, (c) the path segments as a list, (d) the query parameters as a dictionary, (e) the fragment and whether it is sent to the server.

STEPS:
- Step 1: Identify the protocol by locating the substring before `://` → `https`. Reason: `https` indicates TLS encryption; `http` would send data in cleartext — critical for board "secure communication" questions.
- Step 2: Extract the host between `://` and the next `/` → `www.cbse.gov.in`. The registered domain is `cbse.gov.in` (second-level `cbse`, TLD `gov.in`); `www` is a subdomain. Reason: Domain registration happens at the second-level + TLD; subdomains are configured in DNS by the owner.
- Step 3: Extract the path between the first `/` after host and `?` → `/cbsenew/question_papers.html`. Split by `/` ignoring empty first segment → segments: `['cbsenew', 'question_papers.html']`. Reason: Path hierarchy mirrors server filesystem or routing logic.
- Step 4: Extract query string between `?` and `#` → `year=2024&class=12&subject=informatics_practices`. Split by `&` → pairs, then each by `=` → dict: `{'year': '2024', 'class': '12', 'subject': 'informatics_practices'}`. Reason: Query parameters are key-value data for server-side processing (filtering, pagination).
- Step 5: Extract fragment after `#` → `download`. Reason: Fragment is client-only; browser scrolls to element with `id="download"` after page loads. It is **never** transmitted in the HTTP request.

REASONING: This decomposition follows the RFC 3986 grammar: `URI = scheme ":" hier-part [ "?" query ] [ "#" fragment ]` where `hier-part` = `//` authority path-abempty. The fixed delimiter order (`://` → `/` → `?` → `#`) ensures unambiguous parsing. Board exams test this exact stepwise extraction in "label the parts" and "write the component" questions.

ANSWER: (a) Protocol: `https` (secure, encrypted). (b) Registered domain: `cbse.gov.in`. (c) Path segments: `cbsenew`, `question_papers.html`. (d) Query dict: `{'year': '2024', 'class': '12', 'subject': 'informatics_practices'}`. (e) Fragment: `download` (not sent to server).

The platform uses HTTPS, no `www` subdomain, and the path structure is `/course/{course_id}/week/{week_num}/lecture/{lecture_num}`. Query parameters: `quality` and `autoplay`.

## WORKED_EXAMPLE_3
PROBLEM: A school website has the base URL `https://school.edu.in`. The following malformed URLs were found in student project submissions. For each, identify the error, explain why it breaks parsing, and provide the corrected URL.
(i) `https:/school.edu.in/profile` (missing slash)
(ii) `https://school.edu.in/search?q=python programming` (space in query)
(iii) `https://school.edu.in/about#team#contact` (double fragment)
(iv) `https://school.edu.in:abc/admin` (non-numeric port)

STEPS:
- Step 1 (i): Error: Protocol delimiter is `://` (two slashes), not `:/`. Browser interprets `https:/school.edu.in` as path `school.edu.in` under protocol `https` with no host → fails. Correction: `https://school.edu.in/profile`.
- Step 2 (ii): Error: Space in query value `python programming` is not allowed; must be encoded as `python+programming` or `python%20programming`. Correction: `https://school.edu.in/search?q=python+programming`.
- Step 3 (iii): Error: Only one fragment allowed (first `#` starts it, second `#` is part of fragment value). Browser treats fragment as `team#contact` — likely not an existing element ID. Correction: Use single fragment `https://school.edu.in/about#team` or pass `contact` as query param `?section=team&contact=true`.
- Step 4 (iv): Error: Port must be numeric (1-65535). `abc` is invalid. Correction: Remove port (defaults to 443 for HTTPS) → `https://school.edu.in/admin` or use valid port `https://school.edu.in:8443/admin`.
- Step 5: General rule: URLs must conform to `scheme://[user:pass@]host[:port]/path[?query][#fragment]` with percent-encoding for reserved/unsafe chars in path/query/fragment.

REASONING: These errors represent the top 4 URL syntax mistakes in Class 12 practical files and board "find the error" questions. The protocol delimiter (`://`), space encoding, single fragment, and numeric port are explicitly tested in CBSE Sample Paper 2024 Q12(c) and CUET 2023 Section B Q18. Understanding *why* each breaks (parser state machine expects specific tokens) prevents rote memorization.

ANSWER: (i) Missing `/` in `://` → `https://school.edu.in/profile`. (ii) Space in query → `https://school.edu.in/search?q=python+programming`. (iii) Double `#` → `https://school.edu.in/about#team` (or use query). (iv) Non-numeric port → `https://school.edu.in/admin` (default port 443).

## COMPETENCY_QUESTION_2
QUESTION: Design a REST-style URL scheme for a Class 12 IP project "Student Attendance System" with domain `attendance.school.edu.in`. The system must support:
- Viewing attendance for a student (by roll number) for a given month/year.
- Filtering by status (Present/Absent/Late).
- Pagination (page number, page size).
- Exporting as CSV or PDF (format parameter).
Provide:
(a) Base URL pattern with path parameters for roll number, month, year.
(b) Full URL example for roll `23CS1045`, March 2024, status `Absent`, page 2, page size 20, format `csv`.
(c) Justify why `format` is a query parameter, not a path segment.

COMPETENCY: Translating real-world requirements into structured URL design — applying hierarchical vs. optional parameter distinction (REST best practice).

STEPS:
- Step 1: Identify required hierarchical identifiers (resource identity): student roll, month, year → these define the *resource* → place in path.
- Step 2: Identify optional filters/modifiers: status, pagination, export format → these modify *representation* of the same resource → place in query.
- Step 3: Design path: `/attendance/{roll}/{year}/{month}` (order: most specific to least specific, or logical hierarchy). Use lowercase, plural nouns per REST convention.
- Step 4: Design query: `?status=Absent&page=2&page_size=20&format=csv`.
- Step 5: Combine: `https://attendance.school.edu.in/attendance/23CS1045/2024/03?status=Absent&page=2&page_size=20&format=csv`.
- Step 6: Justify `format` in query: (i) Same resource (attendance data), different representation (HTML/CSV/PDF) — content negotiation via query is acceptable for simple APIs; (ii) Path segments imply hierarchy; `format` is not a sub-resource; (iii) Allows default (HTML) when omitted.

ANSWER: (a) `https://attendance.school.edu.in/attendance/{roll}/{year}/{month}` (b) `https://attendance.school.edu.in/attendance/23CS1045/2024/03?status=Absent&page=2&page_size=20&format=csv` (c) `format` controls representation of the *same* resource, not a distinct sub-resource; query parameters are the standard mechanism for content negotiation in simple REST APIs (alternatively `Accept` header, but query is testable in browser).
