## ELI5
A citizen clicks Submit on the complaint portal and — without any reload — the confirmation flashes, the button disables, the complaint joins the live list. That is DOM manipulation: JavaScript programmatically accessing, modifying, creating, or deleting HTML elements after the page loads. Locate nodes with getElementById or querySelector, read .value, build new <li> with createElement, fill .textContent, attach with appendChild. The DOM is a live tree — change a node and the screen changes with it.

## DEFINITION
DOM (Document Object Model) manipulation refers to the process of using JavaScript to programmatically access, modify, create, or delete HTML elements and their attributes, styles, and content after the page has loaded, enabling dynamic and interactive web pages.

## SCOPE_BOUNDARY
This node covers core DOM access methods (`getElementById`, `querySelector`, `querySelectorAll`), property modification (`innerHTML`, `textContent`, `style`, `classList`, `setAttribute`), element creation (`createElement`, `appendChild`, `insertBefore`), and removal (`remove`, `removeChild`). It does NOT cover advanced topics like `MutationObserver`, `Shadow DOM`, virtual DOM frameworks (React/Vue), or server-side DOM manipulation.

## WALKTHROUGH
Imagine you are building a "Digital India" complaint portal where citizens report civic issues. When a user clicks "Submit", you need to instantly show a confirmation message, disable the button, and add the complaint to a live list — all without reloading the page. This is where DOM manipulation begins: you first locate the form and list elements using `document.getElementById` or `querySelector`, then read input values via `.value`, create new `<li>` elements with `document.createElement`, populate them with `.textContent`, and append them to the `<ul>` using `.appendChild()`. The key insight is that the DOM is a live tree — every change you make to a node object instantly reflects on screen, so you must traverse and mutate it deliberately, not just edit HTML strings.

Takeaway: mastery means the tree traversed and mutated deliberately, never by editing HTML strings. Exam moves: selection questions choose getElementById, querySelector, or querySelectorAll; modification questions change innerHTML, textContent, style, classList, and attributes; creation questions build and append new elements in response to events; mix-up questions reject writing el.style = 'red' — style is an object whose individual properties, like el.style.color, must be set. Method: wire the complaint portal — select, read, create, populate, append — and disable the button in the same handler. Drill: two selectors, three mutations, one creation. The live tree repays precision with instant feedback.

## DIAGNOSTIC_QUESTION_1
What does `document.querySelector('.highlight')` return if there are three `<p class="highlight">` elements in the HTML?

## DIAGNOSTIC_ANSWER_1
It returns only the **first** matching element (the first `<p class="highlight">`), not a list. A wrong answer (e.g., "returns all three" or "returns an array") reveals the student confuses `querySelector` (single) with `querySelectorAll` (NodeList of all matches) — a critical distinction because calling `.style.color = 'red'` on a NodeList throws a TypeError.

## DIAGNOSTIC_QUESTION_2
Explain the difference between `element.innerHTML = '<b>Bold</b>'` and `element.textContent = '<b>Bold</b>'` when applied to a `<div id="msg">`.

## DIAGNOSTIC_ANSWER_2
`innerHTML` parses the string as HTML, so the `<b>` tags become actual bold markup — the div will render **Bold**. `textContent` treats the string as literal text, so the user sees the raw characters `<b>Bold</b>` on screen. A wrong answer indicates the student doesn't grasp that `innerHTML` triggers HTML parsing (security risk for user input) while `textContent` is safe for untrusted data — a common board exam trap in "prevent XSS" questions.

## DIAGNOSTIC_QUESTION_3
Write the exact JavaScript statements to: (a) select the `<input id="pincode">`, (b) read its value, (c) create a new `<span>` with class "error" containing "Invalid PIN", and (d) insert it immediately after the input field.

## DIAGNOSTIC_ANSWER_3

const input = document.getElementById('pincode');        // (a)

## DIAGNOSTIC_QUESTION_4
A student writes `document.getElementsByClassName('btn').addEventListener('click', fn)`. Why does this fail, and how would you fix it for all buttons with class "btn"?

## DIAGNOSTIC_ANSWER_4
`getElementsByClassName` returns an **HTMLCollection** (live), not a single element — it has no `addEventListener` method. Fix: use `document.querySelectorAll('.btn').forEach(btn => btn.addEventListener('click', fn))`. A wrong answer (e.g., "use `getElementById` instead") reveals the student doesn't understand that collection-returning methods (`getElementsBy*`, `querySelectorAll`) require iteration, while singleton methods (`getElementById`, `querySelector`) do not — a classic JEE-style "identify the bug" trap.

## DIAGNOSTIC_QUESTION_5
Critique this code for a "Load More" button that appends 5 new `<article>` elements to a `<section id="feed">`:
```js
const feed = document.getElementById('feed');
for (let i = 0; i < 5; i++) {
  feed.innerHTML += '<article>New Post</article>';
}
```
Identify two performance/functional issues and rewrite it correctly.

## DIAGNOSTIC_ANSWER_5
**Issues:** (1) `innerHTML +=` re-parses the **entire** feed content on every iteration, destroying event listeners on existing articles and causing O(n²) reflow. (2) It creates a stringly-typed workflow vulnerable to XSS if content is user-generated.  
**Correct rewrite:**
```js
const feed = document.getElementById('feed');
const frag = document.createDocumentFragment();
for (let i = 0; i < 5; i++) {
  const art = document.createElement('article');
  art.textContent = 'New Post';
  frag.appendChild(art);
}
feed.appendChild(frag);   // single reflow
```
A poor answer misses the reflow/event-listener destruction or suggests `insertAdjacentHTML` (still string-based). This tests deep understanding of DOM performance — a CUET/board competency differentiator.

## DIAGNOSTIC_QUESTION_6
Design a minimal "Aadhaar Masking" feature: an input field where the user types a 12-digit number, and on `blur`, the first 8 digits are replaced with `XXXX XXXX` while the last 4 remain visible. The original value must be stored in a `data-aadhaar` attribute for form submission. Provide the HTML and JavaScript.

## DIAGNOSTIC_ANSWER_6
**HTML:** `<input type="text" id="aadhaar" maxlength="12" placeholder="Enter 12-digit Aadhaar">`  
**JS:**
```js
const inp = document.getElementById('aadhaar');
inp.addEventListener('blur', () => {
  const raw = inp.value.replace(/\s/g, '');
  if (raw.length === 12 && /^\d{12}$/.test(raw)) {
    inp.dataset.aadhaar = raw;                    // store original
    inp.value = 'XXXX XXXX ' + raw.slice(8);      // masked display
  }
});
```
A good answer uses `dataset` for custom attributes, `slice` for masking, and validates length/format. A poor answer uses `setAttribute('data-aadhaar', ...)` (works but verbose) or modifies `value` without saving original — revealing ignorance of `dataset` API and form-data separation.

## COMMON_MISCONCEPTION
Students believe `document.getElementById('x').style = 'color: red; font-size: 18px'` works like CSS `style="..."`. In reality, `.style` is a **CSSStyleDeclaration object** — you must set individual properties: `el.style.color = 'red'; el.style.fontSize = '18px'` (camelCase!). They also think `classList.add('hide')` removes other classes; it only adds. This stems from treating `.style` and `.classList` as strings instead of live objects/sets — a mental model error reinforced by copying inline-style syntax.

## WORKED_EXAMPLE_1
PROBLEM: Build a "GST Calculator" for a small business. The page has two inputs: `amount` (number) and `gstRate` (select: 5%, 12%, 18%, 28%). On clicking "Calculate", show the GST amount and total in a `<div id="result">` formatted as ₹X,XXX.XX. If amount is empty or ≤ 0, show "Enter valid amount" in red.

STEPS:
- Step 1: Select all needed elements — `amountInput`, `rateSelect`, `calcBtn`, `resultDiv` — using `document.getElementById`.
- Step 2: Attach a `click` event listener to `calcBtn` that calls a handler function.
- Step 3: In handler, read `amountInput.value`, parse to float; read `rateSelect.value` (already a number like 18).
- Step 4: Validate: if `isNaN(amt) || amt <= 0`, set `resultDiv.textContent = 'Enter valid amount'`, `resultDiv.style.color = 'red'`, and return early.
- Step 5: Compute `gst = amt * rate / 100`, `total = amt + gst`. Format both with `toLocaleString('en-IN', {style: 'currency', currency: 'INR'})`.
- Step 6: Set `resultDiv.innerHTML = `GST: ${gstFmt}<br>Total: ${totalFmt}`;`, `resultDiv.style.color = 'green'`.

REASONING: This example combines form input reading (Step 3), validation with early return (Step 4), numeric computation (Step 5), locale-aware currency formatting (Indian context), and safe HTML injection via `innerHTML` for `<br>` (Step 6). Using `textContent` for error avoids XSS; `innerHTML` for result is safe because we generate the string ourselves.

ANSWER: Working GST calculator that updates result div dynamically without page reload.

## WORKED_EXAMPLE_2
PROBLEM: Create a "Dynamic To-Do List" for a student's study plan. HTML has `<input id="taskInput">`, `<button id="addBtn">Add</button>`, and `<ul id="taskList">`. On "Add" click: (a) read input, trim whitespace; if empty, alert and return. (b) Create `<li>` with task text and a "✕" delete button. (c) Clicking "✕" removes only that `<li>`. (d) Clear input after adding.

STEPS:
- Step 1: Select `taskInput`, `addBtn`, `taskList` via `getElementById`.
- Step 2: On `addBtn` click, get `text = taskInput.value.trim()`. If `!text`, `alert('Task cannot be empty')` and return.
- Step 3: Create `li = document.createElement('li')`. Set `li.textContent = text`.
- Step 4: Create `delBtn = document.createElement('button')`. Set `delBtn.textContent = '✕'`, `delBtn.className = 'del-btn'`.
- Step 5: Append `delBtn` to `li`, then append `li` to `taskList`.
- Step 6: Attach `click` listener to `delBtn`: `delBtn.onclick = () => li.remove()`.
- Step 7: Clear input: `taskInput.value = ''`; `taskInput.focus()`.

REASONING: Demonstrates element creation (`createElement`), composition (`appendChild`), event delegation at element level (each delete button handles its own `<li>` via closure), and UX details (trim, focus). The closure in Step 6 captures the specific `li` — a key JS pattern. Using `textContent` for task text prevents XSS if a student enters `<script>alert(1)</script>`.

ANSWER: Functional to-do list where tasks can be added and individually deleted, with input reset.

## WORKED_EXAMPLE_3
PROBLEM: Enhance the To-Do List (Worked Example 2) with: (a) "Mark Done" checkbox per task that strikes through text via CSS class `.done { text-decoration: line-through; opacity: 0.6; }`. (b) A "Clear Completed" button that removes all `.done` tasks. (c) Persist tasks to `localStorage` so they survive page reload.

STEPS:
- Step 1: In `addBtn` handler (from Ex 2), after creating `li`, prepend a checkbox: `const chk = document.createElement('input'); chk.type = 'checkbox'; chk.addEventListener('change', () => li.classList.toggle('done', chk.checked)); li.prepend(chk);`.
- Step 2: Add `<button id="clearDone">Clear Completed</button>` in HTML. Select it and attach click handler.
- Step 3: In clear handler: `document.querySelectorAll('#taskList li.done').forEach(li => li.remove())`.
- Step 4: Create `saveTasks()`: collect all tasks into array `[{text: li.childNodes[1].textContent, done: li.classList.contains('done')}]` (adjust index for checkbox), then `localStorage.setItem('tasks', JSON.stringify(arr))`.
- Step 5: Call `saveTasks()` after every add, delete, and checkbox change.
- Step 6: On page load (DOMContentLoaded), read `localStorage.getItem('tasks')`, parse JSON, and for each task re-create `<li>` with checkbox state and text, appending to `taskList`.

REASONING: Combines DOM manipulation (classList.toggle, querySelectorAll with compound selector, prepend), localStorage serialization (JSON.stringify/parse), and initialization from stored state. The `querySelectorAll('#taskList li.done')` efficiently selects only completed tasks. Re-creating elements on load mirrors real-world hydration patterns. This integrates 3+ concepts: DOM mutation, CSS class toggling, and client-side persistence.

ANSWER: Persistent to-do list with completion marking and bulk clear, surviving browser refresh.
