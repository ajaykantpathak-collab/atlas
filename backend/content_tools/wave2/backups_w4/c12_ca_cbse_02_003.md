## ELI5
A raw sales dump arrives: dates shown as serial numbers, amounts without separators, everything the same grey. Formatting turns it into a report — currency symbols on amounts, readable dates, colour scales that make scarce stock glow, banded table rows with filters. Nothing underneath changes; the value stays, the dress differs. That is the point: formatting is communication, not decoration, and the numbers remain exactly what they were.

## DEFINITION
Data formatting in spreadsheets refers to the systematic application of visual and structural rules — such as number formats (currency, percentage, date), text styles (font, alignment, borders), conditional formatting (color scales, data bars, icon sets), and table styles — to transform raw data into a readable, analysable, and professionally presentable worksheet without altering the underlying cell values.

It does NOT cover advanced chart formatting, pivot table styling details (covered in c12_ca_cbse_02_005), VBA-based formatting, or Power Query transformations.

## WALKTHROUGH
Imagine you have just received a raw sales dump from your family's small wholesale business: 500 rows of dates, product codes, quantities, unit prices, and customer names — all in default General format, left-aligned text, right-aligned numbers, no currency symbols, no thousand separators, and dates showing as serial numbers like 45231. Your task is to turn this into a report your father can read in 30 seconds to decide which products to restock. Start by selecting the amount column and applying Currency format with ₹ symbol and zero decimals; then format the date column as DD-MMM-YYYY; use Conditional Formatting → Color Scales on the quantity column to instantly spot high/low stock; apply a Table Style (Format as Table) to get banded rows, filter buttons, and a total row; finally set a print area and add a header with the firm's name. The key insight: formatting is not decoration — it is a communication layer that encodes meaning (e.g., red for negative, green for positive) so the viewer's brain processes patterns, not cells.

Takeaway: mastery means each formatting layer applied to a reason and the no-alteration rule stated. Exam moves: application questions format amounts, dates, and text for a reporting need; conditional questions deploy colour scales, data bars, and icon sets to surface exceptions; principle questions explain why formatting communicates patterns and never edits stored values. Method: give the raw dump the thirty-second test — what does the eye find first, and which format guided it there? Drill: five hundred rows, one report, one untouched value. The reader's brain should see patterns, not cells — formatting is how.

## DIAGNOSTIC_QUESTION_1
What is the default alignment for text and numeric values in an Excel cell before any formatting is applied?

## DIAGNOSTIC_ANSWER_1
By default, text is left-aligned and numeric values (including dates and times) are right-aligned in a cell. A wrong answer (e.g., "both are centered" or "text is right-aligned") reveals that the student has not observed the default behavior, which is critical because many formatting decisions (like applying Center alignment to headers only) depend on knowing the starting state.

## DIAGNOSTIC_QUESTION_2
A student enters `12/04/2024` in a cell and sees `12-Apr-2024` displayed. They then apply the "Number" format with 2 decimal places and see `45386.00`. Explain why the displayed value changed and what the number `45386` represents.

## DIAGNOSTIC_ANSWER_2
Excel stores dates as serial numbers where 1 = 1-Jan-1900; `45386` is the number of days since that epoch for 12-Apr-2024. Changing the format to Number reveals the underlying stored value. A student who says "the date got corrupted" or "Excel converted it wrongly" misunderstands that formatting only changes *display*, not the stored value — a core concept for later work with date arithmetic and conditional formatting on dates.

## DIAGNOSTIC_QUESTION_3
You have a column of profit margins (e.g., 0.12, 0.05, -0.03, 0.18). You want to display them as percentages with one decimal (12.0%, 5.0%, -3.0%, 18.0%) and highlight any negative margin in red font with a red fill. Describe the exact sequence of steps using the Ribbon (no shortcuts) to achieve both.

## DIAGNOSTIC_ANSWER_3
1. Select the range. 2. Home → Number group → click % (Percent Style) → click Increase Decimal once. 3. Home → Conditional Formatting → Highlight Cells Rules → Less Than → enter `0` → choose "Light Red Fill with Dark Red Text" → OK. A student who applies the red fill *before* percentage formatting may not realize the condition `Less Than 0` works on the underlying decimal (0.12, -0.03), not the displayed percentage — both work, but understanding the stored value is key for complex rules.

## DIAGNOSTIC_QUESTION_4
Compare "Format as Table" (Home → Styles → Format as Table) with manually applying banded row fill colors via Conditional Formatting → New Rule → Use a formula `=MOD(ROW(),2)=0`. Which method is more robust when rows are inserted or deleted, and why?

## DIAGNOSTIC_ANSWER_4
"Format as Table" is more robust because it creates a structured Table object (ListObject) that automatically maintains banded rows, filter buttons, and structured references when rows are added/removed. The Conditional Formatting formula approach breaks if rows are inserted above the range (ROW() shifts) or if the range is not updated. A student who prefers the formula method may not grasp that Tables are dynamic objects, not just formatting — a critical distinction for data integrity in accounting.

## DIAGNOSTIC_QUESTION_5
A colleague sends you a workbook where the "Total Sales" column shows `#####` in several cells. You widen the column and the numbers appear. The colleague insists the data was "fixed" by widening. Evaluate this claim: is the data actually fixed? What would you check to be sure?

## DIAGNOSTIC_ANSWER_5
The claim is false: `#####` is a *display* error (column too narrow or negative date/time), not a data error. The underlying values are intact. To verify, check the Formula Bar for a `#####` cell — it will show the actual number. Also check if any cell contains a negative date/time (e.g., `=A1-B1` where A1<B1) which also shows `#####` regardless of width. A student who thinks widening "fixes" the data confuses presentation with data integrity — dangerous in accounting where hidden negatives matter.

## DIAGNOSTIC_QUESTION_6
Design a conditional formatting rule (using a formula) for a range `B5:B100` (invoice amounts) that highlights the entire row (A5:F5, A6:F6, ...) in yellow if the invoice amount is greater than the average of all invoices in B5:B100 AND the invoice date in column A is in the current month. Write the formula for the rule applied to `A5:F100`.

## DIAGNOSTIC_ANSWER_6
`=AND($B5>AVERAGE($B$5:$B$100), MONTH($A5)=MONTH(TODAY()), YEAR($A5)=YEAR(TODAY()))` applied to `A5:F100`. The formula uses mixed references: column locked ($B, $A) so the condition travels across columns, row relative (5) so it evaluates per row. A student who writes `=$B5>AVERAGE(B5:B100)` without absolute references for the average range will get a shifting average — a classic error showing misunderstanding of reference locking in conditional formatting formulas.

## COMMON_MISCONCEPTION
Students believe that applying a format (e.g., Currency, Percentage, Date) *changes the stored value* in the cell. For example, they think typing `0.12` then applying % format makes it `12%` *and* changes the cell's numeric value to `12` (instead of `0.12`). This leads to errors in formulas: `=A1*100` on a cell showing `12%` (value 0.12) returns `12`, not `1200`. The misconception arises because the display *looks* like the value changed, and students rarely check the Formula Bar. In accounting, this causes GST calculations (18% on 0.18 vs 18) to be off by a factor of 100.

## ON_FAILURE
1. Have the student enter `0.18` in A1, apply % format (shows `18%`), then in B1 enter `=A1*100`. Ask: "What does B1 show? Why?" (Shows 18, not 1800). 2. Open Format Cells → Number tab → click between Category and Sample: point out "The sample changes, the value in the Formula Bar does not." 3. Assign a micro-task: create a column of 5 decimals (0.05, 0.12, etc.), apply % format, then use SUM on the column — verify the sum matches the decimal sum, not the displayed percent sum. 4. Re-diagnostic: give a cell with `18%` displayed, ask "What is the actual value? Write a formula to multiply it by 500 and predict the result."

## WORKED_EXAMPLE_1
PROBLEM: A stationery shop owner has a raw sales list in Excel: Column A = Date (serial numbers like 45386), Column B = Item, Column C = Qty, Column D = Unit Price (numbers like 15.5), Column E = Total (formula =C*D). The owner wants: (1) Dates as DD-MMM-YY, (2) Unit Price and Total as ₹ with 2 decimals and comma separator, (3) Negative totals (returns) in red font with parentheses, (4) Header row bold, blue font, light gray fill, centered, with bottom border. Show steps.

STEPS:
- Step 1: Select Column A → Home → Number Format dropdown → More Number Formats → Custom → type `DD-MMM-YY` → OK. (Converts serial numbers to 12-Apr-24 format).
- Step 2: Select Columns D and E → Home → Number group → click Comma Style (adds ₹ and commas, 2 decimals) → click Decrease Decimal once if needed to fix at 2 decimals. (Alternative: Format Cells → Currency → Symbol ₹ → Decimal places 2 → Negative numbers: (1,234.00) → OK).
- Step 3: For negative totals in red with parentheses: the Currency format step above with "Negative numbers: (1,234.00)" already does this; if using Custom, use format code: `₹#,##0.00;[Red](₹#,##0.00)`.
- Step 4: Select header row (Row 1) → Home → Font group: Bold (B), Font Color → Blue, Fill Color → Light Gray → Alignment → Center & Middle Align → Borders → Bottom Border (thick).
- Step 5: Verify: check Formula Bar for a date cell (still shows serial), a price cell (shows 15.5, not ₹15.50), a negative total (shows -25.00, not (₹25.00)). Print Preview to confirm visual result.

REASONING: Each step targets a specific formatting layer: number format for semantic meaning (date, currency), custom format for accounting convention (parentheses for negatives), and cell style for visual hierarchy (header distinct from data). The verification step reinforces that formatting ≠ value change.

ANSWER: Worksheet now displays dates as 12-Apr-24, prices as ₹15.50, totals as ₹1,234.50 or (₹25.00) for returns, with a professional header row.

## WORKED_EXAMPLE_2
PROBLEM: In a student fee register, Column D has "Days Overdue" (integers 0, 5, 30, 90). The admin wants: (1) 0 → "On Time" in green, (2) 1-30 → "Due" in yellow, (3) 31-60 → "Overdue" in orange, (4) >60 → "Critical" in red with white font. Achieve this using Conditional Formatting with Icon Sets *and* a custom rule for text labels in adjacent Column E.

STEPS:
- Step 1: Select D2:D100 → Home → Conditional Formatting → Icon Sets → 4 Icons (e.g., 4 traffic lights) → Manage Rules → Edit Rule → Set: Green ≥ 1, Yellow ≥ 31, Red ≥ 61 (adjust thresholds) → check "Show Icon Only" → OK. (This gives visual icons in Column D).
- Step 2: For text labels in Column E: select E2:E100 → Conditional Formatting → New Rule → Use a formula → enter `=D2=0` → Format → Font Color Green, Fill N/A → OK → Repeat for three more rules: `=AND(D2>=1,D2<=30)` → Yellow font; `=AND(D2>=31,D2<=60)` → Orange font; `=D2>60` → Red font, Bold, White font on red fill.
- Step 3: Order rules correctly in Manage Rules: the `=D2>60` rule must be *above* the others (or use Stop If True) because conditions overlap.
- Step 4: In E2 enter formula: `=IF(D2=0,"On Time",IF(D2<=30,"Due",IF(D2<=60,"Overdue","Critical")))` → copy down. (This ensures text labels match icons even if printed in B&W).
- Step 5: Test edge cases: change D5 to 0, 30, 31, 60, 61 → verify icon and text update. Check that formatting does not affect D's numeric value (Formula Bar shows 31, not "Overdue").

REASONING: Icon Sets provide instant visual scanning; text labels in adjacent column ensure accessibility (color-blind, B&W print). Using formulas for text labels decouples display from conditional formatting logic, making it auditable. Rule order matters because Excel evaluates top-down.

ANSWER: Column D shows colored icons; Column E shows "On Time"/"Due"/"Overdue"/"Critical" in corresponding colors; both update dynamically when Days Overdue changes.

## WORKED_EXAMPLE_3
PROBLEM: A GST invoice dataset (500 rows) has: Invoice Date (col A), GSTIN (col B), Taxable Value (col C), IGST 18% (col D = C*18%), Total (col E = C+D). The accountant needs: (1) Table with banded rows, filter buttons, total row showing Sum of Taxable Value and Total, (2) Conditional formatting on Total column: Data Bars (gradient fill) for quick visual of invoice size, (3) Custom number format for GSTIN: `00AAAAA0000A0Z0` (15-char pattern) to validate structure, (4) Print setup: landscape, fit to 1 page wide, header "GST Invoices - FY 2024-25", footer "Page &[Page] of &[Pages]", print area = entire table. Show steps.

STEPS:
- Step 1: Select any cell in data → Home → Format as Table → choose Medium style with banded rows → check "My table has headers" → OK. Table Tools → Design → check "Total Row" → in Total Row, for Taxable Value and Total columns, choose "Sum" from dropdown.
- Step 2: Select Total column (structured ref: Table1[Total]) → Home → Conditional Formatting → Data Bars → Gradient Fill → Blue → Manage Rules → Edit Rule → check "Show Bar Only" (optional) → set Minimum = Lowest Value, Maximum = Highest Value → OK.
- Step 3: Select GSTIN column → Format Cells → Custom → Type: `00AAAAA0000A0Z0` → OK. (Note: this is display-only; for validation use Data Validation → Custom → formula `=AND(LEN(B2)=15, ISNUMBER(MATCH(LEFT(B2,2),{"01".."99"},0)), ...)` but custom format helps visual check).
- Step 4: Page Layout → Orientation → Landscape → Scale to Fit → Width: 1 page, Height: Automatic → Page Setup → Header/Footer → Custom Header → Center: "GST Invoices - FY 2024-25" → Custom Footer → Center: "Page &[Page] of &[Pages]" → Sheet tab → Print Area → select table range (auto-named) → Print Titles → Rows to repeat at top: $1:$1 (header row) → OK.
- Step 5: Print Preview → verify: banded rows, filter buttons hidden in print, total row at bottom, data bars visible, GSTIN aligned, header/footer on each page, all columns fit on one page wide.

REASONING: Combines Table object (dynamic range, structured references, auto-total), conditional formatting (data bars for magnitude), custom format (pattern enforcement), and page setup (professional printing). The accountant can now filter by GSTIN, see large invoices via bars, and print a compliant report.

ANSWER: A fully formatted, filterable, printable GST invoice table with visual analytics and structural validation cues.

## COMPETENCY_QUESTION_1
QUESTION: You receive a workbook where a colleague has formatted a column of "Discount %" values (e.g., 5, 10, 15) using Custom format `0"%"` so they display as `5%`, `10%`, `15%`. The column is used in a formula `=Price * (1 - Discount%)` to calculate net price. The results are wrong (e.g., Price=1000, Discount=5 → Net=995 instead of 950). Explain why the formula fails and provide two correct approaches: one by changing the data, one by changing the formula.

COMPETENCY: Error identification and correction in formatting-formula interaction
STEPS:
- Step 1: Recognize that Custom format `0"%"` only appends "%" text; the stored value remains 5, not 0.05.
- Step 2: The formula `=Price * (1 - Discount%)` treats `Discount%` as 5 (not 0.05), so `1-5 = -4`, `1000 * -4 = -4000` — but the example shows 995, implying they used `=Price - Discount%` (1000-5=995). Either way, the discount is treated as absolute rupees, not percentage.
- Step 3: Approach 1 (change data): Re-enter discounts as decimals (0.05, 0.10) and apply Percentage format (Home → %). Then `=Price * (1 - Discount)` works.
- Step 4: Approach 2 (change formula): Keep data as 5,10,15 but use `=Price * (1 - Discount/100)` or `=Price * (100 - Discount)/100`.
- Step 5: Verify with test case: Price=1000, Discount=5 → Net=950 in both approaches.

ANSWER: The formula fails because formatting does not change the stored numeric value. Correct approach 1: store 0.05 and use % format. Correct approach 2: store 5 and divide by 100 in formula. Both yield Net=950 for 5% discount on ₹1000.
DIFFICULTY: medium

## COMPETENCY_QUESTION_2
QUESTION: A school fee register uses Conditional Formatting on "Balance Due" column (E) with three rules (in order): 1) `=$E2>0` → Red fill, 2) `=$E2=0` → Green fill, 3) `=$E2<0` → Blue fill (credit balance). A student has Balance Due = 0 but the cell shows Red fill. Diagnose the cause and fix it without changing the rule formulas.

COMPETENCY: Analyzing and debugging conditional formatting rule precedence
STEPS:
- Step 1: Understand that Conditional Formatting rules are evaluated top-down; the first TRUE rule applies and stops (unless "Stop If True" is unchecked).
- Step 2: For Balance Due = 0, rule 1 `=$E2>0` is FALSE, rule 2 `=$E2=0` is TRUE → should be Green. But it shows Red → meaning rule 1 evaluated TRUE.
- Step 3: Check if the cell actually contains a tiny positive number (e.g., 0.0001) due to floating-point arithmetic from a formula like `=ROUND(Fees-Paid,2)` where Fees-Paid = 0.0000001. The displayed value shows 0.00 (due to number format), but the stored value >0.
- Step 4: Fix: either (a) change rule 1 to `=$E2>0.005` (tolerance) or (b) wrap the Balance Due formula in `ROUND(...,2)` so 0.0001 becomes 0. Or (c) reorder rules: put `=$E2=0` first.
- Step 5: Best fix: Round the source formula to 2 decimals (accounting precision) AND keep rule order logical (Zero first, then Positive, then Negative). This prevents similar issues for near-zero values.

ANSWER: The cell's stored value is a tiny positive number (e.g., 1E-6) displayed as 0.00 due to formatting. Rule 1 (`>0`) catches it. Fix: Round the Balance Due formula to 2 decimals (`=ROUND(Fees-Paid,2)`) and reorder rules: Zero first, then Positive, then Negative.
DIFFICULTY: hard
