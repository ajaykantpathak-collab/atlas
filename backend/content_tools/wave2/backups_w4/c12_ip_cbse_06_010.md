## ELI5
A calculator page stores the book price of ₹450 and a quantity of 3 — JavaScript needs boxes and rules for both. Variables are named containers declared with var, let, or const; data types split into primitives — String, Number, Boolean, Null, Undefined, Symbol, BigInt — and reference types like Object and Array. Operators combine them: arithmetic, comparison, logical, assignment, ternary — with === checking value and type together. Store, type, operate: the whole language in three moves.

## DEFINITION
JavaScript variables are named containers for storing data values that can be changed during program execution, declared using `var`, `let`, or `const` keywords with `let` and `const` being block-scoped (ES6+). Data types are classified as primitive (String, Number, Boolean, Null, Undefined, Symbol, BigInt) and non-primitive/reference (Object, Array, Function), where primitives hold single immutable values and reference types hold memory addresses to complex structures. Operators are symbols that perform operations on operands: arithmetic (`+`, `-`, `*`, `/`, `%`, `**`), comparison (`==`, `===`, `!=`, `!==`, `>`, `<`, `>=`, `<=`), logical (`&&`, `||`, `!`), assignment (`=`, `+=`, `-=`, etc.), and ternary (`condition ? expr1 : expr2`), with strict equality (`===`) checking both value and type without coercion.

## DIAGNOSTIC_QUESTION_1
What is the output of `typeof null` in JavaScript, and why does this result often surprise beginners who expect it to be `"null"`?

## DIAGNOSTIC_ANSWER_1
The output is `"object"`. This is a long-standing JavaScript quirk from the first implementation where `null` was represented as a null pointer (0x00) which the `typeof` operator identified as an object. Beginners expect `"null"` because `null` is a primitive value, but `typeof` returns `"object"` for `null`. A wrong answer (e.g., `"null"` or `"undefined"`) reveals the student has memorised the primitive list but hasn't encountered this specific historical bug that appears in CBSE theory questions and competitive exam MCQs.

## DIAGNOSTIC_QUESTION_2
Explain the difference between `let` and `const` in terms of reassignment and mutation. If you declare `const arr = [1, 2];`, can you execute `arr.push(3)`? Can you execute `arr = [4, 5];`? Justify both answers.

## DIAGNOSTIC_ANSWER_2
`let` allows reassignment (binding a new value to the same variable name); `const` forbids reassignment but allows mutation of the object/array it references. `arr.push(3)` works because it mutates the existing array object — the binding `arr` still points to the same array. `arr = [4, 5]` fails with `TypeError: Assignment to constant variable` because it attempts to rebind `arr` to a new array. A student who says both fail or both work confuses reassignment with mutation — a critical distinction for CBSE practicals where `const` is preferred for arrays/objects that will be modified in place.

## DIAGNOSTIC_QUESTION_3
Predict the output of each expression and explain the type coercion rule applied:
(a) `"10" + 5`
(b) `"10" - 5`
(c) `true + 2`
(d) `null + 1`
(e) `undefined + 1`

## DIAGNOSTIC_ANSWER_3

## DIAGNOSTIC_QUESTION_4
Compare `==` and `===` with these pairs. For each, state the result of both operators and explain WHY they differ or match:
(i) `0 == false` vs `0 === false`
(ii) `"" == false` vs `"" === false`
(iii) `null == undefined` vs `null === undefined`
(iv) `"5" == 5` vs `"5" === 5`

## DIAGNOSTIC_ANSWER_4
(i) `0 == false` → `true` (both coerce to 0); `0 === false` → `false` (number vs boolean, different types). (ii) `"" == false` → `true` (both coerce to 0); `"" === false` → `false` (string vs boolean). (iii) `null == undefined` → `true` (special ECMA spec rule: they are loosely equal only to each other); `null === undefined` → `false` (different types: `object` vs `undefined`). (iv) `"5" == 5` → `true` (string coerced to number); `"5" === 5` → `false` (string vs number). A student claiming `===` is "stricter `==`" without explaining the coercion steps misses the mechanistic difference — CBSE asks "why" in 2-mark questions.

## DIAGNOSTIC_QUESTION_5
A student writes this code to check if a user-entered age (from `prompt()`) is eligible for voting (age ≥ 18):
```javascript
let age = prompt("Enter age:");
if (age >= 18) { alert("Eligible"); } else { alert("Not eligible"); }
```
When they test with input `18`, it works. But input `"18"` (with quotes) also works. Input `"eighteen"` shows "Not eligible" but no error. Identify the latent bug and rewrite the code to robustly validate numeric input, explaining each fix.

## DIAGNOSTIC_ANSWER_5
`prompt()` always returns a string. `age >= 18` triggers implicit coercion: `"18"` → `18` (works), `"eighteen"` → `NaN`, and `NaN >= 18` is `false` (silently wrong). The bug: non-numeric strings pass the `else` branch without validation. Fix:
```javascript
let input = prompt("Enter age:");
let age = Number(input);
if (Number.isNaN(age) || age < 0 || !Number.isInteger(age)) {
  alert("Invalid age");
} else if (age >= 18) { alert("Eligible"); }
else { alert("Not eligible"); }
```
`Number()` converts string to number (returns `NaN` for invalid). `Number.isNaN()` detects conversion failure. Checks for negative and non-integer ages. A student who only adds `parseInt()` misses `NaN` handling and `"18.5"` → `18` truncation — CUET practicals test this exact validation pattern.

## COMMON_MISCONCEPTION
Students believe `const` makes the value immutable (like `final` in Java). They write `const x = 5; x = 10;` and are surprised it errors, but then write `const arr = []; arr.push(1);` and think it should also error — or conversely, they think `const obj = {}; obj = {a:1};` works because "objects are mutable." The root error: confusing **variable binding** (the name-to-memory-address link) with **value mutability** (changing the contents at that address). `const` freezes the binding, not the value. This causes bugs in CBSE practicals where students declare `const students = [];` then later try `students = filterStudents(students);` (reassignment fails) instead of `students.length = 0; students.push(...filtered);` (mutation works). The misconception stems from applying Java/C++ `const`/`final` mental models to JavaScript's reference semantics.

## WORKED_EXAMPLE_2
PROBLEM: A web form collects a student's name (string), age (number from input), and whether they have a scholarship (checkbox → boolean). Write JavaScript code that validates: age must be a positive integer ≤ 25; if valid, compute fee as ₹50,000 minus 50% if scholarship else full fee; display result. Handle invalid age gracefully.

STEPS:
- Step 1: Simulate form inputs using variables (in real code, these come from `document.getElementById().value`): `const name = "Priya"; const ageInput = "20"; const hasScholarship = true;`
- Step 2: Convert age string to number explicitly: `const age = Number(ageInput);` — `Number()` returns `NaN` for non-numeric strings, unlike `parseInt()` which parses leading digits.
- Step 3: Validate age using logical AND (`&&`) combining three checks: `const isValidAge = Number.isInteger(age) && age > 0 && age <= 25;` — `Number.isInteger()` rejects floats like `20.5`; short-circuit evaluation stops at first `false`.
- Step 4: Use ternary operator for conditional fee: `const fee = isValidAge ? (hasScholarship ? 50000 * 0.5 : 50000) : null;` — nested ternary mirrors `if-else` but is an expression yielding a value.
- Step 5: Display result using template literal with conditional message: `console.log(isValidAge ? `${name}, your fee is ₹${fee.toFixed(2)}` : `${name}, invalid age: ${ageInput}`);`

REASONING: Explicit `Number()` conversion + `Number.isInteger()` validation is the robust pattern CBSE expects for form handling — `parseInt("20abc")` returns `20` (silent bug), while `Number("20abc")` returns `NaN` (caught). Logical AND (`&&`) chains conditions efficiently. Ternary operator keeps fee calculation as a single expression assignable to `const`. The final `console.log` uses a ternary to choose between two message templates, avoiding duplicate code. This demonstrates "defensive programming" — validating external input before computation.

ANSWER:
Priya, your fee is ₹25000.00

## COMPETENCY_QUESTION_1
QUESTION: A CBSE practical question asks: "Write a JavaScript program to calculate the total marks and percentage for 5 subjects. Marks are entered via `prompt()` for each subject. Maximum marks per subject is 100. Display total, percentage (2 decimals), and grade (A: ≥90%, B: ≥75%, C: ≥60%, D: ≥40%, E: <40%). Validate that each input is a number between 0 and 100."

COMPETENCY: Translating real-world requirements into structured code with input validation, stepwise computation, and multi-branch conditional logic

STEPS:
- Step 1: Initialize array of subject names and empty marks array
- Step 2: Loop 5 times, each time: prompt for marks, convert with `Number()`, validate (not NaN, integer, 0-100), re-prompt on failure using `while`
- Step 3: Compute total using `reduce()` or loop
- Step 4: Compute percentage = (total / 500) * 100
- Step 5: Determine grade using if-else if ladder (ordered highest to lowest)
- Step 6: Display all results using template literals

ANSWER:
```javascript
const subjects = ["Physics", "Chemistry", "Maths", "English", "CS"];
const marks = [];
for (const sub of subjects) {
  let input, mark;
  do {
    input = prompt(`Enter marks for ${sub} (0-100):`);
    mark = Number(input);
    if (Number.isNaN(mark) || !Number.isInteger(mark) || mark < 0 || mark > 100) {
      alert("Invalid! Enter integer 0-100.");
    }
  } while (Number.isNaN(mark) || !Number.isInteger(mark) || mark < 0 || mark > 100);
  marks.push(mark);
}
const total = marks.reduce((sum, m) => sum + m, 0);
const percentage = (total / 500) * 100;
let grade;
if (percentage >= 90) grade = 'A';
else if (percentage >= 75) grade = 'B';
else if (percentage >= 60) grade = 'C';
else if (percentage >= 40) grade = 'D';
else grade = 'E';
console.log(`Total: ${total}/500`);
console.log(`Percentage: ${percentage.toFixed(2)}%`);
console.log(`Grade: ${grade}`);
```
