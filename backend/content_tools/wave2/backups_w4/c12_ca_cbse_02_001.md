## ELI5
The kirana owner hands you two hundred sales slips and asks for monthly revenue, high-value items, and the GST collected. In a spreadsheet each sale becomes a row; revenue is a formula; GST a rate locked in one cell so every row obeys it. Copy the formula down and the month computes itself — change the rate once and every figure ripples. A spreadsheet is not a table; it is a live model.

## DEFINITION
A spreadsheet is a computer application that organizes data in a grid of rows and columns forming cells, where each cell can hold a value (numeric, text, date), a formula (arithmetic expression starting with =), or a function (predefined calculation like SUM, IF, VLOOKUP), enabling automated calculation, what-if analysis, and structured reporting for accounting and financial decision-making.

It does NOT cover advanced PivotTable design (node c12_ca_cbse_02_005), complex nested functions beyond 2-level IF, macro/VBA programming, or database connectivity — these are beyond NCERT Class 12 scope.

## WALKTHROUGH
Imagine you are the accountant for a small Delhi-based wholesale kirana store. The owner hands you a notebook with 200 daily sales entries — item name, quantity, unit price, date — and asks: "What was our total revenue last month? Which items sold above ₹5,000? How much GST did we collect at 18%?" Doing this manually with a calculator takes hours and risks errors. Open Excel: each row becomes one sale, columns become Item, Qty, Price, Date, Revenue (=Qty*Price), GST (=Revenue*18%). Suddenly, SUM(Revenue) gives monthly total, COUNTIF(Revenue,">5000") counts high-value items, and a PivotTable (next node) summarizes by item/category. This node teaches you the building blocks: how to structure that grid, write =B2*C2 correctly so it copies down 200 rows (relative reference), lock the GST rate cell with $F$1 (absolute reference), and name the rate cell "GST_Rate" for readability. Start by opening a blank workbook, press Ctrl+Home to reach A1, type headers in Row 1, enter 5 sample rows in Rows 2–6, then build your first formula in E2. The key insight: a spreadsheet is not a static table — it is a dynamic model where changing one input (e.g., GST rate from 18% to 12%) instantly ripples through all derived values.

Takeaway: mastery means the grid structured, the references understood, and the model's dynamism demonstrated. Exam moves: navigation questions identify the active cell and distinguish relative, absolute, and mixed references; formula questions build correct expressions with the order of operations and core functions; modelling questions show one input change rippling through derived values. Method: build the five-row sample first, lock the rate cell, then copy down and change the rate once to watch the ripple. Drill: two hundred slips, one locked cell, one ripple. The ripple is what separates a model from a typed table.

## DIAGNOSTIC_QUESTION_1
What is the cell address of the cell located at the intersection of column IV and row 65536 in Excel 2007, and how many total cells exist in one worksheet?

## DIAGNOSTIC_ANSWER_1
The cell address is IV65536. Total cells = 65,536 rows × 256 columns = 16,777,216 cells. A wrong answer like "IV65536 has 1,65,00,000 cells" reveals the student misread the NCERT approximation (1.65 crore) as exact, or confused 256 columns (A to IV) with 256 rows — a common error when students don't verify column count: A=1, Z=26, AA=27, ..., IV=256.

## DIAGNOSTIC_QUESTION_2
In cell E4 you enter the formula `=B4*C4` to calculate Revenue (Qty × Price). You copy this formula down to E5:E100. What happens to the cell references, and why is this behavior called "relative referencing"?

## DIAGNOSTIC_ANSWER_2
In E5 the formula becomes `=B5*C5`, in E6 `=B6*C6`, ..., in E100 `=B100*C100`. The row numbers adjust automatically because the references B4 and C4 are relative (no $ signs). A wrong answer like "references stay B4 and C4" or "references become $B$4 and $C$4" reveals the student confuses relative with absolute referencing — a critical error because if the formula didn't adjust, every row would multiply the same Qty and Price from Row 4, giving identical (wrong) revenue for all 100 sales.

## DIAGNOSTIC_QUESTION_3
You have GST rate 18% in cell G1. In column F you want GST Amount = Revenue × GST_Rate for rows 2 to 100. Write the formula for F2 using absolute referencing so it copies correctly down to F100. Then explain what happens if you mistakenly use relative reference `=E2*G1` and copy down.

## DIAGNOSTIC_ANSWER_3
Correct formula: `=E2*$G$1` (or `=E2*G$1` since only row must lock). When copied to F3, it becomes `=E3*$G$1` — column G and row 1 stay fixed. If you use `=E2*G1` (relative), in F3 it becomes `=E3*G2` — G2 is empty/zero, so GST calculates as zero for all rows below Row 2. This "shifting reference" error is the #1 cause of silent calculation mistakes in board practical exams — students see correct Row 2, assume all rows work, and lose marks.

## DIAGNOSTIC_QUESTION_4
Compare the formulas `=IF(A2>10000, "High", "Low")` and `=IF(A2>10000, "High", IF(A2>5000, "Medium", "Low"))`. For a value of 7500 in A2, what does each return? Explain the logic flow of the nested IF.

## DIAGNOSTIC_ANSWER_4
First formula returns "Low" (7500 ≤ 10000). Second formula: outer IF checks 7500>10000 → FALSE → goes to value_if_false which is another IF: inner IF checks 7500>5000 → TRUE → returns "Medium". A wrong answer like "both return Low" or "nested IF gives error" reveals the student doesn't trace the FALSE branch into the nested IF — they treat nested IF as parallel rather than sequential. In board exams, nested IF questions often test this exact "fall-through" logic for slab-based calculations (tax, commission, grading).

## DIAGNOSTIC_QUESTION_5
A student writes `=VLOOKUP(100, A2:D10, 5, FALSE)` to find a value in the 5th column of a 4-column table (A:D). What error will Excel return, and why? Propose two ways to fix it without changing the table range.

## DIAGNOSTIC_ANSWER_5
Excel returns `#REF!` because `col_index_num=5` exceeds the 4 columns in `table_array=A2:D10`. Fix 1: change 5 to 4 (if 4th column has desired data). Fix 2: use `=INDEX(D2:D10, MATCH(100, A2:A10, 0))` — INDEX/MATCH doesn't require column index within table_array. A wrong answer like "#N/A" or "#VALUE!" reveals confusion between "column not found" (#REF!) vs "lookup value not found" (#N/A). This distinction is tested in CBSE practical viva: "Why did your VLOOKUP give #REF! not #N/A?"

## DIAGNOSTIC_QUESTION_6
Design a mini-spreadsheet (describe layout, not build) to calculate EMI for a ₹10 lakh home loan at 8.5% p.a. for 20 years, using the PMT function. Specify: (a) which cells hold inputs (rate, nper, pv), (b) the exact PMT formula with correct sign convention, (c) how to make it a what-if model so changing rate in one cell updates EMI instantly.

## DIAGNOSTIC_ANSWER_6
(1) The input cells — B2 holds the annual rate, B3 the number of years and B4 the loan amount, (2) The formula — B6 carries =PMT(B2/12, B3*12, -B4), with the rate divided and the years multiplied by twelve to match monthly periods, (3) The sign convention — the loan amount enters negative because it is money received, so the EMI comes out positive, about 8678 rupees, (4) The what-if design — because the formula references the input cells, changing the rate cell alone recalculates the EMI instantly. A poor answer hard-codes the numbers inside PMT, which is not a what-if model, or forgets the periodicity conversion and gets a wildly wrong EMI.

## COMMON_MISCONCEPTION
Students believe "formulas and functions are the same thing" and write `=SUM(A1+A2)` instead of `=A1+A2` or `=SUM(A1:A2)`. They also think `=IF(A1>10, "Yes", "No")` is a formula, not a function. Why: NCERT uses "formula" broadly for any expression starting with =, but technically a formula is user-defined arithmetic (e.g., `=B2*C2`), while a function is a predefined keyword (SUM, IF, VLOOKUP). In board exams, questions like "Write a function to calculate total sales" require `=SUM(D2:D100)`, not `=D2+D3+...`. Writing `=SUM(D2+D3+...)` works but defeats SUM's purpose (range argument) and shows conceptual confusion. Another error: using `=AVERAGE(A1, A2, A3)` for non-contiguous cells instead of `=AVERAGE(A1:A3)` for range — both work but the latter is scalable. Students memorize syntax without grasping "function = named operation with arguments; formula = your own expression."

## ON_FAILURE
If the student confuses formulas/functions or misuses cell references: (1) Have them create a 5-row sheet: Col A=Qty, Col B=Price, Col C=Revenue. In C2 type `=A2*B2` (formula). In C7 type `=SUM(C2:C6)` (function). Ask: "What happens if I insert a row between 3 and 4?" — formula in new C4 auto-fills, SUM expands to C2:C7. (2) For absolute reference: put tax rate 18% in F1. In D2 type `=C2*$F$1`, copy down. Change F1 to 12% — all GST updates. Then delete $ signs, repeat — only D2 updates. (3) For nested IF: give a 3-slab commission problem (≤10k: 2%, 10k-50k: 5%, >50k: 8%). Walk through tracing A2=25000 through `=IF(A2<=10000, A2*2%, IF(A2<=50000, A2*5%, A2*8%))`. Emphasize: each IF is a complete "if-else" block, not a list of conditions.

## WORKED_EXAMPLE_1
PROBLEM: A stationery shop sells 3 items. Row 2: Pens, Qty=150, Price=₹10. Row 3: Notebooks, Qty=80, Price=₹45. Row 4: Erasers, Qty=200, Price=₹5. GST rate 18% is in cell G1. Build a spreadsheet to calculate: (a) Revenue per item (Qty × Price), (b) GST per item (Revenue × 18%), (c) Total Revenue, Total GST, Grand Total (Revenue + GST). Use absolute reference for GST rate. Show formulas for Row 2 and Row 3.

STEPS:
- Step 1: Set up headers in Row 1: A1=Item, B1=Qty, C1=Price, D1=Revenue, E1=GST, F1=Total. Enter data in Rows 2–4. Enter 0.18 in G1 (not 18).
- Step 2: In D2 (Revenue for Pens), enter formula `=B2*C2` → 150×10 = 1500. This is a basic arithmetic formula with relative references.
- Step 3: In E2 (GST for Pens), enter formula `=D2*$G$1` → 1500×0.18 = 270. The $G$1 locks column G and row 1 so copying down keeps GST rate fixed.
- Step 4: In F2 (Total for Pens), enter formula `=D2+E2` → 1500+270 = 1770. Alternatively `=D2*(1+$G$1)`.
- Step 5: Copy D2:F2 down to D3:F4 (drag fill handle or Ctrl+D). Verify D3 becomes `=B3*C3` (80×45=3600), E3 becomes `=D3*$G$1` (3600×0.18=648), F3 becomes `=D3+E3` (4248).
- Step 6: In D5 (Total Revenue), enter `=SUM(D2:D4)` → 1500+3600+1000 = 6100. In E5 (Total GST), `=SUM(E2:E4)` → 270+648+180 = 1098. In F5 (Grand Total), `=SUM(F2:F4)` or `=D5+E5` → 7198.
- Step 7: Test what-if: change G1 to 0.12 (12%). All GST and Total columns recalculate automatically — Revenue unchanged, GST drops to 732, Grand Total = 6832.

REASONING: This example demonstrates the complete workflow: basic values (Qty, Price, GST rate) entered once; derived values (Revenue, GST, Total) built with formulas using relative references for row-specific data and absolute reference for the constant rate; aggregation (SUM) for totals. The absolute reference $G$1 is the key to what-if analysis — changing one cell propagates to all dependent cells. Using 0.18 not 18 in G1 avoids the common error of multiplying by 18 instead of 0.18.

ANSWER: Row 2: D2=`=B2*C2` (1500), E2=`=D2*$G$1` (270), F2=`=D2+E2` (1770). Row 3: D3=`=B3*C3` (3600), E3=`=D3*$G$1` (648), F3=`=D3+E3` (4248). Totals: Revenue=6100, GST=1098, Grand Total=7198.

## WORKED_EXAMPLE_2
PROBLEM: An employee's monthly sales (in ₹) for Jan–Jun are in B2:G2: 45000, 52000, 48000, 61000, 55000, 49000. Commission structure: ≤50000 → 3%; 50001–60000 → 5%; >60000 → 7%. Write a nested IF formula in H2 to calculate commission for January, then copy across to H2:M2 for all months. Show the formula and compute Jan, Feb, Apr commissions.

STEPS:
- Step 1: Understand the slab logic: three tiers, mutually exclusive. Nested IF must check from lowest to highest (or highest to lowest) without overlap.
- Step 2: Write nested IF for January (B2=45000). Since 45000 ≤ 50000, commission = 45000 × 3% = 1350. Formula: `=IF(B2<=50000, B2*3%, IF(B2<=60000, B2*5%, B2*7%))`.
- Step 3: Trace logic for B2=45000: First condition B2<=50000 is TRUE → returns B2*3% = 1350. Stops. Correct.
- Step 4: Trace for February (C2=52000): First condition 52000<=50000 is FALSE → goes to second IF: 52000<=60000 is TRUE → returns 52000*5% = 2600. Correct.
- Step 5: Trace for April (E2=61000): First condition FALSE, second condition 61000<=60000 FALSE → goes to final value_if_false: 61000*7% = 4270. Correct.
- Step 6: Enter formula in H2. Copy across to I2:M2 (Ctrl+R or drag fill handle). References shift: H2 uses B2, I2 uses C2, ..., M2 uses G2 — relative column reference works horizontally.
- Step 7: Verify all: Jan=1350, Feb=2600, Mar=1440 (48000*3%), Apr=4270, May=2750 (55000*5%), Jun=1470 (49000*3%). Total commission = SUM(H2:M2) = 13880.

REASONING: Nested IF evaluates sequentially — first TRUE condition wins. Order matters: checking >60000 first would misclassify 52000 as >60000 if written incorrectly. The formula uses relative column reference (B2, not $B$2) so copying right shifts to C2, D2, etc. Percentage written as 3% (Excel stores as 0.03) avoids decimal conversion error. This pattern (slab-based calculation) appears in tax, commission, grading — a board exam staple.

ANSWER: Formula in H2: `=IF(B2<=50000, B2*3%, IF(B2<=60000, B2*5%, B2*7%))`. Jan (45000): 1350. Feb (52000): 2600. Apr (61000): 4270. Total 6-month commission: 13880.

## WORKED_EXAMPLE_3
PROBLEM: A trader has product codes and prices in a lookup table: A2:A6 = {P101, P102, P103, P104, P105}, B2:B6 = {250, 480, 1200, 350, 900}. In a sales sheet, Column D has sold product codes (D2=P103, D3=P101, D4=P105, D5=P102, D6=P104). Column E has quantities sold (E2=5, E3=10, E4=2, E5=8, E6=3). Use VLOOKUP to fetch price for each code in Column F, then calculate Line Total (Qty × Price) in Column G. Write formulas for F2 and G2, explain VLOOKUP arguments, and compute all line totals.

STEPS:
- Step 1: Identify lookup table: A2:B6 (2 columns: Code, Price). Codes are in first column (A), prices in second (B). Table is sorted? P101, P102, P103, P104, P105 — yes, ascending.
- Step 2: For F2 (Price for P103), VLOOKUP arguments: lookup_value=D2 (P103), table_array=$A$2:$B$6 (absolute so table doesn't shift when copied), col_index_num=2 (price is 2nd column), range_lookup=FALSE (exact match required for codes).
- Step 3: Formula F2: `=VLOOKUP(D2, $A$2:$B$6, 2, FALSE)` → returns 1200 (price of P103).
- Step 4: Formula G2 (Line Total): `=E2*F2` → 5 × 1200 = 6000.
- Step 5: Copy F2:G2 down to F6:G6. F3: `=VLOOKUP(D3, $A$2:$B$6, 2, FALSE)` → D3=P101 → 250. G3: 10×250=2500. F4: P105→900, G4: 2×900=1800. F5: P102→480, G5: 8×480=3840. F6: P104→350, G6: 3×350=1050.
- Step 6: Total Sales = SUM(G2:G6) = 6000+2500+1800+3840+1050 = 15190.
- Step 7: Error check: If a code not in table (e.g., P999), VLOOKUP returns #N/A. Wrap with IFERROR: `=IFERROR(VLOOKUP(D2,$A$2:$B$6,2,FALSE),0)` — shows 0 instead of error.

REASONING: VLOOKUP is the standard "lookup price from master table" pattern in accounting. Absolute table_array ($A$2:$B$6) is mandatory — without it, copying down shifts table to A3:B7, A4:B8, causing #N/A or wrong prices. FALSE (exact match) is critical for codes — TRUE (approximate) would match P103 to P102 if unsorted. This combines relative reference (D2, E2 shift down) with absolute reference ($A$2:$B$6 fixed) — the core referencing skill. IFERROR handles missing codes gracefully, a best practice for robust spreadsheets.

ANSWER: F2=`=VLOOKUP(D2,$A$2:$B$6,2,FALSE)` → 1200. G2=`=E2*F2` → 6000. Line totals: P103(5)=6000, P101(10)=2500, P105(2)=1800, P102(8)=3840, P104(3)=1050. Total Sales = ₹15,190.

## COMPETENCY_QUESTION_1
QUESTION: A CBSE Class 12 student creates a spreadsheet for a "School Fee Collection" model. Columns: A=Student Name, B=Class, C=Tuition Fee, D=Transport Fee, E=Total Fee (C+D), F=Discount % (5% if Total>20000 else 0%), G=Discount Amount, H=Net Payable. The student writes in F2: `=IF(E2>20000, 5%, 0%)` and in G2: `=E2*F2`. When copying down, row 5 (Total=25000) shows Discount 5% but Discount Amount = 0. Row 8 (Total=18000) shows Discount 0% but Discount Amount = 900. Identify the TWO errors in the student's approach and provide corrected formulas for F2 and G2.

COMPETENCY
Error identification and correction in spreadsheet logic (formula auditing)

STEPS:
- Step 1: Analyze F2 formula `=IF(E2>20000, 5%, 0%)`. In Excel, 5% is stored as 0.05. This part is actually correct — returns 0.05 or 0.
- Step 2: Analyze G2 formula `=E2*F2`. If F2=0.05, E2*0.05 works. But the problem says Row 5 (Total=25000) shows Discount 5% but Amount=0. This implies F5 displays "5%" but value is not 0.05 — likely the student typed "5%" as TEXT (with space or apostrophe) or formatted cell as Text before entry.
- Step 3: Row 8 (Total=18000) shows Discount 0% but Amount=900. 18000×0.05=900. This means F8 actually contains 0.05 (5%) despite displaying 0% — perhaps the IF condition is reversed: `=IF(E2<20000, 5%, 0%)` would give 5% for 18000.
- Step 4: Two errors: (1) IF condition likely reversed (should be >20000 for discount, but student wrote <20000 or similar). (2) Percentage entered as text "5%" not numeric 0.05 or 5% format.
- Step 5: Corrected F2: `=IF(E2>20000, 0.05, 0)` or `=IF(E2>20000, 5%, 0%)` with cell formatted as Percentage. Corrected G2: `=E2*F2` (works if F2 is numeric). Better: combine in G2: `=IF(E2>20000, E2*0.05, 0)` — avoids separate discount column.

ANSWER: Error 1: IF condition reversed — should be `E2>20000` for discount eligibility, but student likely used `<`. Error 2: "5%" entered as text instead of numeric 0.05 or percentage format. Corrected F2: `=IF(E2>20000, 0.05, 0)` (format as %). Corrected G2: `=E2*F2` or combined `=IF(E2>20000, E2*0.05, 0)`.

## COMPETENCY_QUESTION_2
QUESTION: You are building a "Loan Comparison" spreadsheet for a customer choosing between two home loan offers:
Offer A: ₹50 lakh, 8.75% p.a., 20 years
