## ELI5
Ransomware locks the laptop overnight — projects, photos, applications all encrypted — and the only undo button is a backup. Data backup creates and maintains copies of data; data recovery restores them. The 3-2-1 rule shapes a strategy: 3 copies, on 2 different media, 1 offsite. Full backups restore simply, incrementals copy only the changes, differentials sit between. Fix how much you can lose (RPO) and how long you can wait (RTO), then layer frequent local copies with periodic offsite fulls and one offline copy.

## DEFINITION
Data backup is the process of creating and maintaining copies of data to protect against loss from hardware failure, malware, human error, or disasters; data recovery is the process of restoring data from those copies. A backup strategy defines the backup types (full, incremental, differential), storage locations (on-site, off-site, cloud), scheduling, retention, and recovery objectives (RTO, RPO) to ensure data can be restored within acceptable time and loss limits.

## WALKTHROUGH
Imagine your laptop with all your Class 12 project files, photos, and college applications gets hit by ransomware overnight — everything encrypted, a ransom note demanding ₹50,000. You have no backup. How do you recover? This nightmare scenario is why backup isn't just "copying files to a pen drive once." A strategy starts with the 3-2-1 rule: 3 copies (original + 2 backups), 2 different media types (e.g., external SSD + cloud), 1 offsite (cloud or another building). Then choose backup types: full (complete copy, slow but simple restore), incremental (only changes since last backup, fast backup but chain-dependent restore), differential (changes since last full, faster restore than incremental). Define RPO (max data you can lose — e.g., 1 hour) and RTO (max downtime — e.g., 4 hours). The key insight: a good strategy layers these — frequent incrementals to local fast storage for quick recovery, periodic fulls to cloud for offsite survival, and an air-gapped offline copy for ransomware immunity.

Takeaway: mastery means the strategy built to a scenario's clock, not to a habit. Exam moves: rule questions apply 3-2-1 to a given setup; type questions contrast full, incremental, and differential on speed and restore chains; objective questions define RPO as tolerable data loss and RTO as tolerable downtime; mix-up questions reject calling cloud sync a backup. Method: plan the project laptop — hourly incrementals locally, nightly differentials, weekly full to cloud, one air-gapped drive. Drill: three types, two objectives, one rule. Students miss it because sync feels safe — a deleted file deletes itself everywhere, and ransomware rides the sync too.

## DIAGNOSTIC_QUESTION_1
What is the 3-2-1 backup rule, and why does each number matter?

## DIAGNOSTIC_ANSWER_1
The 3-2-1 rule: keep at least 3 copies of data (original + 2 backups), on 2 different media types (e.g., external HDD and cloud), with 1 copy offsite (different physical location or cloud region). A wrong answer like "3 backups on the same external drive" reveals misunderstanding of media diversity and geographic redundancy — a single drive failure or fire would destroy all copies.

## DIAGNOSTIC_QUESTION_2
Explain the difference between incremental and differential backups. In a ransomware attack that encrypts files over 3 days, which backup type would likely allow cleaner recovery and why?

## DIAGNOSTIC_ANSWER_2
Incremental backs up changes since the last backup of any type; differential backs up changes since the last full backup. In a 3-day ransomware encryption, incremental backups from each day would contain encrypted files, so restoring requires going back to the last clean full backup and reapplying only clean incrementals — but if incrementals ran after encryption started, they're poisoned. Differential backups grow daily; the last clean differential (before encryption) plus the full backup gives a clean restore point without a chain. A wrong answer claiming "incremental is always better for recovery" shows confusion about backup chain dependencies and malware propagation.

## DIAGNOSTIC_QUESTION_3
A freelancer has 200 GB of client videos. They do a full backup to an external SSD every Sunday, and incremental backups to the same SSD every weekday at 6 PM. On Thursday at 10 AM, the SSD fails. What is the maximum data loss (RPO), and how many backup sets are needed to restore the latest clean state?

## DIAGNOSTIC_ANSWER_3
Last incremental was Wednesday 6 PM. Failure Thursday 10 AM → data created between Wed 6 PM and Thu 10 AM is lost (max ~16 hours). To restore: need Sunday full + Monday incremental + Tuesday incremental + Wednesday incremental = 4 backup sets. A wrong answer saying "only Sunday full backup needed" ignores that incrementals capture changes after the full backup; skipping them loses all work done Mon-Wed.

## DIAGNOSTIC_QUESTION_4
Compare a 3-2-1 strategy (local HDD + cloud) with a 4-3-2 strategy (local HDD, local NAS, cloud provider A, cloud provider B). What specific additional risks does 4-3-2 mitigate, and what are the practical cost/complexity trade-offs for a small business?

## DIAGNOSTIC_ANSWER_4
4-3-2 adds a second on-site device (NAS) and a second cloud provider. It mitigates: (1) simultaneous failure of two media types (e.g., HDD controller failure + cloud provider outage), (2) regional disaster taking out one cloud region, (3) vendor lock-in or account compromise at one cloud provider. Trade-offs: ~2x storage cost, more complex scheduling/monitoring, longer backup windows, need for multi-cloud management tools. A wrong answer only saying "more copies = safer" without naming specific risk scenarios shows superficial analysis.

## DIAGNOSTIC_QUESTION_5
A school stores all student records only in Google Drive (unlimited education edition). The IT admin says, "Google's durability is 99.999999999%, so we don't need local backups." Evaluate this claim against the 3-2-1 rule and three realistic threat vectors.

## DIAGNOSTIC_ANSWER_5
The claim violates 3-2-1: only 1 copy (Google Drive), 1 media type (cloud), 1 offsite location (Google's infrastructure). Three threat vectors: (1) Ransomware encrypts local files → Drive File Stream syncs encrypted versions to cloud, overwriting good copies. (2) Admin account compromise → attacker deletes all Drive data; no second offsite copy exists. (3) Google service outage or region failure → inaccessible data with no local fallback. A wrong answer accepting "cloud durability = backup" confuses infrastructure durability with logical data protection against user/attacker actions.

## DIAGNOSTIC_QUESTION_6
Design a backup strategy for a wedding photographer who shoots 100 GB of RAW images per event, needs to cull/edit within 24 hours, and must protect against: (a) laptop theft, (b) ransomware, (c) corrupted SD card. Specify media, schedule, backup types, RPO/RTO, and how it meets 3-2-1.

## DIAGNOSTIC_ANSWER_6
Good answer: (1) On-site: ingest to laptop → immediate copy to rugged external SSD (media 1) + verify. (2) Before editing: copy SSD to second external SSD kept offline (air-gapped, media 2) — protects against ransomware. (3) After culling (24h): upload final selects to cloud (Backblaze B2/Wasabi) (media 3, offsite). (4) Weekly: full backup of entire archive to cloud. RPO: 0 hours for selected images (cloud upload after cull), 24h for raw archive. RTO: minutes from local SSD, hours from cloud. Meets 3-2-1: 3 copies (laptop, SSD1, SSD2 offline, cloud), 3 media types (internal SSD, external SSD, cloud), 2 offsite (cloud + offline SSD stored at studio). Poor answer missing air-gapped copy or relying only on cloud sync shows inability to synthesize threat-specific controls.

## COMMON_MISCONCEPTION
Students equate "cloud sync" (Google Drive, OneDrive, Dropbox) with "backup." They believe automatic sync protects against all data loss. In reality, sync replicates the current state instantly — if you delete a folder, ransomware encrypts files, or a sync error corrupts data, those changes propagate to the cloud within seconds, overwriting the only "backup." A concrete example: a student works on a Python project, accidentally deletes the main folder, OneDrive syncs the deletion — the files are gone everywhere. They have no point-in-time recovery because sync is not versioned backup (though some services offer limited version history, it's not a guaranteed, comprehensive backup strategy).

## ON_FAILURE
If the student holds this misconception: (1) Have them list three data-loss events: accidental deletion, ransomware encryption, sync corruption. (2) For each, trace what happens to a single synced folder vs. a 3-2-1 setup with an air-gapped external drive. (3) Practical exercise: create a test folder with 5 files. Sync to OneDrive. Delete 2 files locally → observe cloud deletion. Then recover from OneDrive recycle bin (shows limited versioning). Then simulate ransomware: encrypt files locally → sync uploads encrypted versions. Finally, show how an external drive backup taken yesterday restores clean files instantly. This hands-on demo proves sync ≠ backup and why offline/media diversity is essential.

## WORKED_EXAMPLE_1
PROBLEM: A student has a 100 GB project folder. They want to implement a 3-2-1 backup strategy using an external hard drive (1 TB) and Google Drive (100 GB free). They can only upload 10 GB/day due to bandwidth limits. Design a weekly backup schedule that meets 3-2-1 and minimizes data loss to 24 hours.

STEPS:
- Step 1: Identify the three copies needed: original on laptop, copy on external HDD, copy on Google Drive.
- Step 2: Choose two media types: external HDD (magnetic) and cloud (SSD/remote). Offsite is Google Drive.
- Step 3: To achieve 24-hour RPO, perform daily incremental backups to external HDD (fast, local). Weekly full backup to external HDD on Sunday.
- Step 4: For cloud, upload weekly full backup (100 GB) over 10 days (10 GB/day) starting Sunday, completing by Wednesday. Then daily incremental uploads (small) for rest of week.
- Step 5: Verify: 3 copies (laptop, HDD, cloud), 2 media (HDD, cloud), 1 offsite (cloud). RPO 24 hours via daily incremental on HDD; cloud may lag but serves as offsite disaster recovery.

REASONING: The 3-2-1 rule requires diversity of media and location. Local HDD provides fast daily backups for quick recovery; cloud provides offsite protection against fire/theft. Bandwidth constraint shapes cloud schedule: full backup spread over days, then small incrementals.

ANSWER: Weekly full backup to external HDD every Sunday; daily incremental to HDD Mon-Sat. Cloud: Sunday start uploading full backup (10 GB/day for 10 days), then daily incremental uploads. Meets 3-2-1 with 24-hour RPO for local, ~10-day RPO for cloud full but incremental cloud catches up.

## WORKED_EXAMPLE_2
PROBLEM: A small office has 2 TB of data. They do full backup every Friday at 10 PM (takes 8 hours). Incremental backups daily at 10 PM (take 30 min). On Tuesday 9 AM, a ransomware attack encrypts all data. The IT admin discovers the attack at 10 AM. What is the data loss? How many backup sets to restore? If they had done differential backups instead, how would recovery differ?

STEPS:
- Step 1: Determine last successful backups before attack. Friday full backup completed Saturday 6 AM. Monday incremental at 10 PM. Tuesday incremental not yet run (scheduled 10 PM).
- Step 2: Data loss: all data created/modified after Monday 10 PM incremental (approx 23 hours).
- Step 3: Recovery sets needed: Friday full + Monday incremental = 2 backup sets? Actually incremental requires all incrementals since full. So Friday full + Saturday incremental + Sunday incremental + Monday incremental = 4 sets.
- Step 4: If differential: Friday full, then differential Sat, Sun, Mon. Each differential contains changes since Friday full. Recovery needs only Friday full + Monday differential = 2 sets. Data loss same (since last differential Monday 10 PM).
- Step 5: Compare: incremental uses less storage daily but more sets to restore; differential uses more storage but fewer restore sets.

REASONING: Incremental backups only capture changes since last backup (any type), creating a chain. Differential captures changes since last full, so each differential is self-contained relative to full. Recovery time is longer for incremental because more sets to process.

ANSWER: Data loss ~23 hours. Incremental recovery requires 4 backup sets (full + 3 incrementals). Differential recovery requires 2 sets (full + latest differential). Data loss same in both cases (since last backup at Monday 10 PM).

## WORKED_EXAMPLE_3
PROBLEM: A school's student database (500 GB) is hosted on a local server. They want RTO < 2 hours, RPO < 1 hour. They have a 1 Gbps LAN, a secondary server on-site, and a cloud backup service with 100 Mbps upload. Design a backup and recovery architecture meeting these objectives.

STEPS:
- Step 1: Analyze requirements: RPO 1 hour means backup frequency at least hourly. RTO 2 hours means restore must complete within 2 hours.
- Step 2: On-site secondary server can replicate data in near real-time (synchronous or asynchronous). Use block-level replication to secondary server for RPO ~ minutes, RTO ~ minutes (failover).
- Step 3: Cloud backup for offsite: hourly incremental backups to cloud. 500 GB initial full backup would take ~11 hours at 100 Mbps (500*8/100 = 40 hours? Actually 500 GB = 4000 Gb, /100 Mbps = 40000 seconds ≈ 11 hours). Do initial full over weekend.
- Step 4: Hourly incrementals: assume 1% change rate = 5 GB/hour = 40 Gb, at 100 Mbps = 400 seconds ≈ 7 minutes. Feasible.
- Step 5: Recovery: For server failure, failover to secondary server (RTO minutes). For site disaster, restore from cloud: need to download full + incrementals. 500 GB download at 100 Mbps = 11 hours, exceeds RTO. So cloud is for disaster recovery with longer RTO, not for primary RTO.
- Step 6: Document: Primary protection: on-site replication (RPO mins, RTO mins). Secondary: hourly cloud incrementals (RPO 1 hour, RTO 11 hours for full restore). Meets 3-2-1: original, on-site replica (different media? same media type but separate device), cloud (offsite, different media).

REASONING: RTO/RPO requirements dictate technology choices. On-site replication meets tight RTO/RPO; cloud meets offsite requirement but cannot meet 2-hour RTO for full restore due to bandwidth. This is a typical hybrid approach.

ANSWER: Use synchronous replication to on-site secondary server for primary HA (RPO < 1 min, RTO < 5 min). Schedule hourly incremental backups to cloud for offsite disaster recovery (RPO 1 hour, RTO ~11 hours for full restore). Initial full backup to cloud done over weekend. Meets 3-2-1 with hybrid strategy.

## COMPETENCY_QUESTION_1
QUESTION: A student claims: "I don't need a backup strategy because I save all my files to OneDrive, which syncs automatically. That's my backup." Identify the fallacy in this reasoning. Explain three distinct data loss scenarios where OneDrive sync alone would fail to protect data, and for each, describe how a 3-2-1 strategy would help.

COMPETENCY: Translating real-world situations to technical concepts; error identification and correction.

STEPS:
- Step 1: Understand the student's claim: sync = backup.
- Step 2: Identify fallacy: sync mirrors changes (including deletions, corruption, encryption) in real-time, so it does not provide point-in-time recovery.
- Step 3: Scenario 1: Accidental deletion of a folder. Sync deletes from cloud. 3-2-1: external drive backup has previous version.
- Step 4: Scenario 2: Ransomware encrypts local files. Sync uploads encrypted files. 3-2-1: offline/air-gapped backup unaffected.
- Step 5: Scenario 3: OneDrive account compromised/hacked. Attacker deletes all files. Sync propagates. 3-2-1: second offsite copy (e.g., different cloud) or local copy safe.
- Step 6: Conclude: Sync is for accessibility, not backup.

ANSWER: The fallacy is confusing synchronization with backup. Sync replicates current state, including errors. Three scenarios: (1) Accidental deletion – sync removes everywhere; 3-2-1 provides historical copy on external drive. (2) Ransomware – sync uploads encrypted files; 3-2-1 air-gapped copy allows clean restore. (3) Account compromise – attacker wipes cloud; 3-2-1 second offsite copy preserves data. A proper backup strategy includes versioned, offline, and geographically separate copies.

## COMPETENCY_QUESTION_2
QUESTION: A startup has 2 TB of critical data. They propose: "We'll do a full backup to AWS S3 every night. That's it. Simple and cheap." Evaluate this proposal against the 3-2-1 rule, RTO/RPO considerations, and cost. Calculate the approximate monthly cost for S3 Standard storage (assume $0.023/GB/month) and data transfer (assume $0.09/GB for first 10 TB/month out). Assume 10% daily change rate, and they keep 30 daily full backups. Recommend a better strategy.

COMPETENCY: Comparing and justifying; multi-step calculation with real-world constraints.

STEPS:
- Step 1: Evaluate against 3-2-1: Only one copy (S3), one media type (cloud), one offsite location (AWS region). Violates 3-2-1 (needs 3 copies, 2 media, 1 offsite). Actually S3 provides durability but still single provider.
- Step 2: RPO: 24 hours (nightly). RTO: Restore 2 TB from S3. Download speed? Assume 1 Gbps connection: 2 TB = 16 Tb / 1 Gbps = 16000 seconds ≈ 4.4 hours. Might exceed RTO if they need <4 hours.
- Step 3: Cost calculation: 30 full backups * 2 TB = 60 TB stored. But S3 charges for stored data. 60 TB * $0.023/GB = 60,000 GB * $0.023 = $1,380/month storage. Data transfer: each night upload 2 TB (full) = 60 TB/month upload (free inbound). Restore (outbound) not regular. But if they need to restore, 2 TB out = $180. Monthly cost ~$1,380.
- Step 4: Better strategy: Full backup weekly to S3 (4 fulls = 8 TB). Daily incremental to S3 (10% of 2 TB = 200 GB/day * 30 = 6 TB). Total stored ~14 TB. Cost: 14,000 GB * $0.023 = $322/month. Add local NAS for fast restore (RTO minutes). Keep one offline copy monthly. Meets 3-2-1.
- Step 5: Justify: Reduced cost, faster local recovery, offline copy for ransomware.

ANSWER: Proposal violates 3-2-1 (single provider, single media). RPO 24h, RTO ~4.4h (may be acceptable). Cost ~$1,380/month for 30 full backups. Better: Weekly full + daily incremental to S3 (14 TB stored, $322/month), plus on-site NAS for immediate recovery, plus monthly offline drive. This meets 3-2-1, reduces cost 75%, improves RTO to minutes for common failures.
