## 📌 PINNED — GENERATION DESIGN INSIGHTS (owner-endorsed; binds every generation wave)

1. **Demand-driven order** — generate sims/diagrams first for the nodes students actually visit (mastery ledger + attempt logs know), not subject-by-subject. Maximizes learning impact per item built.
2. **Every sim is a mastery instrument** — wire sim validate-goal results into the mastery ledger (Kernel 2); attach the node's misconception-keyed remediations. A sim session diagnoses, not just visualizes.
3. **Mechanical sim QA** — after each template tranche, auto-probe the parameter space (extremes/zero/negative) like the solver flywheel; NaN/broken-state sims die before publish.
4. **Diagram specs, not just SVGs** — emit a machine-checkable spec (elements, labels, geometry constraints) beside each diagram so structural correctness is validated mechanically and restyling is a re-render, not a rebuild.
5. **One design system across all generators** — shared fonts/palette/strokes so all diagrams look like one hand; every builder consumes it, none defines its own.
6. **Language-layer fixes are mechanical, not generative** — KrutiDev वेफ→के corruptions are a deterministic font-mapping table; preprocess in bulk, never per-file authoring.
7. **Touch-scope contract (standing)** — questions never change; only ELI5 intros / walkthrough appends / diagnostic-answer appends are mutable, verified per file vs `.orig`. Generation programs are ~95% pure addition; replacements target audited defects only.
